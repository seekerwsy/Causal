\section{Evaluation}

\subsection{Evaluation Overview}

We organize the evaluation around four complementary research questions. RQ1 compares the overall effectiveness of \model with competing methods in identifying actionable prompt-side security hypotheses. RQ2 examines which parts of the representation and prioritization pipeline produce that advantage. RQ3 tests whether the resulting requirement explanations can be translated into prompt hardening that changes independently measured security outcomes. RQ4 evaluates the perceived quality and usefulness of the explanations in a separately governed expert study. Together, the four questions evaluate method effectiveness, component contribution, downstream security impact, and human-centered explanation quality.

All computational methods receive the same discovery and held-out task manifests, generator-model and request-randomness policy, independent security Oracle and functional contract, candidate budget, family-valid requirement protocol, randomization, outcome encoding, semantic-cluster uncertainty, and multiplicity policy. Candidate universes, rankings, expected directions, realization policies, and decision rules are frozen before held-out outcomes. The primary confirmatory analysis is hypothesis- and generator-model-specific semantic-task-clustered assigned-arm ITT on oracle-evaluable secure-code yield. Every committed assignment remains in its assigned-arm denominator; target-change, semantic compliance, generation success, and non-target drift remain diagnostics.

\noindent\textbf{Datasets.} The task inventory draws from SecurityEval, LLMSecEval, SALLM, CWEval, CyberSecEval, and SeCodePLT, with BaxBench used for backend replication~\cite{siddiq2022securityeval,tony2023llmseceval,siddiq2024sallm,peng2025cweval,bhatt2023cyberseceval,nie2025secodeplt,vero2025baxbench}. The frozen task manifest records exact provenance and enforces semantic-cluster-disjoint discovery and evaluation splits.

\noindent\textbf{Baselines.} We compare \model with association, regularized prediction, LLM-based explanation, and seeded random ranking under a shared candidate universe and top-$K$ budget. We additionally evaluate causality-aided prompt--code analysis and natural-language perturbation in their native output spaces before applying the same fixed bridge~\cite{ji2025causality,chen2026nlperturbator}.

\subsection{RQ1: Overall Effectiveness}

\textbf{RQ1. How effectively does \model identify actionable prompt-side security hypotheses compared with state-of-the-art methods?}

We compare \model with competing methods under the same semantic-cluster-disjoint task splits, generator configurations, candidate budget, and downstream randomized evaluation protocol. Because the methods emit different objects, every output is mapped through a prospectively fixed bridge into the same catalog of actionable context--requirement--operation hypotheses before held-out evaluation. Mapping failures and unused budget slots remain in the original denominator; held-out outcomes never rerank a method or replace a failed slot.

The primary method-level endpoint is Supported-Effect Yield@$K$ after held-out randomization. We additionally report the complete selection-to-evidence funnel and Practically-Actionable Yield@$K$, which requires a beneficial effect, supported specificity, and preserved functionality under the frozen decision rules.

\subsection{RQ2: Component Contribution}

\textbf{RQ2. Which components of \model contribute to its effectiveness in identifying actionable security hypotheses?}

We conduct controlled ablations of the typed Prompt TSG representation, relational security context, typed structural constraints, and stability-guided hypothesis prioritization. Each comparison holds the task splits, generator models, candidate budget, bridge, prompt arms, outcome measurement, randomization, and inference policy fixed. This design separates the contribution of structured hypothesis representation from the contribution of prioritization and tests whether their combination is what concentrates the fixed evaluation budget on supported hypotheses.

Because representation ablations can change the candidate identities and eligible populations, they are interpreted as end-to-end component comparisons rather than as interchangeable rankings over an identical list. We report candidate coverage, applicability, invalid-operation rate, protocolization, randomized coverage, Supported-Effect Yield@$K$, and Practically-Actionable Yield@$K$. Empty, invalid, and non-evaluable slots remain visible so that component gains cannot be created by denominator filtering.

\subsection{RQ3: Prompt Hardening Effectiveness}

\textbf{RQ3. Can security explanations produced by \model guide prompt hardening that reduces insecure code generation?}

We operationalize each frozen explanation as a task-specification-preserving ADD or REMOVE requirement and apply it to semantic-cluster-disjoint held-out tasks. Matched no-op prompts preserve the original factor state; placebo and, when family-valid, generic-security arms distinguish the named requirement from rewriting, presentation length, and non-specific security guidance. The primary analysis is the target-minus-no-op assigned-arm ITT risk difference on oracle-evaluable secure-code yield, with uncertainty resampled at the semantic task cluster. Every committed assignment remains in its assigned-arm denominator regardless of target change, semantic compliance, generation success, or non-target drift.

Code validity, Oracle support, unknown coverage, functionality, and secure-and-functional joint success are reported as separate outcomes. Functionality is a secondary guardrail rather than a post-assignment filter: it reveals whether a security gain preserves the requested task without redefining the primary safety estimand. ADD and REMOVE remain distinct frozen hypotheses, and multiplicity-adjusted intervals determine support under the decision rule in Section~\ref{sec:matter-definition}.

\subsection{RQ4: Explanation Quality}

\textbf{RQ4. How do security experts evaluate the quality of explanations produced by \model and competing methods?}

Qualified security experts evaluate anonymized explanations under a balanced case--method assignment. Each explanation uses the same wrapper and presents the applicable context, editable requirement, selection evidence, randomized effect and uncertainty, specificity, functionality, and claim scope. Experts rate clarity, evidence sufficiency, credibility, actionability, and overall usefulness on five-point ordinal scales and additionally rank the explanations shown for the same case. Overall usefulness is the primary human-study outcome; the remaining dimensions and within-case ranking provide complementary evidence.

RQ4 evaluates perceived explanation quality only. It does not validate causal discovery, objective repair accuracy, or the computational evidence used in RQ1--RQ3.
