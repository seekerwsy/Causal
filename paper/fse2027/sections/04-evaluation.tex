\subsection{Evaluation Overview}

Our evaluation isolates each methodological contribution and its end-to-end
hardening value across three research questions:
\begin{itemize}
  \item \textbf{RQ1 (Structured Graph Representation):} How effectively does
  \prompttsg improve multi-operation requirement binding, pre-assignment
  attribute accuracy, and code validity compared with \textsc{Raw} and
  \textsc{Flat} representations?
  \item \textbf{RQ2 (Directional JCI and Cross-Fitted Learning):} Under
  identical attributes and outcome budgets, does context-anchored directional
  JCI role-grouped shrinkage with task-unit cross-fitting reduce
  effect-estimation variance across downstream, target-shift, and upstream
  mechanisms compared with unstructured and undirected-skeleton baselines?
  \item \textbf{RQ3 (End-to-End Scoped Security Hardening):} How effectively
  does \model identify confirmed positive security-hardening edits compared with
  state-of-the-art prompt analysis baselines while keeping adverse warnings,
  functionality, and Oracle coverage distinct?
\end{itemize}

All comparisons share frozen task manifests, generator decoding policies,
candidate budgets $K$, assigned-arm ITT accounting, and independent programmatic
measurement. Prospective settings (Table~\ref{tab:evaluation-settings}) and
nominations are frozen prior to confirmation outcome access; \pendingresult{}
denotes pending formal natural-task measurements where prospective protocol
activation has not yet occurred.

\subsection{RQ2: Directional JCI and Cross-Fitted Effect Learning}

\textbf{RQ2.} \emph{Does context-anchored directional JCI role-grouped
shrinkage with task-unit $K$-fold cross-fitting reduce effect-estimation
variance relative to unstructured learners and undirected-skeleton ablations?}

RQ2 holds covariates $X=(C,Z)$, source observations, target task units, and
cross-fitting folds fixed, comparing \model's JCI role-grouped estimator
against seven unstructured baselines (\textsc{Direct Uniform}, \textsc{Direct
Context}, \textsc{Full Logit}, \textsc{Sparse Logit}, \textsc{Screened Logit},
\textsc{Boosted}, \textsc{PCA}) and three structural ablations
(\textsc{Undirected Skeleton}, \textsc{Propagated Skeleton}, \textsc{Shuffled
Roles}), alongside \textsc{Target-Only} adaptation. Evaluation spans
downstream confluence (\texttt{downstream\_signal}), shifted target attributes
(\texttt{target\_new\_attribute}), upstream precursor mechanisms
(\texttt{upstream\_control}), and a \emph{negative control}
(\texttt{misaligned\_signal}) in which the outcome loads only on
latent-confounded attributes outside every structural role, so the role menu
carries no correct hypothesis. A sensitivity arm repeats all four regimes with
random attribute flips to emulate Stage~I extraction error. The prespecified
reading is asymmetric: directional roles must improve precision when the
structure is informative, and must reduce to the unstructured fallback without
supported harm when it is not. We measure relative variance reduction
$\Delta\text{Var}$, simultaneous Bonferroni-adjusted intervals, bias, MSE, and
coverage (Table~\ref{tab:rq2-jci}).

\subsection{RQ3: End-to-End Scoped Security Hardening}

\textbf{RQ3.} \emph{How effectively does \model identify and confirm actionable
positive security-hardening edits compared with existing prompt analysis
baselines while tracking adverse regressions separately?}

RQ3 compares \model against \textsc{Prompt Attribution}, \textsc{Ji et al.}~\cite{ji2025causality},
\textsc{NLPerturbator}~\cite{chen2026nlperturbator}, and \textsc{LLM-Judge}
using a common outcome-blind bridge into the admissible scoped-intervention
space (Table~\ref{tab:rq3-discovery}). Crucially, we measure \textbf{Positive
Hardening Yield@$K$}—the fraction of $K$ nominated slots achieving confirmed
positive-meaningful security yield above margin $m_h$—while reporting
negative-meaningful findings separately as \emph{Adverse Warnings} rather than
conflating regressions with hardening yield. Table~\ref{tab:rq3-outcomes}
records the full assigned-arm endpoint decomposition for confirmed edits,
keeping code validity, Oracle evaluability, functionality, and joint success
explicitly separate.
