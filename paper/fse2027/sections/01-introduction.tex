\section{Introduction}

Developers using large language models (LLMs) for code generation face a
concrete prompt-engineering question whenever hardening multi-operation modules:
\emph{which security requirement genuinely drives secure code rather than acting
as a spurious correlate, and where within a shared-object task must that
requirement apply without breaking sibling functionality?} Insecure idioms
remain prevalent in LLM outputs~\cite{pearce2022copilot,perry2023assistants},
and explicit security prompting or iterative prompt refinement can shift
generation behavior~\cite{tony2025prompting,nazzal2024promsec}. However,
converting prompt modifications into trustworthy engineering guidance confronts
two coupled failures that neither generic checklists nor observational prompt
correlations resolve.

The first challenge is \textbf{compositional multi-operation scope bleed}.
Real-world software modules routinely house multiple operations over shared
request mappings, nested attribute paths, or standard-library
primitives~\cite{cicalese2026language}. Requiring strict SQL parameterization,
path confinement, JSON deserialization, or cryptographic randomness inside a
security-sensitive operation is beneficial \emph{only within that target scope};
issuing the exact same security requirement as a flat, module-wide directive
frequently induces LLMs to propagate input rejection, escaping, payload hashing,
or non-deterministic randomness into sibling helper or formatting operations that
must preserve raw values or deterministic seeds. Moreover, coarse AST security
analyzers that scan entire modules indiscriminately conflate safe target
hardening with legitimate non-target sibling logic. Effective prompt
representation must bind normative constraints cleanly to target operations,
\texttt{part\_of} object ownership chains, and execution guards while
degrading unanchorable background clauses locally rather than discarding valid
operation scope.

The second challenge is \textbf{environment and latent confounding in
observational prompt signals}. Observing that repository prompts containing
detailed docstrings, type signatures, or file metadata correlate positively with
secure completions does not imply that inserting those artifacts will harden an
unsecured baseline~\cite{ji2025causality,velasco2026smells}. Environment shift
($C_{\mathrm{env}}$) across benchmarks and unobserved task difficulty ($U$)
induce strong spurious associations between benign style predicates and
post-generation security, whereas unscoped intervention indicators induce
negative functional side effects through shared objects. Causal discovery must
therefore exploit multi-environment exogenous contexts and targeted
intervention probes while orienting observed post-generation outcomes as strict
temporal sinks---separating genuine causal security drivers from confounded
proxies and automatically abstaining when no causal mechanism is supported.

We present \model, a two-stage framework linking Task-Grounded Semantic Graphs
(\prompttsg) with Joint Causal Inference (JCI)~\cite{mooij2020jci} mechanism
discovery and within-task paired counterfactual intention-to-treat (ITT)
evaluation:
\begin{enumerate}
  \item \textbf{Task-Grounded Scoped Representation and Intervention (\prompttsg).}
  In Stage~I, we formalize evidence-grounded semantic graphs $G_P$ with tolerant
  span recovery (\texttt{unresolved} local degradation instead of global
  rejection), extract an eight-predicate orthogonal structural mechanism vector
  $Z = q(G_P,r)$ audited for extraction stability prior to discovery, render
  operation-scoped prompt interventions $\operatorname{Do}_{\mathrm{TSG}}(G_P,
  \mathcal{M})$ that protect sibling contracts, and decouple semantic scoping
  from deterministic AST symbol splicing and target-operation-scoped AST
  security evaluation.
  \item \textbf{Temporal-Sink JCI Mechanism Discovery and Paired Counterfactual
  Evaluation.} In Stage~II, under strict split isolation between Discovery
  ($D_{\mathrm{disc}}$) and Held-Out Evaluation ($D_{\mathrm{eval}}$,
  $D_{\mathrm{disc}} \cap D_{\mathrm{eval}} = \emptyset$), \model discovers a
  JCI-12 Partial Ancestral Graph (PAG)~\cite{spirtes1995fci,zhang2008ancestral}
  over exogenous environment/intervention contexts $C=(C_{\mathrm{env}},I)$,
  structural mechanisms $Z$, and post-generation temporal outcome sinks
  $(Y_{\mathrm{sec}}, Y_{\mathrm{func}})$, filtering out environment-confounded
  and latent-confounded proxies as well as unscoped scope-bleed hazards. On
  $D_{\mathrm{eval}}$, matched four-arm within-task paired counterfactuals
  (\texttt{baseline}, \texttt{corr\_tsg}, \texttt{jci\_flat}, \texttt{jci\_tsg})
  cancel baseline task difficulty identically while keeping code validity,
  Oracle evaluability, \texttt{unknown} rates, functionality, and joint success
  distinct across the full ITT denominator.
\end{enumerate}

Section~\ref{sec:evaluation} tests both contributions and their combined yield
across three research questions: \textbf{RQ1} quantifies \prompttsg{}'s protection
against multi-operation functional scope bleed versus unscoped flat causal
prompts; \textbf{RQ2} measures JCI causal deconfounding, spurious negative-control
abstention, and paired counterfactual precision across 48 multi-regime
validation cells and live LLM generations; and \textbf{RQ3} decomposes live
32B model endpoints across six CWE families alongside our prospective
confirmatory protocol.
