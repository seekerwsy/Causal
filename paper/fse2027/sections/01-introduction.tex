\section{Introduction}

Natural-language prompts now participate directly in the security boundary of
code generation. They often specify what a program should do while leaving
validation, authorization, trust boundaries, or safe-API constraints implicit.
Studies of AI-assisted code generation show that functional-looking outputs
can still contain security weaknesses and that developers may overestimate the
security of assisted solutions~\cite{pearce2022copilot,perry2023assistants}.
The practical question is therefore not only which prompt text matters, but
which missing or weakly scoped requirement can be edited without changing the
programming task.

Feature attribution, concept-based interpretation, and rationale evaluation
offer complementary views of model
behavior~\cite{sundararajan2017integrated,kim2018tcav,lundberg2017shap,deyoung2020eraser},
while secure-prompt studies compare predefined reminders, reasoning strategies,
and repair loops~\cite{tony2025prompting,bruni2025promptbenchmark}. These methods
can identify important text or useful strategies, but they do not determine
which context-specific requirement is an editable security factor. Free-form
perturbations also risk changing task semantics and security content together,
making behavioral differences difficult to attribute.

The missing link is a path from structured prompt meaning to usable effect
evidence. Free-form requirements must first become bounded factors whose
applicability and valid edits are explicit. Observational evidence must then
allocate a limited experimental budget without being mistaken for an
intervention effect. Finally, the selected hypotheses and their prompt policies
must be frozen before controlled evaluation on held-out tasks.

\model follows a representation--selection--evaluation architecture.
\textbf{Typed Prompt Representation} maps each programming request into a
\prompttsg that separates task semantics, security context, editable safety
factors, and presentation controls; context-conditioned intervention templates
are queries over this representation. \textbf{Hypothesis Discovery and
Selection} uses TSG-derived constraints, FCI evidence, and stability under
semantic-cluster resampling to discover, rank, and freeze a budgeted set of
intervention hypotheses. \textbf{Evaluation of Intervention Effects}
constructs matched prompt arms and estimates their assigned-arm effects on
cluster-disjoint held-out tasks. The resulting intervention evidence record
connects represented context, the frozen edit, selection rationale, evaluated
effect, uncertainty, and claim scope. The Prompt TSG defines what can be
edited; observational discovery determines what should be tested; blocked
randomization identifies the assigned prompt-policy effect.

\needspace{8\baselineskip}
This paper makes the following contributions:

\begin{itemize}
  \item \textbf{Typed Prompt TSG representation.} A bounded task-security
  graph separates task semantics, security context, editable safety factors,
  and presentation controls. Graph queries derive context-conditioned
  templates with explicit factor states, valid operations, and invariants.
  \item \textbf{Budgeted hypothesis discovery and selection.} TSG-derived
  constraints, FCI uncertainty, and stability under semantic-cluster
  resampling turn observational evidence into a frozen, budgeted hypothesis
  set without treating learned relations as effect estimates.
  \item \textbf{Evaluation of intervention effects.} Matched prompt policies
  and held-out blocked randomization estimate assigned-arm effects on
  independently measured security and functionality while retaining failed,
  null, harmful, and non-evaluable assignments under the frozen analysis.
  \item \textbf{Expert-facing evidence interface.} A standardized
  intervention evidence record connects context, editable action, selection
  evidence, randomized effects, uncertainty, and scope; a separately governed
  study evaluates its expert-perceived utility without promoting those ratings
  to computational effect evidence.
\end{itemize}
