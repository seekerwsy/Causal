## 1. 今晚要得到的研究答案

先回答是否需要结构发现及什么算法适配，再用一项明确的 Atomic ADD 政策，完成两项彼此区分的有界开发检查：

0. **因果算法选型：**区分自然观测结构、混合观测/干预环境结构、政策效果和上下文效应差异。核对 FCI、JCI-FCI 以及最多一个有针对性的替代方法的适用假设与当前数据条件，交付保留/适配/替换/暂不用的明确结论；不能把取消 FCI 普遍准入直接等同于算法研究无价值。

1. **作者模拟的表示与编辑检查：**Codex 根据源文准备完整要求、TSG、对象/条件绑定及四臂编辑，检查语义、引用和渲染是否一致。必要时从同一记录导出 G/L 视图检查信息等价，不进行自动抽取能力或自动 G/L 优越性评分。
2. **政策检查：**在来源已审阅、政策完整且端点可测的开发任务上，Target 相对 No-op / Style / Generic 的观察安全产出、功能与 unknown 有何变化？

早上交付实际请求与结果、独立复算、可解释案例、当前方法缺口，以及是否值得进入更大独立研究的决定。阴性、相同输出和不确定均为有效结果；不以“TSG 必须胜出”或“政策必须显著有效”为验收条件。

这轮采用作者辅助的结构与政策原型：Codex 模拟抽取/构建/编辑，远程模型真实生成代码。不得伪装成已运行独立自动抽取器，不报告自动抽取准确率、自动 G/L 增量或端到端自动产品收益。作者参考不是独立金标准。所有目标、条件、对照和测量规则在查看本轮代码结果前固定；结果出现后不得反向修图、强化 Target 或重评分。自动表示价值另留独立验证。

## 3. 算法选型及政策与对照的夜间取舍

### 算法选型是必交付，不以先前建议代替验证

先阅读原论文或官方实现，区分其结论与本项目适配推断。既有意见只是候选方向，尚未完成算法选优：

- FCI：复核现有自然状态矩阵、离散检验、小样本支持、背景知识及任务内依赖的适配；保留为已实现参照。
- JCI-FCI：核对自然上下文与随机干预身份、实际可接受的外生性/混杂假设，以及怎样表达这些条件；不把所有名为 context 的变量视为随机化，不把提示编辑视为完美设置代码性质的干预。
- 替代方法最多选一个：根据实际瓶颈决定是否评估 GFCI 等方法；选它的依据必须是结构识别、统计假设或有限样本问题，而非名字不同。RFCI 的计算取舍、PC/GIES 的额外前提可作纸面排除，不必全部实现。
- 效果估计作为不同研究目标的参照，不能把因果树/森林列为与 PAG 恢复同一任务的算法排行榜。

交付一张“科学目标—假设—数据支持—实现状态—预期增量—验收办法”表和一个主推荐。若结构真值未知，不以自然数据的边更多、邻接更稳定或图更复杂评价正确性。

若存在可信且无需新框架即可调用的候选，可在少数与本项目相关、真值已知的合成场景上做一次有界诊断，检查混杂、干预身份或任务重复造成的具体问题。模拟场景、参数与判断标准在看输出前固定；这些结果只是适配诊断，不证明自然任务有效，也不能据单一反例选出“最优算法”。若假设不成立或实现尚不支持，明确记为未测试/不适用并给出原因，不用有边率补结论。

算法工作限定在前 2 小时左右；作者模拟免去自动抽取比较的调用负担，将更多时间用于适配判断。它可以改变后续推荐，但不能在已生成开发结果后临时切换主分析，也不能为了实现所有算法挤掉测量与结果交付。

### 完整政策和四臂

沿用已有完整要求记录与 renderer，不建设第二套编辑框架。首次准备时固定：目标要求、源表达状态、对象集合、guard、时点、非目标不变量和四臂文本。

首选检查文件权限性质的源绑定与测量可行性。Pro 提议的“正常返回时 group/other 读写权限位为零”可以作为**有明确名称的窄开发端点提案**；必须说明它不是全过程安全、ACL/属主保证，也不等于旧文件权限 profile 已合格。不能把终态端点当成原有更强要求的等价替代。

前置阶段据原研究问题和可见源材料固定本夜具体性质。不能依据保存的代码效果或预期正收益挑选。若无法确定不偷换含义的政策与端点，则不启动代码生成，转为完成该缺口的有限诊断，并如实报告实验未执行。

四臂：
- Target / No-op / Style 共享同一源定位说明。
- No-op 保持源要求表达状态；不能以“等词数”代替控制语义。
- Generic 使用共同泛化安全提醒，不带方法特有定位。
- Target−No-op 解释为共享定位下完整要求编辑的增量。
- Target−Generic 包含定位、具体要求等全部差异，不称为纯安全内容效应。
- 本夜不加 BASE，不启用 Generic 回退，不声称自动建议采纳。

### 时间与批次完成的关系

在读取批次结果前，按完整任务臂包的估计耗时和可用服务容量冻结 N，预留至少 1 小时做复算与报告。不能仅因预算允许 24 题就承诺一定完成 24 题。

时间上限不能改变已经冻结的分母或触发选择性补跑。若意外延迟导致部分承诺槽位未执行/未返回，分别记未执行或基础设施缺失，不补软件结果零、不只分析已完成“好任务”。受影响对比保持未评估，夜间报告如实标明批次不完整。

尽量靠结果前缩小 N、合理超时及已有并发控制满足窗口；只有当前执行器确实缺少必要限制时，才作局部修复，不另建夜间调度服务。

## 5. 作者模拟与真实结果的证据边界

### TSG、来源绑定和编辑由 Codex 准备

保留实际 system/user 输入、源片段、要求、对象、条件、量词、时点、非目标不变量及四臂完整文本。优先使用已有结构与 renderer；程序只检查结构、引用和忠实编译，不替作者判断语义。

本夜的作者模拟可以验证：一个完整政策是否可定义和可物化、源文能否支持所需绑定、后续真实生成和测量是否能回答问题。它不验证独立自动抽取性能，也不能用 Codex 自制参考和自制图相互评分来宣布正确率。

如导出 G/L，仅作同信息表达与请求一致性诊断；不人为添加图/文本差异来制造效应。输出应包括每个任务的作者判断及依据、无法确定项、编辑前后差异、完整四臂和检查结果。自动 G/L 的增益表从本夜验收中移除。

所有输入在本轮生成结果出现前固定。生成代码是真实模型输出，不能由 Codex 编造或代写；安全与功能测量沿用冻结规则，不能看结果再放宽标准。

### 政策效果和结果组装

代码政策包由作者源审阅确定，以测量合法政策本身。其结果单独报告，不能用来事后修图或强化政策。

采用任务级 assigned-arm ITT。两次生成先在任务内平均；任务内种子不当作独立 n。输出 Target−No-op 及事前固定的辅助比较、各臂安全产出、Oracle 覆盖、功能和联合结果。

- 物化失败保留原 realization 和覆盖记录，不换题或换版本。
- 已承诺生成后的无代码、无效代码、不遵从和非目标漂移保留分母。
- Oracle-unknown 对观察安全产出贡献零，但不改标 insecure。
- 平台失败和未执行槽位不补零；相关对比不得伪装完整。
- 测量目标由源参考和固定场景决定，不从模型实际写了哪些对象反向定义。
- 不以全部请求数量代替独立任务支持。

本夜只给开发描述性结果及按现有开发规则计算的不确定性，不激活正式主/次级多重比较族。新建/更新等源上下文可以做描述性分组和支持表，不能解除 BLOCKED_NO_FROZEN_CONTEXT_RULE，不能声称确认了效应异质性。
