# 42 题开放候选与完整开发闭环

本轮按授权采用作者构图和模拟回复，完成从来源表示到结果核验的开发闭环。
**自然样本与模拟延续分开保存；尚未完成自然数据上的自动 Discovery 或有效性验证。**
没有外部 API 调用、费用、新增自然任务或论文修改。main 保持 Atomic-only，
协议仍是 `SPECIFIED_DRAFT`。

本轮作者已接触上一轮结果，不能把来源专用请求不含结果字段说成独立盲审。

## 模拟究竟替代了什么

模拟替代任务槽位、代码回复和资格输入；**没有模拟 FCI 的边或直接写入最终效果。**
24 个合成 Discovery 槽位引用两张明确的正/负状态图，各 12 个。它们是软件测试输入，
不是额外的自然任务，也不是 24 份独立自然证据。

代码回复采用已知效应方案：禁止 shell 的状态对应结构化参数代码，另一状态对应
shell 拼接代码。安全标签由现有 subprocess Oracle 实际测量。FCI 使用
causal-learn 0.1.4.7、G²、alpha=0.05、十次 bootstrap；10/10 次有效且有邻接。
这是刻意设置的数据关系，不能据此声称发现了真实机制。

Full 与 RD-only 在这一单候选案例中选中同一项，并共享一个后续比较。
10 个合成确认槽位各四臂，共 40 次分配。实际 renderer 生成目标、no-op、
字数匹配的样式控制和通用安全提示；不是仅将臂名称附加到相同提示中。

目标臂回复中预设八份安全代码、一份 Oracle 未知代码、一份语法错误代码；
三个控制臂预设不安全代码。测得的 ITT 为 0.8，恰好验证预设的 8/10，
失败和未知均留在分母。**0.8 不是模型效应估计。** 所有有效代码的功能结果均保留
unknown；表中功能成功产出为零表示没有确认成功，不能解读为全部功能失败。
未运行 pigar，也不声称验证了真实依赖捕获行为。

独立 verifier 重放冻结、分配、结果与 ITT，不独立判断来源语义、重算 FCI，
或证明安全 Oracle 正确。FCI 原始矩阵、PAG 和抽样索引单独保存在报告中。
此单候选模拟不能证明 Full 优于 RD-only。

## 查看和复现

- `run/graphs/sample-XX/`：每题记录、合同、TSG、结构读法和局限。
- `run/candidates/proposal.json`：17 项候选、来源节点、范围和作者判断。
- `run/natural-support/candidates.json`：全部 42 题的逐候选状态与实际折分阻塞。
- `run/simulation-inputs/`：来源候选、正负图、编辑文本、模拟回复和来源声明。
- `run/summary/simulation-report.json`：实际 FCI、七阶段结果、已知效应核对。
- `run/simulation-results/`、`run/simulation-verification/`：非主张结果包及独立核验。

Python 3.12，安装仓库的 `dev,selectors,languages` extras 后：

```text
python data/method/full-chain-development-v1/run.py NEW_OUTPUT
prompt-mechanism-study study verify-result NEW_OUTPUT/simulation-results
```

执行环境和输入身份在 `run/scope/`。本轮从新建 Python 3.12.13 环境完成复现；
原有标准七阶段测试及空候选测试共两项通过。没有新增测试函数。
标准七阶段结果包与 `discovery-path-development-v1/run` 的保留参考逐字节一致。
代码仅允许现有 smoke 接收显式离线 fixture，默认入口与七阶段方法未改变。

下一项研究证据应来自**真实自然数据的候选支持、具体编辑兼容性与测量质量**，
而不是再证明图能编译。若扩大材料，应先固定研究范围与独立的自然来源覆盖规则；
不能根据这 17 项因素的空缺、风险标签或 FCI 结果补齐样本格子。
