## Remaining failure

The original-side reviewer considers "inserts it" insufficient to certify username
storage. The deleted-source reviewer accepts both credentials as its referent.
These are conflicting source interpretations, not an independently established
gold label. The frozen insertion concept itself says "Insert the user's username
and password value into the database." It therefore embeds the uncertain input
even after its explicit input edge is removed. No narrower insertion concept is
available in that frozen vocabulary.

The patch retained this same concept and changed `fact.layer` to `unresolved`, with
unresolved source coverage. A layer flag does not remove the rejected proposition:
the existing guard returned `patch repeats rejected claim op_insert_credentials.fact`.
The request's JSON was valid. The failure concerns semantic representation and the
permitted repair, with source-interpretation disagreement upstream. The response,
its rejection, and the unexecuted dependent stages are retained unchanged.

This points to a remaining design question: which participant meanings belong in
an operation's frozen identity versus its explicit bindings, and how can a reviewed
local uncertainty be retained without recertifying a rejected combined predicate?
That question is not addressed by additional reviewers or by bypassing this guard.
