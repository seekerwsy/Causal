# Operation predicates and repair closure

This is an implementation check using authored controls on already exposed source
records. It made zero fresh model calls and zero external API calls. It does not
measure automatic extraction improvement or resolve the registration pronoun's
meaning. The main protocol remains SPECIFIED_DRAFT and Atomic-only.

The active record contract now assigns an operation's action/API meaning to its
predicate and concrete inputs, results, guards and order to their existing fields.
The program supplies the actual operation bindings to the existing source review.
Distinct source occurrences remain distinct records. The model must still produce
and review faithful predicates; the compiler cannot prove natural-language meaning
or automatically strip embedded assertions from an arbitrary old definition.

Normalization occurs in exposed development before freezing. This control uses
the explicit author-supplied `operation-predicates.json`, recompiles open records,
then freezes a new catalog. No old definition is overwritten, and candidate input
omission never redefines its operation. Requirement content and owned order are
preserved. This is not a new paid normalization or review stage.

The repair code now rejects retained references to withdrawn records. Withdrawal
also marks the affected source coverage unresolved; formerly accepted source
influence that names a removed operation is invalidated rather than silently
narrowed. A valid remaining locality declaration is retained. Dependent requirements
must be explicitly repaired or withdrawn, never automatically shortened into a
different asserted requirement. A frozen concept alias or a layer-only change
cannot revive the same rejected fact.
