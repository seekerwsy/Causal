# JCI requirement-policy method

This is the active method specification for `codex/jci-framework`, selected by
the owner on 2026-10-28. The method remains bounded research. The Atomic formal
protocol on `main` retains `SPECIFIED_DRAFT`; formal claims, provider spending and
protected-task use require their own authorization. Existing frozen studies keep
their original designs, evidence identities and scientific results.

## Variables and scientific target

W records pre-assignment source requirement states and task attributes. C records
the mutually exclusive random choice of baseline or one Atomic policy. X records
the prepared prompt requirement states. Y records independently measured outcomes.
Prompt TSG supplies source meaning and scope; its relations supply no causal
arrows. Generated code supplies outcomes and is excluded from the primary PAG.

One Atomic policy changes one complete requirement. The SCM check uses four ADD
policies and integer success counts as the structure-search outcome; count divided
by generation repetitions is the response for effect learning. Repeated generation
does not increase independent task count. Real-outcome replay retains the original
expression-policy identities and secure-code-yield, finite-functionality, Oracle
support, failure and unknown semantics.

The primary method question is whether JCI structural information yields policy
value beyond shared-information direct learners and structural ablations. A graph
change, an ancestry statement and a policy-value increment are separate outputs.

## Seven stages

1. Representation fixes source states, complete policies, task identities and
   independently measured endpoint definitions before learning.
2. Prioritization fits conservative FCI-time, JCI12 and JCI123 with common
   conditional tests. In SCM learning, non-ancestry proposes finite penalties;
   a direct randomized-dependence rejection vetoes that proposal. In budget replay,
   requirement ancestry supplies ranking priority before the common effect score.
3. Hypothesis freeze fixes mechanisms or source tasks, task roles, seeds, methods,
   parameter grids, selection rules, budgets and the complete comparison family.
4. Intervention/randomization assigns baseline or one requirement edit. Each
   task retains its assigned outcome. Discovery, calibration, confirmation and
   test descendants retain their parent task identity and their declared roles.
5. Measurement observes the registered endpoint. SCM results are explicit
   probability-model computations. Real replay consumes original model outcomes.
   Security unknown is retained and contributes zero observed secure yield.
6. Outcome assembly fits effects on D, chooses fit parameters and policies on
   disjoint CAL subsets, retains baseline as a candidate, and evaluates fixed
   decisions. Replay completes all discovery choices before reading confirmation
   labels and all confirmation choices before reading final test labels.
7. Inference/reporting compares exact SCM policy values over independent learning
   repetitions, or real held-out task outcomes with family-stratified task bootstrap.
   All registered conditions, empty slots, harmful values and unknowns remain.

## Finite regularization and controls

JCI non-ancestry is an estimated structural suggestion. All policy penalties stay
positive and finite; no estimated non-ancestry decision fixes an effect to zero.
Direct Ridge, ElasticNet, standardized-effect and conditional-independence consumers
receive the same assigned tasks, source attributes, training-only nuisance estimates
and calibration outcomes. The direct scalar grid covers uniform penalties induced
by the structural grid. Adjacency ablation uses the same JCI123 skeleton and direct
dependence veto. True-zero structure is an isolated information-bound diagnostic.

CAL fit selection uses assigned-outcome prediction loss. Its disjoint policy
subset uses known-propensity doubly robust value, including the baseline action.
Target truth and exact target value are unavailable during learning and selection.
The full configuration and all candidate fits and choices remain inspectable.

## Inference and evidence

The frozen SCM reliability design requires JCI123 to have positive simultaneous
paired-t interval lower endpoints against every registered comparator and positive
mean differences in both independent seed batches. Bonferroni allocation covers
the complete mechanism/sample-size/generation-count/comparator family. The practical
gain threshold is reported separately. The computational smoke uses the same
consumer and inference with its explicitly smaller declared reproduction scope.

Budget replay keeps fixed selection slots and actual original request budgets.
Its final task bootstrap moves all replay permutations and nested budgets together;
the permutations are dependent descendants. These intervals are descriptive for
already exposed historical tasks. An observed secure-yield gain alone establishes
neither latent software safety nor complete functionality or joint success.

The existing 48-condition SCM study has zero reliable-increment conditions. Its
direct population test and guarded JCI123 recover the same true-zero set in the
registered constant-coefficient mechanisms. Natural-task transfer, independently
qualified automatic semantic preparation, full functionality and context-modifier
inference retain their existing evidence gaps.

## Execution and provenance

`discovery/jci_structure.py` owns the common CI test and R process; the actual
conservative FCI implementation remains in `discovery/jci_reliability.R`.
`discovery/policy_value.py` owns common random streams, effect features and exact
policy values. `artifact_io.py` owns canonical artifact writing and integrity.

SCM execution is independent of earlier diagnostic directories. Each execution
captures its plan and source archive before outcomes and rejects changed inputs
when resuming. Independent verification checks archived execution-source hashes
and independently recomputes numerical results; its current source identity is
recorded separately. A frozen study is never resumed under refactored execution
sources. Server work stays in `/home/wsy/work/prompt-mechanism-study`.
