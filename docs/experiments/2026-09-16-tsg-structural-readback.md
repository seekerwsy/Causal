# 结构回译审核：修订与受控验证

状态：受控实验完成，**本次未观察到回译提示的增量检测收益**。协议保持 `SPECIFIED_DRAFT`，未形成自然任务稳定性或正式研究结论。

本轮只检验一个问题：说明文字保持正确时，审核能否识别实际条件和目标绑定错误。复用已暴露的图书任务，不增加自然任务、不进入 Discovery/Confirmation，不新增 reviewer 或表示 schema。

## 先固定语义与比较对象

两个核心要求是：查到目标记录时，函数对外返回 `(book_id, title, author, price)`；未查到时，对外返回 `None`。它们直接约束返回行为。数据库连接、查询参与该流程，不因此成为这两项返回要求的直接目标。正常的“未找到”与无法完成任务时的异常义务分开。

参考以原文含义及角色区分对象：`book_id` 与 `book ID` 可以是同一输入的不同提及；SQLite 数据库资源与其文件路径分别记录，不能用路径锚点替代数据库资源。节点编号、顺序与合法合取包装不决定语义正确性。返回条件应在条件字段或继承的条件中出现，不能仅在定义里出现。

本次主要评分单位是两条返回要求的完整绑定。其余记录保留并供审核，额外拒绝单列，不能借缺少这些部分的独立参考宣称整图审核准确率。SQL 适用性属于另一层判断；本次不调用范围评估，也不把仍有争议的 SQL 参考纳入审核正确性。旧运行及其缺陷保留原样。

## 实现及实验后保留的改变

`source_records.structural_readback` 确定性解释已有字段：直接目标、要求条件、操作执行条件、非执行上下文、组合及参与关系。共享条件展开、全任务目标展开与构图复用相同函数。空条件明确显示无结构化条件，不从原文或定义补齐。

实验版让模型在现有一次审核中对照原文检查两个方向：结构是否添加不支持的目标／条件，原文的必要条件／目标是否遗漏。原始定义保留为待核查的内容声明，不能代替结构字段。抽取提示同步要求以“条件—目标—要求”共同填充现有字段。局部补丁沿用现有一次上限。

实验后撤下默认付费审核和补丁请求中的增量回译提示，恢复此前的一次来源审核；**程序回译保留为审核前后调试输出**。抽取提示及下述空列表定位修复保留，尚未单独进行自然抽取收益验证。实验版只存在于本批冻结执行归档，不提供第二条活动方法路径。

一并修正可定位性：审核现在可引用整个列表字段，包括空的 `conditions`、`operations`、`subjects`，也可引用已有条目；只改说明文字不能修好被拒绝的空条件。对照的两种审核统一使用此响应接口，避免把字段地址修复误算成回译收益。

## 调用前固定的对照

同一已暴露图书任务的开发作者审定返回绑定，构造五个版本。三个错误版本完全保留原始事实定义和说明，只改结构。等价版本保留原有事实文字，增加一个合法合取容器。

| 版本 | 改变 | 两条返回要求的预期 |
|---|---|---|
| 正确 | 分支条件、返回目标正确 | 保留 |
| 删除条件 | 删除两条要求的条件列表 | 指出遗漏，阻止放行 |
| 扩大目标 | 将两条要求改成全任务范围 | 指出连接／查询不应受该要求约束 |
| 交换分支 | 交换两条要求的条件 | 指出条件—返回值反转 |
| 等价 | 用合取容器引用两条带条件要求 | 保留，不把图形差异当错误 |

旧审核使用上一批归档的请求构造器，新审核使用调用前冻结的回译实现。同一模型、设置、原始记录和输出 schema，每个版本分别调用两种审核；旧／新先后顺序交替。没有基于已知错误提示某一请求应当拒绝。

主要输出：逐版本、逐返回要求的放行／正确定位／拒绝但原因不对应／未确定；正确与等价记录误拒绝单列。必须定位到实际错误，不将笼统拒绝计为正确检测。多个变体来自同一基础任务，只作描述性诊断，不是独立自然样本的准确率。

保留的最大预算为 **10 次审核调用／5.5 元**。若新审核准确定位“扩大目标”，再对该固定版本调用现有局部补丁一次，最多 **1 次／2 元**，并按相同参考复核字段及非目标变化。合计最多 **11 次／7.5 元**，使用既有授权账本 14.181239 元，不新增预算。模型沿用 `qwen3.7-max-2026-05-20` 和原参数；错误响应按原保守上限记账，不能重试到成功。实际 API 使用须在输入、参考、实现与预算冻结且离线检查通过之后。

完成这组受控比较即停止。本轮不再扩大自然任务运行；识别受控错误不证明自然抽取或跨任务泛化已经可靠。若错误版本仍全部批准，如实报告；若仅靠大量拒绝提高检测，也不能称为改进。

## 实际结果

全部 10 次请求完成，无响应格式或提供方错误。每个表格单元描述两条返回要求，合取容器另行核查。

| 结构版本 | 旧审核 | 回译审核 |
|---|---|---|
| 正确 | 两条均保留 | 两条均保留 |
| 删除条件 | 两条均误放行 | 两条均误放行 |
| 扩大目标 | 两条均误放行 | 两条均误放行 |
| 交换分支 | 两条均指出 `conditions.0` 错误 | 两条均指出 `conditions.0` 错误 |
| 等价合取 | 两条及容器均保留 | 两条及容器均保留 |

两种审核都检测到 **2/6** 条受损要求，保留 **4/4** 条正确或等价要求，没有额外记录拒绝。按结构变体看，都只发现三类错误中的分支交换。这些要求来自同一基础任务，不能当成六个独立样本。记录支持与来源完整性分别保留，不能把模型返回 `complete=true` 当成独立语义证明。

已核实实际 HTTP 请求包含完整回译；删除条件版本明确包含 `UNCONDITIONAL`，没有被传输遗漏或裁切。该版本仍被放行，理由重复了正确的原文含义，未指出结构缺失；目标扩大版本同样被批准。这支持“本次审核对缺失条件和扩大范围不敏感”的诊断，不能据此断言模型看到了某字段或推断其内部决策机制。

原文、原始记录及正确的定义文字仍在请求中，因此本次检验的是**在现有单次审核里增加直接结构读法与双向核对说明**，不是所有可能的结构回译方案，也不是完全屏蔽说明文字的逐命题核对。未检测到增量收益，不等于证明结构回译普遍无效；但不支持将这个具体提示升级继续用于默认付费调用。

新审核未通过预定的“扩大目标”检测门槛，故**没有执行可选局部补丁**，也未事后改用较容易的分支交换来展示修复。未执行新自然任务抽取、候选判断或结构价值比较；不能据此报告这几项的改善。

## 成本、检查与停止决定

旧审核五次按冻结费率记账 **0.846480 元**；回译审核五次 **1.053684 元**；合计 **1.900164 元**，低于 5.5 元审核上限。依据返回用量及调用前费率计算，并非账户发票核对。一次性结算后授权账本剩余 **12.281075 元**，不是已核实账户余额。

本轮未增加测试用例。调用前完整 **110 项**检查通过；撤下付费提示并保留调试输出后，**29 项**相关检查通过。五个结构变体均可编译，说明本次失败是语义审核漏检，不是无法生成图。已用冻结执行源码对全部十次 HTTP 请求、响应、结果和预算完成精确离线重放；没有联网或再次记账。

保留三项直接用途明确的修改：联合填写条件／目标／要求的抽取提示、与构图共享解释规则的调试回译、可指出并修复空列表的审核接口。撤下没有展示收益的增量付费提示，并停止本轮扩量。当前关键缺口仍是：即使结构明确缺少条件或扩大目标，审核也可能依据正确的定义放行。

如继续方法开发，下一项待检验的改变应是让审核对每个实际目标和每个缺失条件分别给出有来源依据的判定，避免用单个记录的总体批准代替这些判断；先复用本组已暴露对照检查，不增加 reviewer、schema 或自然任务规模。这只是下一步研究假设，本轮未实现或验证。
