# 原始安全程序自然来源的固定开发准备范围

## 研究用途与选择前信息

本次准备检查自然安全任务能否同时提供原始程序、单项提示要求、可观察的非目标行为与独立安全测量。它服务Graph完整要求绑定与下游安全评价的资料缺口，不构成新的科学阶段，也不激活正式协议。原有SQLite和目录任务的模型基线均已安全，不能通过增加这些任务的随机种子创造改进空间。

选择依据仅为Vul4Py公开目录的自然任务身份、仓库URL和修复提交身份。目录固定到 `tabudz/vul4py` 提交 `f80f861012cb7b7cfeca7323be51d33e72eaf8f3`，原CSV对象为 `f6e37ec7f618d391d8d1058aba47d6f9b8570229`。选择前已检查公共准备及执行程序，发现其候选判定允许缺少功能测试；该发现固定了本项目的独立资格要求，尚未读取任何具体任务程序、测试、补丁或方法表现。

## 单次有界来源范围

将目录按大小写不敏感的仓库URL路径分组。每组按 `SHA256("2026111214:" + vuln_id)` 选择摘要最小的身份，再按同一摘要排序，固定前24个仓库组，共24项身份。公开目录全部100项身份保留，目录身份由Git原生命令独立核对。选择不使用漏洞类型、难度、测试是否通过、Graph关系、JCI分数、候选排名或模型结果。

本次来源准备限定一个获取轮次，范围为这24项身份，不因失败、缺失或同源关系替换身份，也不追加来源。仓库重定向、项目更名和共同代码谱系需要按实际来源说明；24个URL组不自动等于24个独立谱系。按固定列表第一项取得具体原始资料，用于检验来源取得与资格步骤；其结果不能改变其余身份、顺序或来源目标。所有取得、未知、失败与尚未取得状态分别保留，不将目录身份直接计为合格实验任务。

## 具体资料与资格边界

具体资料包括原始漏洞版本、自然来源的问题说明或安全公告、相同源码版本中的公开API合同、已有合法输入测试及上游安全回归测试。目标操作、要求已表达状态、允许的输入范围与可保留行为分别判断。不能因程序含有漏洞推断提示缺少安全要求；明确提出修复漏洞的自然任务也不能自动充当ADD来源。来源筛选与干预措辞准备分别执行。

修复提交身份可用于定位原始父提交及独立测量资料。实际修复补丁、答案位置、修复代码和测量测试答案不能进入Graph或平面表示制作上下文。来源准备人员接触这些材料的情况需要单独记录。Graph与平面方法取得相同的原始程序、自然说明与允许合同，参考在方法输出前固定。模型输出不参与来源选择；任何后续方法开发反馈均需记录其开发暴露身份。

具体任务在独立隔离环境中取得实际安全与局部功能资格：相同合法输入测试应在漏洞及修复版本通过，安全检查应区分相应版本，并逐项确认相关断言。至少一个实际通过的合法输入检查才能支持该测试范围的功能判断。没有测试、跳过、收集错误、安装失败及不适用的情况保留未知或对应失败，不接受无测试的成功返回码。有限程序检查不认证完整功能性。

已知漏洞版本不等于实验模型的基线输出；后续还需固定干预和随机化设计并实际生成新代码，才能评价修改要求的安全效果。本次目录固定不授权付费调用或新模型服务，不读取受保护评价任务。来源准备及表示诊断保持开发身份，不因取得上下文而声称随机上下文合格、未来环境稳定或JCI有效。
