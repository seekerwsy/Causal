## 研究目标及当前边界

项目 CausalGuide / Prompt Mechanism Study：从自然编程任务的提示中提取 Prompt TSG，表示要求、操作、对象、条件与范围，构造一个完整要求的 Atomic ADD/REMOVE 政策，优选、冻结，然后通过随机提示编辑和独立代码测量检验安全产出。希望有学术创新，特别是结构表示如何帮助提出、定位、选择可验证的政策，而不是仅证明“提示加安全要求有时有效”。

截至 2026-09-26，仓库 README 指定唯一规范 docs/protocol.md（phase-context-policy-v3），状态 SPECIFIED_DRAFT，正式 Discovery/Confirmation 尚未激活。七阶段：表示→优选→假设冻结→干预/随机化→测量→结果装配→推断/报告。现行正式草案的 Atomic Full 仍为 FCI 邻接准入＋RD 排序，对照 RD-only 使用相同候选、行、折、分数、K，仅去掉门槛。下面开发实验没有自动修改这条规范。JCI/RFCI 只是可选探索附录。

不可跨越的边界：TSG 边是语义关系，不是因果边。代码只供应独立测量的安全/功能结果，不是主 PAG 变量或中介。主分析 assigned-arm、去重 task-unit ITT；同任务多种子/版本不是新增独立 N。分配后忠实度、依从性、生成成功、非目标漂移只能诊断，不能筛分母。主端点是 Oracle 可评估安全代码产出；语法有效、Oracle 支持/unknown、功能、联合成功分别报告。unknown 不等于 insecure，未表达要求不等于代码缺保护。ADD 可从原文未表达要求开始，REMOVE 必须有可定位的源要求；均保留非目标行为。主线 Atomic-only，不恢复 Pair/多安全因素 factorial。

## context 必须区分的三件事

S：语义适用范围。AnalysisScope = security_pattern_id、context_query_id、language_scope、api_scope、task_archetype_scope；context_query 匹配任务操作/对象/条件，不是随机实验环境。
A：四臂随机指派 Target / matched No-op / Style / direction-compatible Generic-security。这才是 JCI context 的候选，但目前没有合格的真实跨环境系统变量矩阵。任务/政策/realization/model 区组内平衡分配请求槽位和种子，结果前冻结。Target−No-op 共享定位；Target−Generic 还包含定位差异。
M：干预前任务结构的效应修饰因子。例如既有对象更新、多目标集合。M 不是代码生成后的行为，也不自动随机。模型、语言、来源等自然环境不能默认满足随机 context 假设。
X0 是原提示完整要求状态，X1 是编辑后文本要求状态，均不是模型遵从或代码安全。

## 已真实执行：FCI/GFCI/JCI-FCI 有真值模拟

50份数据 = 2 SCM × 总n[14,24,50,200,1000] × seeds[11,22,33,44,55]。200/1000及两SCM先固定，14/24/50是看过大样本结果后补加，全部探索性。每行独立模拟单位，C,Z,U独立 Bern(.5)，U隐藏，sigmoid记作s。
causal：X~Bern(s(-1+2C))；Y~Bern(s(-2+2X+1.2Z))。
latent_null：X~Bern(s(-1+2C+1.5U))；Y~Bern(s(-2+1.8U+1.2Z))，没有X→Y。
观测骨架都X–Y、Z–Y；合并C后都C–X、X–Y、Z–Y。真投影分别C→X→Y←Z和C→X↔Y←Z。模拟的C外生且无context-system潜在混杂，满足JCI1/2。

执行300次：causal-learn FCI、Tetrad GFCI 各50（同一C=0子集，约一半行；X,Z,Y）；causal-learn pooled FCI50（全部行C,X,Z,Y，仅JCI0表示，不冒称背景约束）；R pcalg真正JCI0/1/12各50（同全部行）。FCI/GFCI均G² alpha .05；GFCI BDeu ESS10、structureprior0。pcalg2.7-12 disCItest、nlev2、adaptDFfalse、selectionBiasFALSE、contextVars=C、NAdeleteFALSE。300次无后端异常，原始输入、PAG端点、警告均保存并独立重算指标。

|总n/场景|观测FCI完整骨架|观测GFCI完整骨架|pcalg JCI12完整骨架|JCI12正确X–Y端点|
|---|---|---|---|---|
|200 causal|5/5|5/5|5/5|X→Y 4/5，另1次错误X↔Y|
|200 latent_null|4/5|4/5|2/5|X↔Y 2/5，另3次漏X–Y|
|1000 causal|5/5|5/5|5/5|X→Y 5/5|
|1000 latent_null|5/5|5/5|5/5|X↔Y 5/5|

n1000同pcalg同数据：JCI0 causal为X o→Y（5/5）；JCI1/12变X→Y（5/5）。latent_null JCI0/1/12都是X↔Y（5/5），不能把所有进步都归给约束。JCI12另给C→X，JCI1 C o→X。FCI/GFCI骨架47/50相同；3次小n GFCI多找回一真边，没有普遍优势证据。14/24/50严重漏边。150次pcalg调用15次警告n<n.min（12次n14，3次n24），内部把受影响检验当独立，NAdeleteFALSE不补救，不能当无关系证据。

具体n1000 seed11：causal C0时X=1为132/520，Y=1为168/520；C1为362/480、252/480。latent_null C0为234/520、205/520，C1为402/480、185/480。C显著改变X但零作用场景不改变Y的机制。反例n200 causal seed22：C0 X31%、Y39%；C1 X69%、Y50%，JCI1/12却错判X↔Y。

局限：观测FCI/GFCI用半数行且变量不同，不能与全行JCI直接排名；Python/R CI实现不同。只有同pcalg JCI0/1/12比较较干净地隔离约束。仅两简单SCM、五种子、二元变量；未模拟真实四臂、确定性编辑、同任务重复/共享U、Oracle unknown。n1000不是现实样本量门槛。无真实任务图真值，亦无全自动TSG增量证据。
