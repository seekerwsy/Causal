## 先回答哪一个研究问题

下一阶段沿用主协议的研究问题。主要安全效应仍是按分配臂、去重任务单元的
Oracle-evaluable secure-code yield；Atomic 主对比是 TARGET − NOOP，Pair 主对比是
四格交互。五臂开发结果中的 TARGET − BASELINE 有解释价值，但不能替换正式主对比。
显著性不是开发验收条件。正式效应的判定仍需要同时区间、预先固定的实用阈值和
测量资格，不能通过减少比较族或把种子当任务来获得。

当前工作优先完成适用范围内的表示与测量资格，然后以独立自然任务支持正式选择器
比较。SQL、命令、路径不能因本轮收益不同而临时增删。某一边界没有合格 Oracle 时，
保留其缺口；可以在正式结果出现前另行冻结较窄研究范围，但必须说明对应问题的变化。

## 多种子能解决什么

每个任务、每个臂先平均种子，再平均独立任务。两模型共享任务，模型增加一个效应
坐标，不增加独立任务数。当前 12 个任务分为 SQL 3、命令 8、路径 1；10 个种子只能
减少这些任务内生成概率的估计噪声，无法提供新的任务总体证据。

本轮开发精确符号翻转检验的最小双侧 p 值，在 n 个任务的非零差异同方向且达到
极端统计量时为 `2 / 2**n`。因此 n=3 时至少为 0.25，n=8 时至少为 0.0078125。
若 24 项比较中仅一项达到最小 p 值，其 Holm 值至少分别为 1 和 0.1875；其他比较的
排序会影响后续调整，不能将这一算例当作任意情形的精确调整值。零差异会进一步降低
有效信息。这个限制说明开发批次不适合用“是否显著”验收，不说明实际零差异被检验隐藏。

更直接地，本轮每项比较最多只有八个任务，原始双侧 p 不可能低于 0.0078125，而
24 项 Holm 的第一步阈值为 `0.05/24 ≈ 0.0020833`，所以这个开发设计本来就不能
作 0.05 水平的显著性确认。增加到十个种子不会改变这一任务数限制。本轮验收的是
分配和测量可复查、波动能被量化、方法缺口被定位，不是得到拒绝零假设的结果。

种子诊断报告每任务臂的成功次数、代码不同版本数、Wilson 区间和固定任务集对比的
Monte Carlo 标准误。重复代码保留为原始分配；不能去重后改变分母。全成功或全失败时
经验方差可能为零，Wilson 区间仍有宽度。共享服务错误和后端非确定性不由种子标签保证
独立性；这些诊断不是任务总体置信区间。

## 结构价值怎么公平比较

| 比较 | 唯一有意变化 | 必须相同的部分 | 输出及边界 |
|---|---|---|---|
| Atomic Full / RD-only | 是否读取合格 FCI 邻接 Gate | 候选总体、任务、自然状态、折、RD 分数、排序规则、K、干预及确认结果 | 现有 RQ2a 固定分母 meaningful Yield@K 的描述性差；不为差值临时添加显著性检验 |
| Pair Full / No-Relation | 是否读取 Prompt TSG 关系 Gate | 兼容候选总体、四格支持、谱系重叠、折、二阶分数、K、干预及确认结果 | 现有 RQ2b 同类固定分母结果；Pair 不要求 Atomic 父项先被选择或支持 |
| Full TSG / 扁平节点与要求列表 | 是否显式提供对象间关系及关系锚点 | 完整同一来源、相同节点事实和证据、候选任务政策集、模型、上下文上限和调用预算 | 只列为独立表示研究提案；不是当前 RQ2，也未实现或执行 |

表示研究的最小可审设计应逐任务提供同一份节点与要求事实，关系版额外提供边。
扁平版保留原文、节点类型、文本证据和标识，但去掉跨节点端点绑定字段，防止关系从
其他字段泄漏。两版给同一候选要求及任务，要求输出操作/对象选择、保留的非目标行为、
编辑位置与干预文本。扁平版可以依据原文解析绑定，不能先经过“必须有图边”的入口、
再把必然失败称作图结构优势。没有独立、盲于版本的来源核对，机械字段命中率不能
称作语义准确率。不同表示长度导致的 token 使用差异需如实报告。

该提案要先冻结单独协议、候选总体、分配/评审规则、结果族和预算，才可开始新的
模型比较。现有开发任务可用于形成规则，正式检验必须使用未参加规则开发的独立
材料。至少分别衡量：关键对象/操作定位、真实语义缺失与歧义、非目标要求保留、
可协议化比例；只有随后独立安全测量才能回答是否提高安全产出。节点更多或图更完整
本身不是安全效应或因果机制证据。

## 表示与干预的实现和验证方案

本节于 2026-09-12 补充，范围状态、逐因素绑定、局部增删、中性改写检查以及开发执行入口
已完成首轮实现和离线验证；独立资格验证、自然支持及正式研究仍待完成。活动草案已同步
这些语义边界，状态仍为 `SPECIFIED_DRAFT`，不赋予正式角色、不消费资格保留集。
它细化现有 representation、
intervention/randomization 和 measurement 步骤，其余仍沿用唯一七阶段路径。
“覆盖研究目的”指在声明的任务范围内能够有效检验问题，不是预先保证正向效果，
也不是证明所有自然语言 Prompt 均可无误表示。

### 1. 统一要求状态、作用对象和干预范围

保留现有概念、实例、关系和原文证据，只补齐因素作用范围。全局政策固定要求的
操作性定义、适用上下文、对象角色及范围规则；每个任务绑定自己的操作、对象集合、
适用条件、来源状态及证据。任务内节点 ID 不进入跨任务的概念身份。

每个因素的任务绑定明确回答：

```text
哪项要求 + 哪次操作 + 哪些对象 + 什么固定条件 + ADD/REMOVE
来源表达状态 + 支持该判断的原文范围
```

状态查询、候选支持、编辑渲染与编辑核验必须读取同一绑定。继续使用 PRESENT、
ABSENT、NOT_APPLICABLE、UNRESOLVED；未做判断或漏抽不能成为 ABSENT。整操作只有
部分对象受到约束时，应保留对象级状态，汇总的“部分覆盖”只作诊断，不能压成一个
用于任意对象干预的二值状态。原文明确的“所有输入”可按冻结范围规则适用于相应
对象集合；某个输入有要求不代表其余输入有要求或没有要求。

例如，同一 SQL 查询使用 latitude 和 longitude，原文明确只要求 latitude 参数
绑定。应分别审查两个输入的要求状态；只有确认 longitude 的要求确实未表达后，
才允许为它 ADD。输入关系或原文范围不清楚时保留未知。不得把安全要求未表达
解释成生成代码缺少保护。

同概念在两个对象上的要求若要成为两个研究因素，先固定可跨任务解释的对象角色和
范围政策，使两个因素具有独立、明确的身份，不能仅复制同一个 feature ID 或把任务
局部变量名当成新的通用概念。条件是作用范围的一部分，不因干预而改变；这不启用
跨上下文效应比较。

### 2. 在同一编辑路径内完成 Atomic 和 Pair

Atomic ADD 仅增加绑定范围内的一项要求。REMOVE 必须有明确的正向来源要求，
以及保留其他要求的中性删除或改写规则；不能添加“不做防护”或不安全实现指令。
若一句话同时约束两个对象，删除其中一个对象的要求需要先验证局部中性改写，不能
直接删除整句。原文未要求的行为不补成新的业务要求。

目标与 NOOP 使用相同对象、操作、条件及共用指令；长度匹配安慰剂与一般安全提醒
仍按现有规则单列。TARGET−NOOP 保持主比较。字面保留和图投影检查只证明有限的
操作约束，不能单独证明语义完全相同或生成代码保持功能。

Pair 的两个因素各自持有上述完整绑定，可属于同一操作或两个不同操作。沿用现有
兼容性判定及四格任务束：00=N1+N2、10=T1+N2、01=N1+T2、11=T1+T2。
四格保持相同非目标要求；10 不得顺带实现因素 2，01 不得顺带实现因素 1，11 不得
引入第三项要求。无法独立改变、互斥、蕴含坍缩或冲突者不能作为可兼容 Pair。
不要求 Atomic 父项先被选择或有效。

能证明两个编辑可交换时使用固定次序；否则依现有协议，将两种次序作为前瞻冻结的
joint realization，不能事后保留有利次序。表达措辞及权重沿用现有 realization
政策；每个任务政策分配一个 realization，不自动将所有措辞交叉执行。结果解释为
该范围和措辞分布下的 Prompt 政策效应，不宣称抽象语义概念的普遍纯效应。
随机化整段文本并不自动识别其潜在语义因素，这一限制也见
[Fong 与 Grimmer 的原始研究](https://onlinelibrary.wiley.com/doi/10.1111/ajps.12649)。

| B. 自动表示与干预语义 | 规则冻结后，在未参与规则开发的独立来源参考集执行实际抽取，并核对实际输出的干预文本 | 关键对象/操作绑定、来源状态、错误断言、作用范围、非目标要求保留、完整任务覆盖与可协议化比例 | 自动抽取质量必须实际调用冻结抽取器；模板编辑可离线，若用 LLM 编辑则须验证该实际执行器 |
| C. 测量资格 | 拟纳入语言、边界和代码形式中的已知安全、不安全、未知例，以及代表性的实际生成代码 | 安全混淆、未知处理、差异性误测；功能可见矛盾、合理自由度与真正不可评分别处理 | 不以“模型说通过”或语法通过替代结果正确性；不要求资格覆盖未使用的语言 |
| D. 科学效果与结构价值 | 冻结自然任务支持、选择器与实际随机化代码实验 | Atomic 效应、Pair 四格交互、未知与功能变化；相同候选和预算下的结构 Gate 比较 | 必须真实生成和独立测量；合成功效模拟不能替代 |

A 层最小覆盖六类边界：多操作同概念、同操作多输入、单个/全部/部分范围、共享语句
的局部删除、条件与否定的作用范围、同操作及跨操作 Pair。每类保留可判定和未知/不兼容
的例子。合成或改写例只用于方法开发，不进入自然 Discovery 支持或独立样本量。
固定例子的期望行为应全部通过；这不是要求自然任务泛化正确率达到 100%。

B 层的参考判断先于被评估模型输出完成，审查者不读取代码结果或选择器排名。争议
经独立核对后裁决，不能裁决的保留未知。按两个方向审查：从来源到图检查关键遗漏，
从图回到来源检查无根据的断言；字符串引文命中本身不足以证明语义正确。
干预审查者知道允许改变的要求，核对实际差异，但不读取生成结果、方法预期优势或
选择器身份。再次调用同一抽取器得到一致答案不构成独立语义证据。

至少逐任务报告关键绑定正确率、错误 ABSENT 率、要求错绑/越界率、非目标要求改变率、
未评估/无法编译比例及四格完整有效比例；节点/边统计可以辅助，不能让大图支配主指标。
完整图覆盖与本比较必需的绑定分开；不重要的遗漏作为限制，不自动排除整项任务。
所有预先选择的评估任务都要记录，包括失败和弃答，不能只计算成功图上的准确率。
关键错误率需同时报告不确定性；上限容差、所需精度、任务数与一次验收停止条件必须
在查看资格输出前冻结。本节不凭空宣布 90% 或 95% 为已接受阈值，也不沿用旧任务上的
命中率阈值证明新的对象级能力。有限样本零错误不能证明总体零错误。

开发材料可以用于制定规则；独立验收材料不能在调试后继续作为独立验收证据。
表示开发与效果估计的样本分离也有文本因果推断的方法依据，见
[Egami 等人的原始研究](https://pmc.ncbi.nlm.nih.gov/articles/PMC9581481/)。
本项目继续保留既有开发、资格、Discovery、Confirmation 的用途边界，不另加数据阶段。

C 层的 Oracle 只验证拟纳入比较的安全属性。实际代码安全、Oracle 是否可评、功能、
联合成功分别记录。功能参考是完整未干预输入；只对可核查要求给出判断，不把未知
helper 自动判为失败，也不因规范部分缺失跳过本可测量的安全比较。对可能随臂而变化的
代码形式分别检查误测，评估器不读取臂标签或干预文本。失败响应保留原始信息，不
事后猜测失败类别。冻结的历史错误不回填成新结果。

### 5. 研究层的充分性和停止条件

在表示、干预和测量各自通过适用范围资格后，核对真实独立任务容量。Discovery
使用自然来源的状态支持；Pair 检查自己的四格、共同谱系覆盖及分折，不借 Atomic
结果准入。构造出的实验四格不等于自然发现四格。需要 D0 时仍仅按冻结上下文目标
进行一轮盲于结果、选择器及候选状态的自然来源补充。

独立 Confirmation 沿用 TARGET−NOOP、Pair 的风险差交互、任务单元 ITT 和已规定
的同时推断。先按冻结的实际任务—效应—realization 支持表复核功效；目前三十个
假设情景不能直接授权某个正式样本量。分配后的不遵从、非目标漂移、失败及未知
保持原分配和对应状态；不删除失败任务，不将所有基础设施失败猜成安全产出零。
随机化前无法协议化的槽位、任务束和 realization 失败也保留，不以有利候选替换。

当前结构价值仍通过 Atomic Full/RD-only、Pair Full/No-Relation 的同候选、同任务、
同评分、同 K 和共用确认结果比较，按活动 RQ2 报告描述性 Yield@K。不能把这个
比较升级为“完整 TSG 优于任意扁平表示”。后者仍是上节单独列出的未启用表示研究。
Context-modifier、Pair 模式标签、跨措辞或跨模型稳健性结论只在各自规则前瞻冻结后
报告；正负交互本身不自动证明协同或拮抗。RQ4 的专家解释评价保留为独立人类研究，
不由图质量、模型评审或代码实验替代。

实施顺序为：先用已有材料完成范围绑定与 Atomic/Pair 边界，再冻结候选实现及独立
验收规则；随后进行表示/干预和测量资格，最后绑定真实自然支持开展获授权的科学
实验。每层达到其冻结条件后进入下一层，不反复扩大开发检查。资格未过则记录失败
并停止相应范围；若修改规则，原验收材料计为已暴露，不反复使用同一份保留集。
正向收益不是实现或资格的验收条件；结果为零或有害时，仍应完成并报告有效实验，
但不能声称方法改善了安全性。

## 下一步停止条件与可执行顺序

1. 保留本轮冻结结果和两例功能评审的 unknown→fail 误判。先用已暴露材料明确
   “可见矛盾才判失败、无法验证保留未知”的资格准则，并准备独立盲评检查；同一批材料
   反复调提示不能获得独立资格。若不能满足，限制功能结论，不再补一轮有利结果。
2. 只验证拟纳入的 Python 操作边界和代码形式，覆盖已知安全、已知不安全、未知及
   可能的臂间差异性误测。表示检查同时看完整覆盖和比较必需绑定，后者不足则阻塞相应
   协议化，不能把不重要的节点缺失推广为整任务排除。
   正式运行前，还需在现有请求记录处保留未正常结束的原始响应与 finish_reason，区分
   已知的终止无代码、代码无效和基础设施/溯源失败。前两类按主协议为零产出；后一类
   不能猜测。当前七次生成失败缺少原始 envelope，保留原规则下的阻塞，不能事后补成零。
3. 上述有界功效网格已完成。下一步在明确的研究范围下核对已有自然来源的上下文
   容量，再作总体与预算决定；当前单政策支持记录不足以落实模拟中的任务数，也不是
   最终容量上限。需要 D0 时，只允许一次按冻结上下文容量目标、盲于结果、选择器与
   候选状态的自然来源补充。不得为 Pair 四格或有利效应合成、改写或选择采集任务。
4. 只有资格与正式协议授权齐备后才分配角色、冻结 Discovery，再按唯一主路径执行。
   在 Confirmation 前，把同一功效假设绑定到真实任务—效应—realization 表重新检查。
   不合格则保留阻塞结果。context-modifier 推断与 Pair response-pattern 标签继续关闭。

本阶段完成的是可复查的本地开发证据、检查器语义修正、三十个假设情景的功效规划
及这份下一阶段设计。功能资格、自动表示资格和正式任务/功效冻结仍是明确的研究缺口。
