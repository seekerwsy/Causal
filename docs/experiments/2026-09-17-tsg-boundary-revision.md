## 已实施的修订

修订前快照为 `fc85ff79`，保存当时未提交的协议、论文及新增附录源文件。
约 900 MB 的历史实验展开目录保留原位，没有重复纳入代码快照。
实现提交为 `4787b8db`；本轮没有继续修改论文。

- `task` 表示整个运行任务的边界，编译器不再把要求广播到所有运行操作。
- `targets` 明确直接对象，可以指向原文支持的整体函数；函数的返回、接口或累计资源约束不会自动约束每个内部操作。
- `each` 保留开放的目标类别与任务／单个操作边界，不把已抽取实例当成完整集合。
  整体和全称要求进入契约与 TSG 的 `requirement_scopes`，条件继续由既有条件边承载。
- AND／OR／NOT 父节点使用 `composite`，保留成员和共享条件，不再另造一份目标义务。
  只有合取成员被独立断言；复合否定、替代和不明确结构继续保留。
- 模型先填写结构与绑定，再写完整谓词。`atom` 仅表示结构叶子；候选仍须依据完整来源、条件、目标和单因素定义接受原有语义审查。
- 未投影的整体／全称要求不能自动成为局部候选，也不能支持局部“未表达”的结论。
  它们继续参与来源影响范围检查。完整系统／用户原文始终保留，模板重复表达不自动构成因素状态改变。

当前没有实现全称规则到任意局部实例的语义投影；这部分保留表达，暂缓局部使用。
这是需要报告的覆盖限制。程序也不能证明任意自由文本谓词只包含一个实验因素。
候选提示的语义约束已更新，但本轮没有调用模型执行开放候选发现。

| --- | --- | --- | --- |
| 旧版 | 0 | 0 | 2 |
| 新版 | 0 | 0 | 2 |

零接纳时准确率未定义，不能称为 100% 正确。这两个因素来自同一个 pandoc 任务，
不是两个独立自然样本。图书任务用于检查功能范围与条件保留，不据此判定所有 SQL 候选不可用。

将同一个复合源节点提交为两个不同单 API 因素，现有候选构造程序在两版均拒绝：
`source requirement node cannot be split into different candidate meanings; correct the source TSG first`。
精确请求、提案和拒绝结果保留在
[`candidate-probes`](../../data/method/tsg-boundary-revision-v1/candidate-probes/summary/results.json)。
可接纳候选为零，因此实际 Prompt 编辑阶段未启动；没有用人工拆图替代自动结果。
不能据此声称编辑质量提高。
