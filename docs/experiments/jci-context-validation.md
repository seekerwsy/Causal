# 随机编辑环境与条件共享的机制验证

2026-10-29 的执行授权用于验证此前讨论的 Graph/JCI 方法设计。研究身份为
`NON_CLAIM_CONTEXT_MECHANISM_SIMULATION`，使用预先声明的概率机制，模型调用数量为零。
现有真实模型材料缺少随机编辑环境和完整版本分布，因此没有被改写成新设计的数据。
本文件规定当前机制验证的输入、行为与证据边界；已有冻结研究保留其原始规则。

## 变量与目标

每项模拟候选具有独立任务总体和一项二元处理。A 表示目标修改或对照，E 表示目标或
辅助编辑环境，W 表示分配前属性，Z1、Z2 表示准备完成的版本属性，Y 表示二元结果。
两个编辑环境分别具有固定的四版本分布。A 与 E 独立随机分配，联合概率为 1/4。
目标是 E=0 下实际版本分布中的平均处理效应。模拟没有宣称 Z 是自动提取的 Prompt TSG。

共享问题为 `Y independent of E given A,W,Z_H`。结构搜索保留实际分离集合；如果该集合
与目标查询不同，程序另外检验目标查询。每个目标条件单元要求两个环境各有至少两个
独立结果，辅助环境比例介于 0.1 和 0.9 之间。统计检验没有拒绝独立性只产生共享候选。

固定结果模型的均值估计为：

\[
\widehat\mu_{a,0}=\frac1n\sum_i\left[
\sum_vq_{i,a,0}(v)\widehat m(a,W_i,Z_{i,a,0,v})+
\frac{\mathbb 1(A_i=a,E_i=0)}{1/4}
\{Y_i-\widehat m(a,W_i,Z_i)\}\right].
\]

完整版本积分、正确分配概率、独立拟合及一致性成立时，随机分配修正抵消错误预测的
均值偏差。共享假设影响预测和方差，不能成为处理效应识别的附加前提。分数不执行截断。
全部预算用于目标环境的比较使用分配概率 1/2。

## 七个阶段

1. 表示：固定四项模拟候选、分配前属性、四版本属性与概率。真正的 Prompt TSG
   构建质量、完整要求绑定和信息相同的 Flat 比较需要独立语义审计，本次没有实施。
2. 优先选择：真实 pcalg conservative FCI 使用共同条件检验；共享模型以不同 Z 子集
   合并环境。每个单元使用固定 Beta(1/2,1/2) 预测规则，空单元也由该规则定义。
3. 假设冻结：执行前保存配置、实现归档、六种机制、十六次重复、四项候选、两项提名、
   独立任务角色、全部比较和收益门槛。配置为 `configs/jci-context-validation.json`。
4. 干预与随机化：每项候选使用 256 项 Discovery data、128 项 Calibration selection data、
   128 项 Calibration ranking data。每项任务只有一个分配结果，三个角色的任务身份互异。
   这些英文名称均使用完整形式。
5. 测量：根据声明机制采样二元结果。共享成立、遗漏措辞效应、潜在混杂、环境完全编码
   版本属性、异质效应抵消、接近实用门槛均保留。结果属于机制模拟。
6. 结果组装：Discovery data 拟合结果模型；Calibration selection data 以目标环境预测
   均方误差选择模型；Calibration ranking data 计算随机分配修正效果并选择两项候选。
   选择全部固定后，产生独立 Confirmation data。提名仍然存在选择偏差，报告不把提名
   数据上的最高分作为确认效果。
7. 推断与报告：每项候选使用 1,024 项独立确认任务，每项任务各产生一个目标修改和一个
   对照结果，保持完整分母。四项候选使用同时 Hoeffding 界；下限超过 0.04 才通过确认。
   方法间比较按独立模拟重复配对。保存的 Bonferroni t 区间为小样本近似，零差异的
   退化区间不能证明方法等价，也不能提供分布无关的有限样本保证。

## 对照与诊断

- 仅使用目标环境结果拟合、各环境分别拟合、直接合并全部属性。
- 对全部四个条件子集直接执行共享检验。
- JCI 产生的分离集合，以及获得相同随机分配知识的 FCI。
- 真实共享集合、真实图形独立关系、精确总体条件独立关系、真实最优两项候选。
- 相同总生成预算全部用于目标环境；该比较将原模型选择预算也用于拟合固定结果模型。

直接共享检验对应本次有限属性空间中的条件结果不变性检查；本次没有复现文献中完整的
效应不变性学习算法。效应共享而结果基础水平变化的条件仍需单独的比较设计。

本次 JCI 与相同知识 FCI 调用相同的 pcalg JCI12 过程，均知道 E 与 A 随机分配、相互
独立且独立于 W。它们是算法等价检查，不构成两个不同算法之间的独立竞争证据。
当前下游只使用分离集合，没有使用定向信息建立额外的共享候选。因此，本次实现没有
提供 JCI 定向信息带来独立收益的机制，图形变化也不能作为策略收益。

结构搜索遇到没有支持的条件检验时返回 `insufficient_support`，该候选保留分别拟合的
结果模型。pcalg 2.7.12 的 conservative triple 检查不能处理未知检验值，因此程序明确
终止该次图形搜索，避免把未知转换为独立或依赖。该状态不删除任何随机分配结果。
共享候选另外检查目标支持范围，完整保留失败和不支持的查询记录。

## 执行与独立验证

使用 Python 3.12、NumPy 2.5.1、SciPy 1.18.0、R 4.1.2、pcalg 2.7.12 和 jsonlite。
在仓库根目录运行，设置 `OPENBLAS_NUM_THREADS=1`、`OMP_NUM_THREADS=1`。

```text
python -m prompt_mechanism_study study jci-context-validation OUTPUT --plan configs/jci-context-validation.json --rscript PATH_TO_RSCRIPT
python -m prompt_mechanism_study study verify-jci-context-validation OUTPUT
python -m prompt_mechanism_study study diagnose-jci-context-power OUTPUT POWER_OUTPUT
python -m prompt_mechanism_study study verify-jci-context-power POWER_OUTPUT
```

各个输出目录必须为新目录。模拟执行保存 `source.zip`、`inputs`、`oracle`、`cells`、
`summary`；验证另存 `verification`。独立验证器重新计算随机任务、分配、完整版本权重、
条件检验统计量及随机检验概率、支持单元、拟合结果、预测选择、修正分数、提名和确认。
图形输出由真实 pcalg 产生；验证器不另外实现或认证 pcalg 的 FCI 算法。

确认能力诊断在看到本次结果后独立声明为 `POST_HOC_CONFIRMATION_POWER_DIAGNOSTIC`，
不更改原执行规则。它对任务差值的三项分布计算精确检出概率，并在预先写入诊断配置的
2 的幂次网格上寻找至少 80% 检出概率的样本数量。独立验证使用另一种二项条件分解
重新计算相同尾部概率。网格结果不宣称最小样本数量，也不能直接推广到真实代码结果。

## 真实材料的资格边界

本次实现没有构建新的自然任务总体、自动提取 Graph、调用 LLM 编辑提示或生成代码，
没有新授权的正式确认任务。版本改写和代码重复生成不增加独立原始任务数量。
下一项真实研究需要先固定独立语义审计、完整 Atomic ADD/REMOVE 资格、实际版本池、
两个编辑环境的共同支持、测量规则及按检出能力确定的预算。

合格环境必须在相同目标属性条件内仍有实际变化，并拥有独立结果观测。按版本位置
直接定义环境会造成确定性编码；制造随机噪声不能解决这种问题。现有历史结果没有
这些设计信息，因此保留原有开发用途。功能性、未知覆盖和安全结果应分别测量；本次
二元机制模拟不提供功能保持或联合成功证据。
