# 两项自然任务的上下文隔离语义检查结果

## 依据与执行

按 [事前固定的开发设计](2026-11-01-tsg-natural-boundary-design.md)，使用旧研究已暴露的 registration 和 privilege_order 两项自然开发任务。来源分别保留 llmseceval、securityeval 的旧记录身份，不重新抽样、不新增生成代码。选择用于检查既有顺序与语义边界，属于探索性开发，不能当作新自然总体样本。

两个参考上下文以及 Graph、强平面表示上下文均不继承父聊天，只读取相同原始材料包和根目录约束。它们不读取作者 Graph、历史判断或其他上下文输出。Graph 实际输出语义节点与类型关系；平面方法实际输出完整事实及关系，允许交叉引用和重建结构。两种表示回答相同的十二项来源命题，原始输出全部保存。

## 评分

两个参考上下文在十二项命题上全部一致。评分按每个原任务包含的全部六命题计算完整匹配；十二命题不作为十二项独立任务。准确引文逐字核对，全部有效。

| 自然原任务 | Graph 命题参考匹配 | 平面命题参考匹配 | Graph 完整任务匹配 | 平面完整任务匹配 |
| --- | ---: | ---: | --- | --- |
| registration | 6／6 | 6／6 | 是 | 是 |
| privilege_order | 5／6 | 6／6 | 否 | 是 |

共同参考对“辅助函数体必须保持空操作实现”判为 `unresolved`，平面表示也保持 `unresolved`。Graph 将原代码中的 `pass` 作为代码事实单独记录，但对该规范命题回答 `absent`，理由是没有明确要求保留函数体。两者反映对来源中代码片段约束强度的不同解释，本轮不能用自动化一致性将其提升为已证实的软件语义错误。

源提示既给出 `pass` 函数体，又要求通过这些辅助函数改变权限，并要求保留接口与非目标行为。因此，“代码片段是否是占位符、哪些既有行为必须保留”仍需要明确判断。结构化记录了代码事实和要求，并不自动保证查询对 absence 与 unresolved 作出正确区分。

另一项参考边界也必须保留：两个新参考及两种表示都把 registration 中用户名入库判为 present；旧作者源审阅曾对单数代词 it 的绑定提出争议。新的一致性不能单独解决该语言歧义。上述分数是对预先固定的自动化参考匹配，不是人工金标准准确率，也不证明所有相关输入和软件行为已经确定。本轮没有因该争议修改预定命题、参考或评分分母。

## 对方法的影响

这两项自然开发材料没有显示 TSG 表示增量，保留 Graph 低于平面方法的结果。每组只有一次上下文提取，未测量 token 消耗、重抽样稳定性及真实代码功能性，不能据此推广为自然总体优劣。

本轮定位出需要由表示消费者解决的具体边界：观察到的源代码事实、规范性要求、来源覆盖是否充分以及已知歧义必须分别保留。已有节点与关系本身无法证明某项要求不存在。后续表示查询和局部编辑应检验这部分证据状态是否得到正确使用，并给予平面方法相同证据和合理结构重建能力。
