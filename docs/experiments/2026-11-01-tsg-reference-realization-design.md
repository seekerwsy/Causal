# 混合语句中的完整要求移除与事实保持

本开发检查继续处理已经暴露的三个失败问题，来源与固定政策均沿用当前冻结材料。它检验 Graph 发现的指代和来源角色如何支持实际文本编辑。三个问题为事后选定的机制检查，不能评价 Graph 相对平面表示的独立收益，不重新评分既有方法输出。

纯删除可能使保留事实失去先行对象；移除整句又可能丢失事实。实际编辑允许使用既有逐字替换函数，将依赖目标表达的事实改写为原文支持的独立陈述。目标仅为删除显式规范要求；保留已观察结果、比较对象、原有条件、事实、不确定性和其他要求，不增加相反要求，不把一个未知判断改成确定事实。原文支持的事实中仍可出现相同数值、名称或比较表达，必须按语义角色评价。

## 首次实际输出

一个新的隔离实现上下文获得三个完整原文、原固定政策、首次来源角色测量、条件审查，以及两项已编译的规范 Graph 和实际准备诊断。它未获得历史 Graph／平面比较、旧编辑、旧评分或本轮后续评审。额外来源角色审查属于本开发方法的实际输入预算，不能将其结果与未获得同样信息的历史平面流程比较。

每项只提交一次逐字编辑列表。replacement 可为空或为原文语义支持的替换文字；不得反复抽取直到通过。实现可以明确保留 unresolved，全部三个原任务继续占据分母。无法安全解释的混合事实或指代不得由程序猜测。Matplotlib 的来源依赖歧义作为实际输入保留，不自动判定整个问题可用或不可用。

用现有 `apply_prepared_edits` 产生实际文本，并以独立引用位置及字符片段重建核对。全部首次输出冻结后，两个新的隔离评审只读取匿名原文、固定政策和实际修改后文本，分别判断完整目标移除、非目标含义保持、没有增加反向要求、没有解决无关歧义。每项使用 pass、fail、unknown 并提供逐字证据，不读取 Graph、角色判断、实现理由或彼此评分。

## 固定开发判定

机械产生实际文本，且两位评审的四项判断全部 pass、证据有效，才记为该原任务获得完整编辑产出。分母固定为三，未知和无效输出均保留失败。报告全部判断、分歧和文本，不作显著性、总体效果或独立表示收益声明。成功说明这类角色与指代问题在当前实际输出中得到解决；失败用于定位未解决的语义关系，不能反过来改写本轮输出。

该检查在 `tsg-role-dependencies-20261101/realize.py` 中准备输入、生成实际文本并评价，使用现有共同数据读取和逐字编辑函数。未来公平 Graph／平面比较需要给两个流程相同语义规则、原始信息、预算和重写能力，并在新输出之前固定目标和判定。当前检查没有这种比较设计，也不替代它。

没有实验代码生成、受保护任务、模型服务支出或正式协议激活。活动方法仍按现有规范进行独立语义审查；程序能核对来源位置和 Graph 关系，无法自行认证重写后的事实含义。
