## 1. 同数据算法对照：决策目标比结构邻接更关键

旧数据只用于预选 `RD−1.64×SE>5pp` 的保守效应门；新数据的 8×3×50 评价在新输出前冻结于 `frozen/algorithm.json`。对每份共同的随机分配 C、事前结构 X、干扰属性 Z 和结果 Y，按**已知 SCM 精确总体期望**评分，非训练样本自评。图门的明确定义是“仅当 C–Y 邻接且搜索可用时才采用同一个 X 分层 RD 行动”，并不是 FCI/GFCI/JCI 的原生政策输出。`honest-depth1` 是训练分裂与叶效应估计分开的浅树**适配**，不是论文软件复现。

风险与覆盖说明了图门的保护不能直接归功于结构发现。在有害机制 N64，FCI 门和保守分层门都不编辑，收益与有害编辑质量均为 0；零效应机制 N64，两者均无收益，但仍分别编辑 2% 与 4% 的任务状态。在近抵消 N64，FCI 门只覆盖 2%、收益 0.8pp，保守门覆盖 45%、收益 18pp，两者有害编辑质量均为 0；N1024 则分别覆盖 14%/50%、收益 5.6pp/20pp。来源代理失效 N1024 更有方向性：FCI 门覆盖 18%、有害编辑质量 3%、收益 2.58pp；保守门覆盖 46%、有害编辑质量 0、收益 8.74pp。因此本机制组没有观察到 FCI 门独有的安全保护，且更少行动有明显机会成本；但主实验没有前瞻冻结的覆盖匹配对照，不能将全部差别严格分解为“图信息”与“保守程度”。这里的覆盖和质量均是已知 SCM 下的策略评分，不是代码任务比例。

为补充这一机制判断，另在**看过主结果之后**作覆盖匹配诊断，不改变原冻结比较或主结论：对每个机制×N格，将无图的 X 分层 RD 行动独立随机稀释，概率设为该格图门平均编辑质量／直接分层平均编辑质量。因此对照的**期望编辑质量**与图门相同，期望真值收益与有害质量可直接按该概率缩放。三个图门的每条行动经检查确为原分层行动或全不编辑；72 个格的精确计算见 `tables/coverage-matched.csv`。FCI 的 24 格中，匹配覆盖后的图门收益相对随机稀释为 7 格较低、1 格较高、16 格相同（忽略浮点误差）；近抵消 N64/1024 均相同，说明这些格里图门没有额外挑中高价值的分层行动。来源代理失效 N1024，FCI 编辑质量为 18%，收益 2.58pp、有害质量 3%；同覆盖率随机稀释的期望收益为 3.13pp、有害质量 1.02%。GFCI 在该格亦为 1.91pp 对 2.26pp、2% 对 0.74%。这支持**在所测机制中，图门较少编辑并未伴随稳定的额外行动鉴别力**，且有一例反向选择。稀释率按已观察的每格结果设置，没有新的独立检验集，也不匹配每份矩阵的覆盖；这是探索性描述，不能证明图算法一般无鉴别力，亦不能取代前瞻冻结的同覆盖率对照。

精确抵消是已知忠实性压力例，留在旧开发结果中单列，不混入新八机制的适用条件排名。来源代理与稀疏属性机制明确给出真值、样本占比和可观测边界。Tetrad 与 pcalg 是不同后端；比较固定同一输入和 G² alpha .05，但后端差异仍是局限。新 3600 图均有输出、无记录的错误/警告；这不等于后端已被独立证明正确。

## 2. JCI：方向变化没有自动变成可行动信息

冻结的合法正例随机环境 C 只改变完整版本 B 的分配概率 `.25/.75`，C 不展示给代码生成器，B 不是局部合规或生成代码性质。已知 C→B 来自设计，不计为 JCI 发现。查询是：**粗 B 是否足以跨 C 合并版本效果，还是应记录并随机化更细措辞 W？** 直接基线在每个 B 内要求 C 两组各至少 10 行，且 `|RD|+1.64SE<15pp` 才允许合并。JCI 消费者只让任何可用 C–Y PAG 邻接否决该合并并提名更细版本对照；无邻接不能替代直接等价门。允许合并后用已知版本混合概率加权选择完整 B 版本。确定性 B=C、遗漏的 W 以及 U 同时影响 B/Y 分别压力测试正值支持、粗属性不足和违背 B 随机化前提。

在新 600 矩阵、1200 图中，JCI0 与 JCI12 的 PAG 整体矩阵在 590/600 数据上不同，但这条**事前消费者的行动变化为 0/1200**。合法粗 B 正例 N1024，直接门允许合并 36/50；遗漏 W 负例允许 0/50，JCI12 的 C–Y 邻接出现 50/50，却没有额外改变行动。B=C 全部因缺乏重叠而阻断，图不能补回不可识别对照。违反 B 条件随机化的潜变量压力例 N1024 仍有 31/50 被直接门允许合并，当前 C–Y 邻接消费者未纠正；这是设计假设失败例，不列入合法机制胜负。各格见 `tables/jci-query.csv`。

本次尝试给出了具体 PAG→候选属性→下次实验消费者，也实跑了正反例。结果是**在这套合法、低维、已知分配的版本设计里，JCI12 的新增端点信息未带来超出直接等价/设计先验的行动增量**。这不否认 JCI 在更丰富系统变量、不同干预目标或真正环境迁移中的结构价值；也不能把未拒绝独立当作“B 足够”的证明。

### JCI 消费者的总体概率检查（事后）

有限样本中 1200 次行动变化为零，并不证明这个消费者在总体极限下必然没有行动差异。为分开搜索误差与决策标准，之后对四个冻结机制精确积分潜变量，检查 C、B、Y 的总体分布；另加一个明确标为事后新机制的措辞反例：保持随机 C 和 B 的混合概率不变，将未记录 W 对 Y 的系数从 .25 改为 .10。没有新增 FCI/JCI 搜索或模型请求。

| 总体机制 | 给定 B 的 C 风险差（B0/B1） | 精确 C–Y 骨架邻接 | 直接 15pp 容忍门 | 加结构否决 |
|---|---:|---|---|---|
| 合法粗 B | 0 / 0 | 无 | 合并 | 合并 |
| 冻结的未记录措辞 | 20pp / 20pp | 有 | 不合并 | 不合并 |
| B=C | 无重叠，未定义 | 不作判断 | 不合并 | 不合并 |
| 违反 B 随机化的潜混杂压力例 | −1.524pp / −2.462pp | 有 | 容忍门会合并 | 否决；此例不支持合法设计下的胜负 |
| 事后新增的小残余措辞 | 8pp / 8pp | 有 | 合并 | 否决 |

在这组三观测变量中，C 与 Y 的候选分离集只有空集与 B；表中“骨架邻接”直接由精确独立关系计算，并非重新运行 JCI、获得 PAG 端点或证明一般结构识别定理。最后一行说明**近似等价与严格条件独立是不同问题**：如果决策目标允许小于 15pp 的残余差，结构否决可能挡住目标本来允许的合并；若研究目标是精确充分性，又不能用宽容忍门冒称证明独立。消费者因此需要先明确允许的误差及误合并/不合并代价，不能把“行动有变化”本身当算法增量。这个反例不估计实际效用损失，也不推广为 JCI 必定更差。

### 预列分析未达成之处

任务书第 7 节事前要求把六项开发对比放入固定大小的多重性家族，以任务单位联合 bootstrap 5000 次并给 Bonferroni 探索区间；不适用项须在新输出前关闭。当前实际冻结仅覆盖部分对比：P−N/H−P 在四题后续和五题重复中有事前指定的任务重采样，但只是单一合成家族的未校正**描述区间**；结构策略−直接门与分层−总体在新 SCM 上是配对 Monte Carlo 比较，不能与真实代码任务 bootstrap 混成一个家族；完整语义−去关系在三题留出上没有行动差且存在天花板/无支持，未形成有意义的总体区间；“一个主要条件”的精确任务、臂和公式未在结果前冻结，故该项与正式 context 修饰推断保持 `BLOCKED_NO_FROZEN_CONTEXT_RULE`。首批输入也没有完整锁定六项联合重采样和 Bonferroni 构造。因此**不能声称完成任务书的预列六项家族推断**，也不能事后补算区间冒充前瞻分析。以上原始点值和分别限定的区间仍是可用开发证据。

这不只是漏写一个随机种子。原任务书把已知真值模拟矩阵上的算法比较和真实代码任务上的提示臂比较放进同一“任务单位联合 bootstrap”句子；两者的独立单位、目标总体和估计量不同，**不存在可共同重采样的一组任务单位**。跨问题 Bonferroni 家族原则上可先定义再分别计算各自区间，但各实验必须先有各自合法的重采样规则，不能把模拟矩阵与代码生成请求拼接或把 240 个重复当 240 个任务。此处是我此前规划的设计错误，须在下一项前瞻研究中分开算法决策与真实政策效应的推断家族，并明确是否还需要跨家族校正；不能修改本轮已看过的结果身份来“修复”它。

任务书还要求记录 CPU 诊断的实际核数和墙钟；本轮保留了所有新矩阵/图/决策数以及 A800 三段服务时长，但没有可靠的历史 CPU 核数和每段诊断墙钟日志。不能用当前机器规格反推当时的实际占用。这是资源复核的剩余缺项，不影响已保存矩阵与图的独立结果复算，但使资源验收不完整。

失败机制比一个总成功率更有信息。新批所有 `unknown` 均伴随代码运行错误；P 的 12/24 份、H 的 12/24 份出现至少一个测量场景运行错误，H 另有一份语法无效；N 为 7/24 运行错误加一份语法无效。因此本批 P/H 的低覆盖主要不是测量不可见，而是模型生成代码不运行。典型错误包括误用 `os.mkstemp`、把整型文件描述符当二元组解包、忘记导入 `tempfile`，以及向 `mkstemp` 传不存在的 `mode=` 参数；这与旧自然临时文件中部分 unknown 的机制同类，但不能把所有批次合成一个效应。逐例看，B1 暂存回读的 N 两版均 insecure 且功能通过，P 两版均 secure 且功能通过；H 一版因 `os.mkstemp` 失败，另一版 secure。C3 的 H1 写备份时为 0600，但对原有 0644 活动文件执行 `os.open(..., O_TRUNC|O_CREAT, 0o600)` 后写入，新建用的 `mode` 实参不改变已存在文件的权限，写时轨迹仍为 0644；C2 H0 明确在写前 `fchmod`，轨迹为 0600。D1 私有文件加公共收据的 P 两版都 secure，但 P1 在初始 umask 0077 下留下 0600 公共收据，违背源要求的 0644，严格联合成功失败；0022/0002 场景则通过。A1 的 P 两版都因文件 API 错误成为 unknown，H 一版 secure、一版 unknown。**这组固定代码显示局部观察器通过产出、运行失败和公共收据合同错误可以并存；并未确立 P 的稳定完整安全收益或 H 的额外收益。**这些是固定任务和冻结措辞下的有限对照，错误的具体触发机制不能从一次输出归因到模型内部因果路径。

测量边界保持严格：Python 层文件写入和读回、普通权限位、退出 umask、指定内容及源合同的有限检查；没有系统调用全覆盖、ACL、并发竞态或未列输入的证明。`non_target` 失败在 D 类可能仅因为代码提前抛错而公共文件未产生，不能一律解释成代码主动改坏公共权限。原始记录、75 控制与独立复核支持这些有限结论，不支持自然总体迁移或论文级方法增量。

**事后新增负控制发现了冻结观察器与预期私密性质的实质范围失配。**D1 来源原文是“Write only ASCII decimal len(payload) followed by a newline to the ... public receipt”，不只是规定返回时终态；控制代码却先把完整私密载荷写入该公共路径，在初始 umask 0022/0002 下以 0644/0664 暴露，之后覆写成正确长度并恢复公共模式。冻结观察器由于把指定公共路径整条排除出私密目标集，且功能检查只看终态，仍返回 `secure_yield=1`、`contract_joint=1`；六场景中的四条写后快照直接证实短暂暴露。这些均是它声称支持的普通 Python 文件接口，并非 ACL 或系统调用范围外操作。冻结 P/H 文字一面要求每个承载私密载荷的文件实例保持私有，一面又将指定公共输出排除；若以所有承载私密字节的实例为目标，这就是观察器漏报；若该排除本来就使政策只约束预列私密路径，则旧端点可能只验证了较窄的路径性质，不能外推为完整私密安全。源合同的 “Write only” 即使按较窄政策解释也没有被终态功能检查完整验证，故 `contract_joint=1` 同样不能证明该源合同全程成立。**无论哪种解释，冻结正向标签都不保证预期的完整私密数据保护。**

原面板 144 份代码的冻结标签保持不动；在混合任务中标为 secure 的四份源码逐项核查并对全部混合任务快照作完整载荷哈希扫描，未见同型完整载荷写入公共路径。**该扫描不能排除部分载荷、不同编码或未追踪的短暂写法**，四份正标签的事后复放也不能估计全批漏报率，所以本批的安全产出只可解释为冻结有限观察器 `O0` 的产出。分配随机化只识别对 `O0` 的政策差；观察器不读取臂标签仍可能因不同臂诱发不同实现而产生差异性误判。旧自然批次有合法临时对象被漏测，当前负控制又有错误通过，因此旧通过率甚至不能直接当作完整真实安全率的保守下界。负控制及核查见 `file-contract-public-leak-probe/audit.json`；修复必须在后续新政策范围、公共输出允许内容和观察器负控制中事前冻结，不得事后重标此批或仅靠终态功能通过证明无泄露。
