# 共同API合同下的操作提示消费检查

## 问题与范围

已有Kedro开发结果中，Graph和强平面均完整表达六项要求，16份生成代码均未正确保护实际恢复路径。当前Graph已保存入口、对象、结果归属和拒绝先后关系。本轮检验表示内容经过明确的操作提示编制后能否进入生成过程，不把新增同类边当作已成立的贡献。

该来源已经暴露生成结果，本轮全部结果保持开发诊断身份。原有负结果、16项分配及672项检查不修改，不与新生成合并为独立任务。自然代码单位仍为一个；后续独立验证按原24项固定来源顺序推进，不按本轮表现选择任务。

## 共同资料和独立参考

在固定Python 3.12.16测量镜像中，真实收集完整shelve、dbm标准库源码，以及pickle.Unpickler、find_class及dbm.open的实际签名和文档字符串，保留文件摘要和Python许可证。没有修复实现、测量样例或生成结果进入共同资料。新增API资料共同提供给全部处理，不能仅向Graph提供。

源操作参考在新操作提示输出之前完成。参考上下文只取得原始任务、原始程序、原始策略和新增API资料，不取得旧失败说明、Graph、Flat、测试或控制实现。六项判断分别为继承与显式入口、原始字节到恢复对象的边界、恢复器输入合同、检查在解析或调用前生效、映射及异常归属、保存与非目标范围。给定资料不能证明的编码覆盖、分支或API行为保持unknown，不以文档的一般性描述认证所有不可信编码。

## 同等预算的操作编制

Graph编制者取得现有完整原生source_proposition_readback及概念含义；Flat编制者取得现有完整Flat条目。两者同时取得相同的基准任务和新增API资料。待增加的策略只从各自表示取得，不额外提供原文策略或参考答案。编制者不取得另一方法、旧生成、测试、控制实现或操作参考。

两种方法分别使用一个相同模型能力的独立上下文，共同输入上限250000规范JSON字符、输出上限20000字符、最多八项操作记录。每项使用相同栏目：适用入口、输入状态、实际操作、检查位置、允许或拒绝分支、结果归属、非目标保留行为及来源证据；另列unknown事项。不编写完整修复代码，不将没有来源支持的API知识作为已知事实。

每种方法保留首次草稿，仅允许一次机械检查和一次字段、类型或逐字证据修订，随后保存唯一最终记录。语义评价不反馈给编制者，不因两种输出相同而继续改写。共同程序按同一栏目生成自然语言提示，不另作语义补充。Graph消费内容来自实际原生读出，TSG关系保持来源语义身份。

## 五个同期处理

固定direct、flat_record、graph_record、flat_operation、graph_operation五种处理。全部取得同一基准任务和新增API合同；direct增加原文完整策略，record处理增加既有完整表示，operation处理增加各自编制的操作提示。共同外层说明明确追加材料中的要求具有规范身份，原始实现只是上下文。

每个处理使用四个共同生成种子2026111751至2026111754，共20项分配，顺序以2026111750打乱。使用既有Qwen2.5-Coder-32B-Instruct本地模型，temperature=0.7、top_p=1、最多4096输出tokens、超时600秒、并发最多两个。完整聊天输入用实际tokenizer核对32768上下文上限，不截断，不重试，不增加种子或更换任务。实际提示、实现和测量输入须在首次生成之前冻结。

Graph_operation与Flat_operation拥有相同编制调用数、资料及预算，作为本轮主要描述比较。operation与record的差异包含一次额外编制上下文及其输出，属于整体消费流程差异，不能单独归因于自然语言格式。所有处理共同取得新增API，所以本轮无法独立估计API知识相对于旧实验的作用，不能将跨实验改善称为Graph增量。

## 测量与可证伪条件

保留既有42项检查及其资格边界，所有20项分配进入分母。完整恢复策略、局部功能、联合成功、生成有效性、真实副作用及完整测量未知分别报告。原始报告、代码、请求参数和实际源码身份必须独立核对。不能以功能成功筛选安全结果。

操作提示由两个新的独立上下文按事前六项操作参考逐项测量。只有两份评价都为complete才计入共同成功；分歧、incorrect和unknown保留。语义输出不用于选择提示或取消已经固定的位置。Graph遗漏既有操作或先后要求说明消费机制未成立；两种操作提示都正确且代码表现相同，保留未观察到Graph额外收益；两者改善接近，只支持共同编制流程；提示正确而代码继续错误，保留生成阶段失败。单一任务不能建立总体统计收益，也不能改变Goal完成标准。
