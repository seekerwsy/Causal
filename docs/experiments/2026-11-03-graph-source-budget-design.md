# 固定来源的完整模块预算检查

本项只检查未来二十项来源的候选完整模块在现有Qwen tokenizer中的长度。source-budget-candidates.json事前列出二十五份模块，来自固定名单第五至第二十四项，包含OctoPrint、Gradio、Bleach及urllib3的相关候选位置。候选文件不等于已经确定的任务编辑范围，多模块共同政策也没有因此取得单模块实现资格。

使用既有实际服务上限49152，并在检查前规定共同候选输出预算16384。每条输入只含完整原始模块与空system消息，由既有check_prompt_context.py应用实际chat template。所有模块须与其已核对snapshot、上下文文件、Git提交和逐文件SHA256完全一致，不截断、不折叠正文、不删除原文内容，也不读取生成模型结果。

检查回答两个具体问题：模块加16384预留是否仍在49152内；剩余多少tokens可供共同完整政策、API资料及表示使用。通过仅表示模块本身没有超过这一必要预算条件，不能证明完整Raw、Flat或Graph提示能够容纳，也不能证明16384足以输出满足完整合同的代码。完整任务、实际表示和输出预算仍须在新生成前统一固定并检查。

OctoPrint、Gradio等来源同时涉及多个对象和入口，模块长度不能决定哪一处修改足以满足政策；该判断仍依赖完整任务和真实测量。不因文件较短选取不能满足要求的编辑位置，不将超出候选预算误报为模型生成失败或方法负结果，也不将通过文件计为合格自然任务。

输入准备使用data/method/graph-jci-goal-20261103/prepare_source_budget.py；token计数复用data/method/aiohttp-representation-20261103/check_prompt_context.py，读取已有本地模型，不调用生成接口。结果字段arms仅是该既有工具的候选输入名称映射，本项没有实验处理分配。该机械检查不改变历史冻结结果、Graph机制修订次数或JCI上下文资格。
