# 完整命题与操作对应关系的读出检查

## 研究问题与开发身份

检查原生 Graph 的读出是否保留每条完整命题与操作实例、对象、条件、范围及组合结构的对应关系。此前48任务比较已显示操作绑定是主要失败来源；当前实现的角色集合并集不能独立表达这些对应关系。

本轮使用已经暴露的48任务材料，不提取新 Graph、不修改原图、不重新评定此前结果。输入身份为 `tsg-source-attribute-20261101` 完整冻结归档，SHA256为 `7807e0d2fa8b1447a4e97a91324eae96d04622de02fff869a7c58ad26b727a43`；其主要结果SHA256为 `af4d0e586c70d62f65f2550be0943b9f8724f3d034ec695f1e81717cda9cd3bd`。本轮属于检查实际失败后开展的开发诊断，不能建立独立语义收益。

## 消费规则

使用现有 `src/tsg/prompt_tsg.py` 中的命题状态解码，并在同一模块实现 `source_proposition_readback`：

1. 验证原文、概念目录、节点证据和原生图形身份。作用状态与原有显式布尔属性的解码保持一致。
2. 每条命题分别保存其完整定义声明、逐字引文和角色端点。角色并集仅保留为汇总，实际绑定从逐条命题记录读取。
3. 选中某个组合成员时，同时保留所属完整表达式的祖先、分支和成员身份。AND、OR、NOT、opaque 保留各自声明；未声明组合结构时明确记为 undeclared。原生表达式成员身份不认证来源的规范作用，也不赋予 Atomic 编辑资格。
4. 操作实例保留自己的输入、输出、执行条件、非门控上下文及独立顺序。要求级 `conditions` 和直接 `constrains` 端点继续归属于该命题。要求拥有的顺序关系继续归属于该要求，不能转换为独立上下文；保留 task／each 边界及目标类别，不展开未提供的实例集合。
5. 节点含义和引文都来自当前实际图形。空条件、缺少端点和未解决关系继续保持原状态。错误的操作实例、错误引用和缺失语义不能由读出程序修正。
6. 指代、支持和对照关系保留方向及两端证据，并展开所需的来源上下文。新增的上下文命题标记为未选中，不并入所选命题的作用状态，也不成为该命题的直接操作目标。

这项修订改变表示的消费方式，不提供额外参考答案，不改变 JCI 的因果假设，不将语义边解释为因果边。

## 固定检查范围

保留原144个 Graph 查询位置。十二个无效表示位置继续记录为失败，不形成替代 Graph。对其余132个位置，核对新读出中的状态、汇总角色集合与原始冻结测量完全一致。

对每个有效任务的全部实际命题节点再读取一次，检查跨命题条件、共享操作及组合成员是否保留各自归属。原始查询图声明过一个 OR 和两个 AND，其中一项 AND 所在原始表示无效；有效图中的组合结构用于实际覆盖检查。没有对应实例的结构类型不获得经验覆盖声明。

独立检查直接读取冻结 JSON 中的节点、语义边、组合、保留范围及拥有关系，使用 NetworkX 计算表达式的祖先与后代，不复用生产读出的组合遍历。必须满足：

- 全部144个位置留存，失效位置身份保持原值。
- 有效位置的原有测量字段逐项一致。
- 每条命题的角色端点等于原图对应的实际边，不能广播其他命题的端点。
- 完整表达式成员、原生独立表达式身份、保留范围和拥有关系均可从原始材料复算。
- 操作输入、输出、条件和顺序与原图一致。
- 实际原生图中的14个要求级条件、45个直接约束端点及七条来源上下文关系完整留存。
- 每个被引用节点的逐字证据和含义声明与原文及冻结目录一致。
