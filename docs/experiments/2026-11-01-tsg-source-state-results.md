# 完整来源状态的开发比较结果

## 固定来源和评价对象

按[预先固定的设计](2026-11-01-tsg-source-state-design.md)，保留上轮全部六个自然任务，检查明确要求、条件、重复表达和来源未决定事项能否共同保存。六个任务已经经过来源反馈，本轮新增独立任务数量为零，研究身份为已暴露材料上的测量开发。

此前严格零未知资格仍为3/6。当前评价允许忠实保留未确定事项，候选参考的 `task_units` 与此前首次参考A完全一致，没有删除未知或根据方法结果修改参考。新的独立来源评审读取完整原文、候选参考、此前首次参考B及来源核对，六项条件全部通过的任务为6/6，允许启动当前开发比较。两种资格评价不同的对象，旧3/6结果保持冻结。

astropy-13398的两种测量均保留正逆变换、数学步骤和坐标矩阵分支。一位评审认为，正文与示例描述共同表达拟议方法，具体实现选择无需成为独立强制要求，全部条件通过。另一位认为，示例标为所提方法的基本概念，其数学行为也具有拟议行为的规范作用；双方将这些步骤保存在描述内容中，没有充分识别这种作用，因此只将“明确要求忠实完整”判定失败，其余五项通过。

这里存在关于方案规范地位的评审分歧，不能报告为数学内容丢失、确定的运算错误或双方评审均否定。按预定双方全部通过规则，该任务在两种方法中均未取得完整成功。不通过结果不经多数表决改判，也不通过改变规范标记取得成功。

## Graph读取机制及验证

`source_requirement_inventory` 增加 `source_state_readback`，返回全部实际命题及其来源作用、表达式路径、条件所有者和未确定关系。此前规范清单与未确定节点编号仍保留；调用者现在能够直接读取清单之外的实际未知内容。读取接口不认证原文覆盖、语义蕴含或软件性质，相关认证字段保持 false。

十七组实际数据检查通过，涉及44张有效历史图和18张未标规范作用的历史图。原有编译结果、规范根选择和未知编号保持一致，完整来源状态覆盖实际命题。没有采用虚假任务或替代节点。

`verify_source_state.py` 使用标准库独立读取原始 JSON，核对六项来源资格、十二个位置的双方评分、Graph原始节点及逐字引文、规范根与未知集合，并检查平面测量与首次原始输出完全一致。核对结果为 `VERIFIED_SOURCE_STATE_DEVELOPMENT_COMPARISON`，Graph和平面表示均为5/6。

## 研究解释与边界

当前接口能够保留已知要求和未知事项；这六项开发比较没有建立Graph的独立收益。两组上下文不足以支持总体显著性结论。模型构建版本与实际推理用量未知，不能声称相同计算量；方法名称被匿名化，但输出形态可能暴露表示形式。独立上下文判断来自相同模型来源，不能称为独立人工真值。

后续任务协议需要明确区分“说明一种可选方案”与“要求采用其中某项行为”，并保留原文没有决定的部分。该约定必须在新的方法输出之前固定，并向两种表示提供相同上下文。当前astropy原文及其首次输出不能补写成具有唯一意图的来源。

本轮没有生成实验主体代码，也未测量安全、功能性、JCI真实任务效应或策略价值。没有新增服务支出、受保护正文读取、正式角色分配或默认方法切换。
