# TSG 完整流程的稳定性验证

本轮承接[单路审查精简实验](2026-09-15-tsg-review-simplification.md)，检验选定流程是否能在完整的新响应重复中保持质量。目标仍是形成稳定质量的 TSG 工作流，尚未达成。

## 冻结方法与达成标准

[冻结方案](../../data/method/open-tsg-scope-development-v1/single-review-stability/freeze/plan.json)在第一轮响应前锁定代码、模型、提示、输入、候选定义和来源参考。该候选路径为原子事实提取、关系绑定、一次全面来源审查、必要时一次绑定修复、保存源图、下游候选范围判断；机械校验最多允许一次节点清单修复。

三轮均对同六题重新调用模型，不复用响应，不修改方法。每轮六题均须通过来源图与最终额外断言核验，三轮合计 585 项参考检查通过，且没有错误的确定性范围状态。任一轮出现语义失败就停止本候选的重复序列，保留失败并定位共同原因；方法改变后另行冻结验证。此前的配对实验和完整组合检查不计入三轮。

通过后，仍须前瞻准备八个未用于调试候选流程的自然任务，每题完整运行两次，至少 15/16 通过且没有错误的确定性范围状态。尚未准备或读取这八题。当前来源核验由开发作者完成，不是外部独立资格认证或总体准确率估计。

## 三轮结论：未达到稳定性标准

[三轮汇总](../../data/method/open-tsg-scope-development-v1/single-review-stability/analysis/summary.json)保留全部 18 份输出：源图通过 17/18，连同下游额外断言的完整验收为 16/18。虽然所选参考检查达到 585/585，逐项来源审查仍发现缺陷，因此稳定性判定为未通过，未开启自然任务验证。没有重跑第四轮替代失败，也没有调整验收标准。

第三轮双查询题在初始清单中把“both selected rows”作为一个集合对象，两个查询的结果列表均为空。最终图只有返回该集合的关系，没有两个查询各自的结果来源。审查模型认可了所有已有关系和完整性声明，漏掉了这项跨句义务。原有绑定修复只能使用既定节点；遇到清单缺陷时，该候选实现只会拒绝阶段不匹配，不能回到节点提取。30/30 参考检查没有覆盖这一具体遗漏，三处完整性声明在来源审查中标为无依据。

第三轮条件题的源图正确，但范围判断从 SQL 文本拼接推断原始输入 `x` 在 raw 模式一定为字符序列，重现配对实验中的类型歧义。依照预先冻结的解释，额外的长度要求状态和相关说明标为 `UNCERTAIN`，未认定为已证实错误，也未认证为正确。

下一项调整是让审查显式检查来源要求的结果及其生产者，并在发现缺失节点时允许一次返回提取阶段的修复；下游需要单独检查原始输入类型的证据。会先用已保留失败做有限组件验证，再决定完整候选流程。旧三轮和旧评价保持原样。后续实施与验证见[结果来源修复报告](2026-09-15-tsg-source-origin-repair.md)。
