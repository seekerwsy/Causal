# TSG source-premise repair

This is response-informed development under `SPECIFIED_DRAFT`, not formal
qualification. The three already exposed cases are stock-order insertion,
conditional SQLite return and file reading with a formatted message. No new task
is exposed. Earlier judgments and source references remain frozen.

## What changed and why

The previous role-domain shortcut made a necessary condition sufficient:
database access plus a data-value role automatically certified SQL-parameter
applicability. The current scope request instead asks for a complete applicability
judgment even when a role check exists. The program preserves unknowns and rejects
affirmative applicability conflicting with an unknown or incompatible role.
Operation context, caller origin and directory boundaries need source support.
An unexpressed requirement is evaluated separately and cannot establish those
premises. This removes a deterministic inference error; it does not certify the
model's semantic judgments.

The prospective development catalogue makes object identity neutral with respect
to origin and later use. For example, a user identifier does not mean caller
supplied, and file contents do not imply a later computation. Required operation
participation remains separately represented. No caller-control verdict is
derived from a concept-ID whitelist. Typed entities such as an HTTP request can
still be used when the source establishes the type; a neutral request concept
also exists. Complete definitions still need source review.

Inventory instructions now require each conditional branch's consequent to be
an atomic requirement with its own condition. A whole if/else rule must not be
put under one branch's guard. Overlapping full-sentence quotations remain valid;
atomicity concerns asserted meanings, not punctuation or the number of verbs in
a citation. The current schema does not mechanically prove semantic atomicity.

These changes use the existing inventory, binding, single review/repair and scope
path. Inventory alone uses native structured output; the other stages use JSON
with local schema checks. No second critic, wrapper framework or extra provider
stage is added. Combined changes are tested together, so this pilot cannot
attribute any improvement to one change in isolation.

## Repair consistency correction

The runner now carries rejected source claims into the same binding replacement,
including a replacement following new inventory IDs. Importable extraction logic
matches unchanged facts by exact concept, definition, type, quotation and
occurrence; it passes mapped corrections to the existing call and rejects a final
response that repeats them. Ambiguous or changed identities are outside this
check. It adds no critic or provider stage, does not automatically delete model
claims, and cannot detect a reviewer confidently approving a false premise.

The [retained-response path check](../../data/method/open-tsg-scope-development-v1/natural-transfer/source-use-branch-repair/repair-consistency-check/report.json)

edges were mapped to new IDs and rejected before scope assessment. The failed

The operational conclusion is narrower than stability: neutral definitions and
task-local requirements remove identifiable representation traps; necessary-role
checks cannot settle full applicability; and bounded repair must preserve known
corrections. A model can still invent a source premise and endorse it. That is an
uncertified semantic judgment, not an error that JSON validation or extra repair
rounds alone resolves. Continue to assess source entailment and complete required
behavior separately from request delivery, graph completion and model self-review.
