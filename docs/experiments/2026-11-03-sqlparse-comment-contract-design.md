# sqlparse注释删除的有限运行测量设计

固定来源为CVE-2021-32839的原始提交e66046785b816e5c2d22f101f36faefd19c4a771，范围为完整sqlparse/filters/others.py。已有注释删除功能由研究者补充有限运行政策。来源文件和测量可以准备同政策表示比较，Atomic ADD资格另行判定。

在sqlparse.format收到保留CRLF的字符串并启用strip_comments时，完整删除合法块注释，保留原有注释末尾换行和间距语义、普通SQL格式及关闭选项的行为。目标注释以`/*`和`*/`定界，包含28、30或32次CRLF，末尾含非换行内容。分别放在SELECT关键词后和数值后的合法位置，形成六项安全输入。每项在独立Linux子进程中实际运行，软CPU限制一秒、硬限制两秒，外层等待上限十秒。明确收到SIGXCPU表示越过限定CPU政策，其他信号、启动错误和外层超时分别保留未知。成功要求正常返回，移除注释标记，并由标准SQLite实际执行得到整数7。仅返回空字符串或删去SQL不可通过。

CLI通过TextIOWrapper以通用换行模式读取输入，会在格式化之前转换CRLF。有限运行安全端点适用于保留CRLF的直接API，CLI只参与普通功能测量。不能依据API的CPU失败推断相同CLI输入也会超限。

正常功能以原始模块实际输出为配对参照。固定输入为单行注释的LF及CRLF、行尾注释、嵌套括号内块注释、两个语句间块注释、含引号的注释样式字面量、短CRLF块注释、无注释SQL。每项通过API和实际CLI读取，分别启用和关闭strip_comments，形成32项功能比较。记录返回状态、标准输出、错误输出及输入摘要。功能通过要求原始与当前输出逐字节相同，且两个进程均正常返回。任何原始普通输入未正常返回均保留未知，不能以空输出相等计为通过。

三个控制为完整原始模块、保留原匹配含义的线性扫描参考及始终用空格替代已删除注释的控制。参考将歧义换行选项写成字符类，只从连续换行序列起点进入，保留原尾部空格及美元结束锚点。空格控制检查普通功能是否能够识别原本需要保留的换行。参考须六项安全及32项功能全部通过，原始至少一项明确超出CPU限额且32项功能通过，空格控制须六项安全通过且至少一项普通功能不符合。所有未知均须为零。先执行一项代表性高风险API输入与一项普通换行输入，使用单独结果路径核查测量。完整运行仍使用全部固定输入。
