# 完整命题读出的已暴露语义检查

本轮检查新的原生读出能否支持完整角色解释，并保留源图中的错误归属。它接续完整命题读出的机械核对，属于在48任务结果已知之后开展的开发诊断；不建立独立收益，不重评此前主要结果，不计新增任务或样本，不计算显著性。

固定四个已暴露查询：`attribute-00-08`、`attribute-00-16`、`attribute-01-00`、`attribute-02-06`。前两个检查完整谓词与替代分支的读出；后两个检查错误操作及错误调用实例是否继续可见。另从原始 Graph 和平面方法均完整成功的查询中，按 SHA256(`2026110814:` + query_id) 排序，排除上述任务，选择来自两个不同任务的两个查询作为保持原表现的对照。

每个查询同时呈现新的实际 Graph 读出和原始平面绑定，共12个位置。Graph 读出直接来自 `source_proposition_readback` 的已核对输出，不增加来源事实、不重新提取、不修正源图。平面方法使用冻结的完整绑定文字。两者获得相同原文和中性命题。方法标签按种子2026110815打乱；表示格式可能被识别，不能视为完全掩蔽。

两位新的独立上下文评审只读取原文、中性命题、匿名绑定和共同指令，判断命题身份、操作、对象、条件、范围。按完整绑定关系解释谓词限定：操作名与完整命题中的结果、否定或条件可以共同表达一个要求；错误端点、相反调用实例或错误条件归属仍须保留未通过。相同规则适用于文字绑定及结构化绑定。旧参考答案、旧评审、案例类别和方法身份均隐藏。

每个位置仅当两位评审的五项判断全部通过且逐字证据有效时，记为本轮语义绑定通过。解释检查要求两个谓词读出案例的 Graph 位置通过、两个源图错误案例的 Graph 位置继续未通过，以及两个保持原表现的对照中两种表示均通过。这个检查只决定读出是否值得进入新的独立验证，不能作为 Graph 增量的统计证据。零收益、不利判断和未知保留原值。

实现为 `data/method/tsg-proposition-readback-20261101/probe.py`；它只准备匿名材料与汇总首次评审。原有机械结果、全部方法输出和48任务研究的指标保持冻结。

```text

python data/method/tsg-proposition-readback-20261101/probe.py evaluate
```
