# 完整要求修订后的自然任务检查

**本轮没有证明可用候选增加。** 两道已暴露自然任务完成了真实构图，但唯一一次
候选生成回答被截断，未得到可接纳的完整候选批次，因此没有继续编辑或代码生成。
这是 `SPECIFIED_DRAFT` 下的开发检查，不是独立资格验证或正式研究结果。

## 固定设计与实际执行

实施代码为 `dae11a0e`，投影对照为修订前的 `1f90fdd4`。
在模型输出前固定固件上传、文件下载两题的原文和参考含义，重点检查大小上限、
文件头、路径范围及重复约束。它们来自已经登记的开发材料，没有新增暴露或读取受保护题。

1. 使用 Qwen Max `qwen3.7-max-2026-05-20`，沿用一次普通审核和既有修复上限。
   两题共五次调用：两次初次抽取、一次机械修复、两次审核；没有语义修复。
2. 使用当前候选入口规定的 Qwen Flash `qwen3.7-flash-2026-07-15`，一次读取两张图，
   不给参考答案，不提供结果或预选因素，最多输出 8,192 tokens，不重试。
3. 原计划用同一份有效候选回答比较新旧投影，再为合格候选冻结词表、重新抽取及实际编辑。
   候选回答失败，因此后续步骤未执行。

候选启动前还有一次本地配置校验失败：任务类别数组未按规定排序，尚未发出请求。
仅排序后重新启动，原配置和失败日志保留；它不是第二次模型采样。

## 得到了什么证据

| 检查位置 | 观察与含义 |
| --- | --- |
| 固件大小与文件头 | 类型和 256KB 上限被拆为不同要求；大小、FWR1 文件头均绑定到 `blob_bytes` 与存储操作。这两项具备正确的局部源结构。 |
| 固件路径范围 | 说明文字正确，但直接对象绑定到 `upload_dir`，没有正确表达“被保存的路径必须位于该目录中”。普通审核批准了这个绑定。 |
| 固件异常条件 | “无法完成任务时”仅留在说明文字；图中异常要求为无条件的任务范围要求。普通审核未检出。 |
| 下载异常分支 | 不存在、越界、其他异常三种条件均进入结构；但普通异常被标作安全要求，不能据此成为可编辑安全因素。 |
| 下载路径限制 | 原文还要求越界时抛出 `PermissionError`。删除单独的安全政策句，不能声称路径限制已变成未表达。 |

参考中的三个固件因素，大小和文件头的局部绑定得到保留，路径因素目标有误。
这不是整图准确率，也不是已经通过编辑验证的 2/3 候选。

Flash 请求实际为 54,198 字节、26,095 输入 tokens；回答输出了 8,192 tokens，
以 `finish_reason=length` 结束，JSON 的 dispositions 列表未完成。现有入口拒收了它。
没有补全 JSON、接受部分回答、制作新词表或继续付费重采样。

为定位问题，仅离线检查回答前部**已经完整输出的 17 个因素条目**。这些条目不是
已接纳候选，逐项检查所需的清单由程序临时构造，只用于诊断，不替代缺失的模型回答。

- 旧规则有九项、新规则有十项通过局部结构检查。新增的一项是普通异常处理条件，
  应作为非目标功能保留，**不能算有效安全候选增益**。
- 模型将函数名、返回类型、返回消息、环境设置和普通异常等列为可编辑因素。
  这违背了当前候选提示中保留接口和非目标行为的要求。
- 若干条目重新添加了源图没有的输入对象绑定，导致结构检查失败。
- 即使结构检查通过，也可能继承源图的错误：固件路径要求仍错误约束目录参数。
- 后缀要求与禁止双扩展名的表述重复，不能作为两个独立移除因素。

原来的 Pandoc 两项单 API 禁令也离线复核了：仍是零项接纳、两项遗漏，没有将其
改名为一个组合政策来宣称成功。

## 本轮判断与下一步

这轮把两层问题区分开了：源抽取仍会丢失条件、混淆被约束对象与参照对象；
候选阶段又让模型重新填写已有绑定，并把普通要求当作研究因素。输出截断是本次
流程停止的直接原因，**放大输出上限不能解决已经可见的语义问题**。

当前修订保留了更丰富的结构通路，但其自然任务收益尚未获得证明。
下一次最小改动应先让候选阶段复用程序已经解析出的完整绑定，仅由模型判断要求含义、
等义归并及可编辑性；使用短局部引用减少重复长 ID。接口、功能及重复要求仍需明确保留。
这不是再增加审核轮次，也不意味着所有复杂要求都应被排除。改动后须另行冻结小批检查，
本轮失败保持原样，不能重算为修复后的成功。
