# Atomic source record development pilot

Status: four bounded batches closed; implementation repaired, semantic stability not established.
This is response-informed development under SPECIFIED_DRAFT, not qualification.

The scientific question is whether binding guards, targets and modality inside each
atomic source record removes semantic drift introduced by a separate free binding
call and by whole-inventory repair. Objects/operations/requirements are extracted
jointly, one reviewer checks all records and source units, a local patch preserves
unaffected records, and deterministic compilation generates TSG relations. Normal
provider calls fall from four to three; the maximum falls from seven to five.

The [frozen inputs](../../data/method/open-tsg-scope-development-v1/natural-transfer/atomic-source-records/inputs/plan.json)
select only already exposed stock-order, SQLite-book and file-message tasks. They
preserve old references and record the disputed temporal wording and distinction
between expected input domains and prescribed rejection. There is no retrospective
regrading. Evaluation reports full acceptance, critical semantic errors, required
meaning coverage and reviewed usable scopes separately. Compiler/model approval
cannot certify those quantities.

The existing43 focused cases passed after updates; no maintained test count was
added. They cover guard ownership, shared conditions, task scope, assumption exclusion,
repeated rejected claims, preserved unaffected records, unknown handling, failed-task
accounting and exact recorded execution replay. These are mechanical boundary checks,
not model accuracy evidence.

Execution uses Qwen qwen3.7-max-2026-05-20 with the preceding model settings. At most
15 provider calls and CNY9 are authorized from the existing CNY20.758175 allowance;
no funds are added. Exact environment and command are in the batch's launch.sh.

input-role definitions or the precise interpretation that task scope expands onto
every runtime operation. Review and patch now receive those definitions, guard
ownership, modality and if/else atomicity explicitly. The earlier positive reviews
cannot be attributed solely to model capability without accounting for that omission.
