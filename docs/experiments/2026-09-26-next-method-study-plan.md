## 1. 建议的方法调整

- 写清三种对象：`S` 是干预前任务适用范围；`A` 是随机分配的四臂；`M` 是可能修饰政策效果的干预前任务属性。它们不是同一个 context。JCI 的候选 context 为 `A`，`context_query_id` 用于 `S` 的语义匹配。
- 当前有界开发的政策效果继续由任务级 assigned-arm ITT 估计，不以发现 `X–Y` 邻接作为必要前置。正式草案的 Atomic Full/RD-only 比较仍保留原义；任何移除、替换或改变 RQ2 的决定需在新的正式冻结前明确作出。
- 图发现的警告、缺乏可检验支持、常量列和不合适的依赖结构必须成为显式不可评估状态。不能把 CI 未被有效执行当成独立，不能用重复代码生成次数替代独立任务数。保留原始图供诊断，不能把补留边解释为肯定关系。
- JCI 暂作独立开发分析；生成代码不进入主 PAG，不引入代码中介，不恢复 Pair 或上下文修饰确认性推断。合成研究允许定义独立测量的终端 `Y`，不能据此改变正式变量字典。

## 2. 优先实验 A：识别边界与变量编码

先不扩大模型调用。使用七个已暴露任务的已冻结提示文本核对含义，不重评其效果；模拟提供真值，真实文本只检查设计是否相符。

固定变量字典：

| 变量 | 定义 | 科学角色 |
| --- | --- | --- |
| `S,Z` | 源任务操作、对象、执行条件和事前批准的背景属性 | 适用范围及协变量；不能由代码结果或臂后依从性决定 |
| `X0` | 原提示是否表达完整目标要求 | 自然状态；全为合法 ADD 的固定任务框中可能恒为 0，不制造自然支持 |
| `A` | No-op、Style、Generic、Target 四水平分配变量 | 单个分类 context；不把四个完全相关的 one-hot 列作为独立环境变量 |
| `X1` | 编辑后文本是否表达同一完整目标要求 | 提示侧状态；与模型是否遵守、软件是否安全分开 |
| `Y` | 模拟中的独立测量安全产出 | 终端结果；真实研究保留有效性、Oracle unknown、功能性等独立字段 |
| `U` | 只在模拟真值中可见的任务难度或背景原因 | 构造混杂及任务内依赖，不向搜索器泄漏 |

把以下结构问题分别登记为：已由设计规定、可由数据识别、不可区分、假设不满足。不能以图中圆端点数量减少作为全部目标。

1. **政策指派作用**：`A` 改变 `Y` 的分布吗？由随机对照估计；不把重新找出该关系当作 JCI 独有贡献。
2. **要求状态的独立作用**：在给定 `A` 下单独改变 `X1` 会怎样？若 `X1` 是 `A` 的确定性函数，数据没有这个对比的独立变异。
3. **新增结构知识**：除了已知的编辑关系和可直接估计的随机臂效果，能否提出一条事前定义、实际可测的结构关系？若没有，不进入算法扩量。

必须运行的最小反例：在目标状态为 `X1=1[A=Target]` 的相同随机臂表上，比较两个 SCM：

- SCM-T：`P(Y=1)=sigmoid(b + beta*X1 + gamma*Z + delta*U)`。
- SCM-A：`P(Y=1)=sigmoid(b + beta*1[A=Target] + gamma*Z + delta*U)`，`X1` 不进入 `Y` 的结构方程。

二者在自然执行的四臂数据中有相同的联合分布，而在固定 `A` 后单独 `do(X1)` 时不同。应以枚举有限状态概率/解析计算验证，不能用一份随机样本的相似性代替等价证明。该例只证明“要求状态独立作用”缺少识别信息，不否定政策指派的随机效应。若主张 `A` 只能通过 `X1` 影响 `Y`，必须列为额外排除假设，并审查四臂文本是否支持；不能假称 JCI 从数据发现了这个假设。

再用前轮随机 context 概率性改变 `X` 的场景作正对照，区分“实现错误”和“当前设计没有识别信息”。确定性/近确定性编码也需检查与所用 CI/PAG 假设的兼容性；确定性编辑本身不意味着 JCI 框架完全不可用。不得为了适配算法而故意降低编辑忠实度或注入随机失败。

**A 的验收**：交付一张真实四臂文本到变量的映射、一对同分布但不同 `do(X1)` 真值的验证记录、一个成立假设下的正对照，以及明确的可识别问题清单。若唯一候选新增主张不可识别，结束该 JCI 用途；零收益是完成结果。

## 3. 条件实验 B：只对剩余可识别问题比较算法

仅当 A 留下非重复、非平凡且实际可测的结构问题时执行。沿用现有两个探索脚本与后端，不新增框架。执行前补齐该问题对应的 SCM、参数、目标 PAG/端点、随机种子及 CI 参数并冻结；本节不是已经冻结的可执行配置。

- 同一 `pcalg` 后端、同一矩阵、同一 G² 规则下比较 JCI0/1/12，隔离背景知识的作用。所施加假设必须在对应 SCM 成立；无效假设的压力例单列，不能混入合格场景平均分。
- 同一 Tetrad 后端、同一观测矩阵和 CI 参数下比较 FCI/GFCI。保留固定的 GFCI 评分设置，不在结果后调参。不能用 FCI 半份自然样本对 JCI 全份干预样本做算法性能排名。
- 建议独立任务数 `N=25,100,400`，每个固定场景 100 个种子，报告 Monte Carlo 不确定性；这不是 400 个真实任务的资源承诺，也不是样本量达标结论。
- 模拟同一任务的四臂、每臂两次生成及共享 `U`。有效的图搜索参考矩阵在结果前为每个任务随机固定一个臂和一个生成槽，只保留每任务一行；所有 JCI 变体读取相同行。任务级 ITT 仍读取完整四臂数据。
- `N=100` 时增加每臂重复到 10 次作为依赖诊断。把全部重复行误作 iid 的搜索结果仅作为错误做法的对照；不因其看似更确定而采用。增加重复不会增加独立任务数。
- 记录真值允许的端点、错误确定端点、未定端点、真边漏检、假边和不可评估率。不可评估次数保留在总分母，另列有效运行条件下表现；不能把“不出图”或“出空图”记为正确零关系。
- `pcalg` 的 `n<n.min` 警告使相应图在可用性评价中不可评估。`NAdelete=FALSE` 不会解决检验内部已返回独立的问题。沿用固定规则，不能为了产生图而放宽资格。

**B 的验收**：能说明增量来自额外背景信息、更多数据还是软件差异；在实际确定性编辑和任务依赖条件下给出错误、遗漏及拒绝输出的数量。模拟通过只支持下一次有界开发，不自动启用正式 JCI 路径；不能按边数或个别成功图选优。

## 4. 真实生成的下一步取决于测量与来源

无论 JCI 是否继续，真实研究都应先解决上轮 `bsub` 和 `ssh-keygen` 暴露的解释问题：安全产出差异可能分别来自固定可执行文件、避免 shell 解释或语法有效性，不能统称为同一机制。在已经暴露的少量任务上，对当前声明的安全端点做有代表性的 secure/insecure/unknown 校验，并明确非目标功能见证；不要求未使用风险或语言的普遍验证。历史标签保持原规则。

真实扩量前，按结果盲规则确认新增自然任务的可用数量和开发暴露，前瞻冻结同一完整 Atomic 政策、四臂、端点、模型及调用上限，再按任务级精度/功效决定 N。若支持不足，如实缩小研究范围。不得把合成场景当自然来源补充，不使用受保护评估输入，不以这轮结果挑最有利的场景。
