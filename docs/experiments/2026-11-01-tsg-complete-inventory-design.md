# 完整任务要求清单的开发测量

## 研究范围

此前三查询研究按固定局部命题评分，六目标编辑检查两种方法均为6/6。它们没有验证一项任务全部已表达要求的清单。本轮建立完整清单的独立来源参考，并检查 Graph 的完整清单读取机制，不重新评分旧研究，也不声称新的表示收益。

对象为任务软件及交付物的全部明确规范要求，包括输入、输出、错误、格式、语言、条件、量词和逻辑分支。问题提交模板中针对报告者的流程指令不属于该范围。事实、示例与较弱实现建议不自动成为要求；同一完整要求的规范重述需要记录全部实际来源位置。完整显式清单不等同于完整程序功能规格，未规定的功能性维持未知。

范围按原文已表达的完整含义判定，不强制唯一分项数。AND 可以保留为整体或分别列出在来源中独立受到要求的成员，但共同含义必须完整一致；OR、NOT 的成员不得各自被当作独立义务。对象属性和操作结果允许不同表述，仍需相同完整谓词及条件的来源支持。泛泛的修复请求不补充来源没有定义的软件行为。

## 固定任务和参考顺序

从固定公开 SWE-bench_Verified revision `78f471bf655a3137b2e8a75af1501690ec009ec3` 获取六个新的自然根任务。原文件 SHA256 为 `030cfd7f2a704c4c0226e7f104c725a3b41230b1d3517f9c915ad7ea5be3fa25`。只读取 instance_id、repo、problem_statement、created_at、base_commit；不读取补丁、测试、提示评论或难度。根据已保留的标识元数据在读取正文时排除受保护标识，不读取受保护正文与标签。

来源长度为5000至12000个 Unicode 字符，至少三个仓库，每仓库最多两个任务。使用此前固定的字符3至5元 TF-IDF、20000项特征及0.92余弦阈值构造近重复分量；任何含此前24或48个已选任务的分量排除，每个分量最多一个新任务。按 SHA256(`2026110931:` + instance_id) 排序取得六个。只进行一轮自然来源获取，数量或仓库覆盖不足时保持不足，不降低门槛或追加。长度只定义长原文范围，不证明要求数量较多。

选择不读取 Graph 关系、方法结果、选择器或评审答案。开发暴露在参考判断之前记录。已有暴露长原文的数量检查单独保存，不改变其旧研究身份。字符近重复整理不证明语义和统计上的完全独立；新自然根任务及其后代仍按原始任务单位计数。

两位新上下文分别只依据原文和共同规则列出全部明确要求、条件、重复来源，以及未确定的软件要求候选和排除的报告流程内容。两份首次清单固定后，第三位新上下文只阅读原文和匿名配对清单，检查每份清单的来源支持、完整覆盖、角色与条件，以及两份清单的联合语义是否一致。清单项目数量不同不自动判为分歧。

已知完整参考要求两位均声明已完成全部范围检查、没有未确定要求候选、引用有效，且第三位对双方来源支持、双方完整性、绑定与条件及语义一致性全部通过。六个位置全部保留。至少五个已知完整参考才允许在本范围启动后续表示清单比较；否则保留测量不足，不替换来源。

## Graph 读取与公平比较要求

现有规范 Graph 的来源编译由 `compile_source_propositions` 复用原生命题、条件与证据校验。`source_requirement_inventory` 从显式规范作用且独立受到断言的命题中选择没有规范祖先的完整表达式，保留完整读出；OR、NOT 内部成员不成为单独清单项。缺失规范作用的候选明确返回未知。程序不认证来源覆盖或语义正确。

后续 Graph 与强平面方法必须获得相同完整原文、定义及预算，并独立生成整个清单，不能得到来源参考。平面方法允许全部关系、完整推理和结构重建。主要评价应同时要求完整覆盖、无额外规范、完整谓词与条件、重复来源归并及正确未知处理，由新的方法盲态评审依据全原文评价；不能以清单条目数或局部查询准确率替代。

本轮包含六个新选自然根任务，模型训练数据中的先验暴露未知。即使通过参考资格，也不建立 TSG 增量、自动提取准确率、软件安全、完整功能性或 JCI 真实效果。LLM 改写后代不能增加独立任务数量。没有新增软件生成、服务支出、受保护任务、正式角色或默认方法切换。
