## What to change next

The tested mechanism has a limited benefit: it can remove unsupported proposals
and recover some missing atoms. It does not reliably detect and replace wrong
semantic types, and its broad compiler diagnostic does not identify the failing
source unit or expected field condition. The observed retention of old wrong
nodes is consistent with anchoring, but this experiment does not identify the
cause as model capacity, decoding, or anchoring.

A next bounded test should improve feedback before increasing round count:

1. Return mechanical errors with an exact response field/source-unit path and the
   violated rule. Keep semantic judgments separate from deterministic checks.
2. Have a source-only critic identify unsupported nodes, omitted source meanings,
   type mismatches and incorrect bindings, citing the source and full concept
   definition. Do not give it the human reference answer.
3. Apply a bounded replacement to the affected construction stage. Inventory
   changes invalidate its dependent bindings/scopes; regenerate those before
   acceptance. The candidate stage still cannot split or repair source facts.
4. Review the complete resulting graph in both directions and keep unresolved or
   failed cases explicit. Compare with an equal-call control prospectively; do
   not choose the best response with the gold reference.

This critic/targeted-revision design has **not** been executed here. No automatic
repair default or unbounded loop is adopted. Acceptance still needs both source
coverage and unsupported-assertion review; weakening the criterion would conceal
the PDF and two-query errors rather than demonstrate an improvement.
