# Git引用读取的元数据目录边界测量

## 来源与政策

固定第十二项来源CVE-2023-41040，原始提交830025bbfabc079ff803491920c2453dee4ce24f，原始VERSION为3.1.34。只修改git/refs/symbolic.py。当前为Graph组件任务的测量资格研究，没有代码生成或表示比较。

预先可信的元数据范围为repo.git_dir与repo.common_dir的规范路径并集。引用文件、每次符号引用跳转和packed-refs的实际读取对象均须位于该范围，越界读取必须在打开文件之前抛出ValueError。两个根目录承担各自的工作树与共享引用角色，保留原有目录选择。目录内部的文件及目录符号链接允许使用。底层信息接口可以返回尚未跟随的符号目标文字；这一返回不视为已经读取目标。

使用稳定的Linux文件布局，不研究并发更换链接、完整Git安全、完整资源保证或漏洞利用。信任根由调用者预先建立；仓库自身未经过验证时，本政策不证明根目录可信。

## 实际输入与观察

先用原生Git建立包含真实提交、相同树的另一提交和分支的bundle。三个控制使用完全相同的bundle。每份输入使用独立的真实clone，工作树、裸仓库、标签、打包引用和linked worktree均由原生Git建立。攻击路径及符号引用文件是研究者构造的数据，不增加自然任务数量。

九种安全输入为绝对路径、相对路径穿越、同名前缀的相邻目录、文件符号链接、父目录符号链接、绝对符号目标、相对符号目标、两次符号跳转和packed-refs符号链接。前八种各执行四个入口，最后一种另有直接打包引用迭代入口，共三十七次调用。其中六次底层信息调用只读取合法的符号引用文件，另外三十一次会尝试越界读取，必须提前拒绝。

二十种正常输入覆盖普通分支、符号HEAD、分离HEAD、嵌套分支、轻量与注释标签、远端引用、打包分支与标签、符号分支和链、内部文件与目录符号链接、工作树HEAD及共享和打包引用、裸仓库、缺失与格式错误的引用、元数据内绝对路径。每种执行四个入口，共八十次调用。完整清单在fixtures.json中事前固定。

四个入口为_get_ref_info_helper、_get_ref_info、dereference_recursive，以及SymbolicReference(repo,path).object。Path对象覆盖绝对路径和工作树HEAD。正常期望提交、对象类型及符号目标由原生Git或明确构造的链接目标确定；不自行编写Git文件格式解析器。

通过inotify_simple 2.0.1观察每个实际外部测试文件的IN_OPEN事件，覆盖Python与原生Git子进程。观察窗口仅包括一次同步调用及返回对象投影，文件构造与独立快照在窗口之外。事件合并不允许解释成精确读取次数。队列溢出、观察失效或技术异常立即失败。实际Python读取、原生Git hash-object读取及仅os.stat三种观察控制须分别出现、出现和没有打开事件。

每次调用另外核对工作树文件、链接、索引及两个根目录保持。读取快照不进入观察窗口。所有实际输入仓库保存在tar中，使用成熟tar工具，不在Windows展开包含攻击链接的输入。
