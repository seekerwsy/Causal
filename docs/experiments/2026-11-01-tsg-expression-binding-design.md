# 完整表达式与条件归属的消费者修订

## 科学问题

来源参考开发检查只有8/12个位置通过固定资格条件，旧参考及四个未知位置保持冻结。本轮检查完整命题消费者能否明确保留表达式的层级、条件所属命题及逐字来源位置，避免在四个汇总字符串中混合不同分支。引用层级的一致率不作为目标，也不启动新的表示收益比较。

## 单一实现

修订现有 `source_proposition_readback`。每个命题记录从表达式根到自身的有序路径；沿该路径保留每条 `conditions` 和 `under_condition` 的实际来源节点、关系类型及命题所有者。关系保持原方向，兄弟分支的专属条件不能归给当前分支，相关背景命题不能成为查询表达式的根。操作自身的执行条件、背景及顺序继续单独保存。

每个读出节点增加其实际证据区间所覆盖的来源单元编号；完整原文、证据边界和原有字段保持对应。所选完整表达式的根独立列出，来源指代引入的其他表达式仍作为未选中上下文。算法不根据 API 名字判断类型或执行实例，不把描述端点差异自动判为错误，也不认证两个不同描述语义等价。

## 固定实际检查

使用既有48任务研究全部144个 Graph 查询位置。十二个原有无效位置保持无效，不尝试重新生成；对132个有效位置核对原有测量不变。对44张实际有效图逐个命题检查完整路径、条件所有者和来源单元位置；预期覆盖由实际输入决定，未出现的逻辑类型不作经验正确性声明。

独立机械核对使用原始图记录及 NetworkX 的祖先、路径运算，不调用生产实现的路径计算。逐字位置通过原文切片核对。原有原文索引实际检查同时运行。全部检查使用真实既有记录，不构造替代任务或替代节点。

本轮成功只指实际记录的条件归属和表达式完整性通过核对；不能替代来源语义参考，不生成新的 Graph/Flat 成绩，不改变 Atomic 候选资格或默认 JCI 方法。后续语义比较需要独立固定新的来源参考、共同消费者说明、预算和下游指标。当前没有新增自然任务、软件生成、服务支出、受保护评价或正式角色分配。
