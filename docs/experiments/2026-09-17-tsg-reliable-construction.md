## Current method decision

The exact-reference candidate transport replaces the inefficient transport.
Semantic review remains necessary. Independent obligation inventory has **not**
been adopted as an extra default stage, a reliable reference or a replacement
for full TSG construction. Adding it without evidence would add cost and another
fallible representation. Default construction still uses source records, one
ordinary review, at most one local patch, and deterministic compilation.

A separate bounded construction-agent pilot uses fresh contexts with only original
source, the existing record schema and deterministic compiler feedback. It has no
reference answers or previous outputs, at most three attempts per task, and stops
at first compilation success. It uses Codex account usage, not external-provider
budget. Its model/runtime differ from the provider checks, so any improvement
cannot isolate an agent-workflow effect. The pilot's results and source audit live
under `agent-construction-pilot`. All three first attempts compiled without repair.
The post-output source audit checked all 24 fixed reference requirements, every
additional requirement and 17 operation/input/result roles. It found no confirmed
critical binding mismatch in these three graphs. A small passing pilot does not
establish stability on repeated or new natural tasks, and the absence of repairs
means compiler feedback cannot explain the observed difference from provider runs.

The pilot exposed a separate projection defect: valid requirements directly on
`blob_bytes` or the saved path had no candidate binding without an additional
requirement-to-operation edge. The object projection correction below handles
these requirements without changing their source graphs or inventing participation.

One debug label was also corrected prospectively: absence of an operation execution
gate now reads “NO DECLARED EXECUTION GUARD,” not “UNCONDITIONAL execution.” An
operation's presence does not mean it executes on every path. This changes no graph,
compiler rule or requirement guard; old archived readbacks remain unchanged. A
missing **requirement** condition is still a semantic omission, not excused by this
clarification.

## Repairing ownership of temporal requirements

The source interface previously used `operations/subjects` for direct recipients
of the whole predicate, while constructors and reviewers sometimes read them as
participants. Required order also lived in ordinary operation edges without its
requirement owner. This was an interface defect with a downstream consequence:
removing the requirement could leave its order asserted as independent context.

The current source schema gives runtime atomic requirements a `relations` list.
Only `precedes` is supported here. The compiler preserves owner, operands, guards
and composition in `requirement_relations`; it emits neither extra direct-target
edges nor ordinary precedence edges for these rows. Extraction, review, patch and
readback share the same binding definitions. Existing direct targets may still be
plural when the entire predicate really applies to each. Independent order needs
separate source support and remains protected during an edit.

Candidate projection freezes direction and operands as `policy_relations`.
Applicability requires unique source endpoints, not the order's prior presence.
Positive expression must match the full binding. Source dependency checks include
the endpoints. A reviewed removal can drop its target owner's order but must retain
other owners and independent ordinary order, including separate support for the
same pair. No new reviewer, model round, Pair analysis or causal variable was added.

reference. Each allowed one compiler-only repair; both first drafts compiled,
