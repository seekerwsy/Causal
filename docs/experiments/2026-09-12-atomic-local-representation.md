# Program-assigned facts and source-local availability

This bounded development revision asks whether removing first-response self-references
can make the source representation executable while preserving atomic meanings and
conservative scope decisions. It remains inside representation in the single active
seven-stage method. The protocol is `SPECIFIED_DRAFT`.

## Implemented behavior

1. The first response has `nodes`, `coverage` and `unresolved_notes`. Nodes cite
   preassigned source-unit keys; the program assigns `fact.1`, `fact.2`, etc. and
   constructs the inverse coverage mapping. Frozen concepts use supplied IDs; open
   concepts are inline. The model does not reference freshly invented node IDs.
2. The second response declares source-cited operation/object roles, confirms
   fixed-ID relations and supplies `unit_impacts` for every source unit. It cannot
   add or relabel facts. Independent requirements are already separate; their
   conditions, negation, thresholds and subject bindings remain intact.
3. Incomplete source units are localized only through explicit whole-source impact
   declarations. Global or uncertain impact blocks all operations. Missing roles
   and unresolved layers propagate through their source-unit ownership and declared
   consumers. Missing graph edges do not prove independence. Every enumerable scope
   remains either assessable or withheld with reasons; task incompleteness remains.
4. `evaluate_open_semantic_case` reports `scope_quality` and `layered_metrics` beside
   full-task completeness. Prospective `scope_dependencies` must cover every expected
   scope and include its state check; absent mappings conservatively use all declared
   critical/non-target checks. Missing graphs retain expected scopes as unassessed.
   Decisive errors, unknowns, unassessed scopes and supported/unsupported/unreviewed
   assertions are separate counts. Source review is still required for usability.

Local availability is a development diagnostic, not accepted independent
qualification. The existing formal qualification thresholds and conservative
task-level uncertainty bounds have not been lowered or relabeled. No old review,
graph, unknown or failed experiment is reinterpreted under this revision.

Concrete failures distinguish the remaining causes:

- **Interface consistency:** seven rows say `effect=local` with an empty operation
  list. Temperature declares six extraction outputs but labels those same objects
  as inputs to extraction instead of results. Role and input/output declarations
  redundantly encode the same incidence and can disagree.
- **Source semantics:** the two-operation case invents concatenation and maps
  "pass x separately as a bound SQL value parameter" to a prohibition. Temperature
  omits the request and endpoint objects. The length case correctly separates binding
  from the at-most-10-character atom, but invents concatenation and substitutes request
  extraction for the SQL operation. Atomicity alone does not fix operation grounding.
- **False completeness:** source-impact answers repeatedly claim completeness despite
  missing meanings or bindings and omit downstream consumers. In the conditional case,
  safe/raw wrongly qualify the query operation itself, producing a combined condition
  context rather than the intended separate requirement branches. Self-declared
  coverage and local reach cannot certify usable scopes.
- **Semantic uncertainty outside the reference:** PDF scope `s1` declares
  `not_applicable`, while its rationale repeatedly treats empty subjects as implicit
  inputs and ends with an applicable interpretation. Structural validation does not
  detect prose contradictions. The review retains uncertainty instead of repairing
  the answer. PDF also omits the explicit storage-before-download relation.

The exact requests contained the correct concept definitions and source texts.
The adapter sends the annotation prompt as the system message and the captured
request as the user message. Exact content replay reproduces the semantic choices;
there is no evidence that local request or graph transformation introduced them.
This diagnoses this model/interface combination; it does not establish a general
model capability ceiling or a controlled improvement over an earlier run.

## What the evaluation still needs

Four nodes preserve a meaning with a shorter citation than the fixed anchor:
the retrieved password and three input-variable mentions. These remain unmatched
under the original rules, but source review separates them from missing meanings.
The conditional case also represents returning selected rows as an operation plus
its object, while the reference demands an additional return-behavior requirement
node. Whether this duplicate encoding is necessary is a prospective reference-design
question. No post-response reference or score was changed.

The next methodological decision should simplify the existing binding interface:
state the operation-local object role once and derive the corresponding input/output
edge, with explicit definitions separating SQL identifiers from values used to
identify business entities. Qualification should accept prospectively documented
source-equivalent atomic meanings and compare their operation/subject/condition
bindings, while retaining unknowns and non-target requirements. Neither change
authorizes weakening semantic accuracy or trusting the extractor's own completeness
claim. This next revision has **not** been implemented or executed by this check.
