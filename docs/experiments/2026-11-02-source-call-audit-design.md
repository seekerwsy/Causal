# 来源调用位置与对象状态的只读核查

## 科学问题

在Codecov表示比较已经冻结、代码结果尚未读取时，核查语法位置是否能够帮助区分被合并的调用与对象状态。已有独立评价指出，Graph的op.collect将引用处理前后root共同连接，但未分别保留YAML、文件清单、.bowerrc与os.walk消费者。原始图已经具有两个对象概念，缺口涉及具体操作分解与来源绑定；这不是新增Graph或代码收益。

本检查只使用已暴露的三个固定自然来源任务，以及此前已取得的Kedro实际Python API源码。它不取得新任务，不读取正在生成的Codecov候选，不改变其表示、模型、分配、测量或判定，也不重新评分旧资料。

## 解析范围与保留的不确定性

使用成熟LibCST解析完整Python源码，保持原始源码逐字一致；只使用只读visitor及官方位置、父节点、表达式上下文、作用域和可能限定名称元数据。提取全部Call、Subscript、BinaryOperation、Assign、AnnAssign、AugAssign，以及Name／Attribute的LOAD位置；不按模型成绩或对表示有利程度选择调用。

每项保存文件和完整源码摘要、字节范围、行列、逐字表达式、词法上下文及语法包含关系。调用参数各自保留位置；条件语法不直接解释为已成立执行路径。Name访问保存库提供的全部词法赋值候选，不按最后文本位置推断运行状态；Attribute访问不赋予超出库作用域分析的对象属性解析能力。

语法树可以定位root=quote(root)、独立的opj与os.walk调用，以及Kedro的dict(_sh)和实际API内部调用。它不证明某条执行路径、不建立跨函数或跨模块真实数据流、不判断输入可信性、不补全要求语义，不提供安全或因果关系认证。调用位置与对象状态的语义连接仍需独立来源判断。

## 固定核对与用途

保留每个实际Python文件及全部上述语法节点，独立使用成熟Python AST逐项核对Call、Subscript、BinaryOperation与三种赋值的源码范围和表达式；另核对每项字节范围与逐字文本、输入摘要及未执行声明。用Codecov的quote(root)、YAML、.bowerrc、os.walk四项来源位置，以及Kedro实际shelve源码的恢复调用作解释示例，不将示例选择当作新的统计任务。

检查结果只决定来源位置工具是否可用于后续研究准备。新增资料如用于新的Graph／平面比较，双方必须获得相同原始来源与位置资料，制作预算和消费者规则另行在新输出之前固定。当前Codecov16项真实生成保持原协议。默认方法及正式协议不变。
