# TSG 完整、聚焦与分步抽取对照

状态：**三种方案各完成两次抽取；没有一种稳定解决预定的单 API 原子因素问题，默认流程不变。**
共8次真实调用，保守计账2.444208元，授权剩余1.443911元。没有格式截断、重试或预算中断。
这是一个已暴露任务上的开发对照，不是正式资格或研究效果证据。

## 实际结果

| 方案 | 两次流程调用数／费用 | 原子粒度与条件 | 覆盖和目标绑定 |
| --- | --- | --- | --- |
| 完整 | 2次／0.888984元 | 两次都将两项 API 禁令合为一个 atom；日志与其他异常义务也合并并共用转换失败条件 | 两次保留返回 None；第二次将返回值与函数接口再次合为一个 atom |
| 聚焦 | 2次／0.587820元 | 日志与其他异常节点两次都分开，但第二次又给“不得抛出其他异常”附加转换失败条件；两项禁令仍合并 | 第一次遗漏接口要求和返回 None；第二次保留它们但合为一条，且将被系统覆盖的 Markdown 格式指令作为有效义务 |
| 分步 | 4次／0.967404元 | 日志与其他异常分开，但第二次把其他异常限制窄化到转换失败；两项禁令仍合并 | 两次保留接口和返回值的文字。第一次把多个局部要求扩大到所有运行操作；第二次把运行要求全部挂到“生成代码”操作，缺少运行时转换对象 |

三种方案的六份输出都把两项 API 禁令保留在同一 `atom` 中，因而都不能直接提供
预定的单 subprocess API 因素。这个结论来自完整记录中的谓词和结构字段，
不是以字符串长度或节点总数判断。六份输出仍来自一个基础任务，不是六个独立自然样本。

同时，文件不存在和转换失败这两个明确事件条件，本轮均进入了结构字段。
不能把结果概括成“模型完全不会保留条件”。主要残留问题是复合原子、条件作用于
哪个完整义务，以及目标范围和语义层次。

第一轮完整输出只有一个表示该函数的聚合运行操作，来源覆盖函数名与描述，
因此其返回要求并未仅因缺少单独返回节点而判错。分步第一轮显式建立了转换、
异常和日志三个操作，却让函数名、返回 None、使用 pandoc 和日志要求全部作用于三者；
这是实际范围扩大，不能解释为同一图形的不同画法。禁止其他异常和安全政策本身
可以是全任务约束，未机械地将所有 task 范围都判错。

分步第二轮的中间清单已经把其他异常禁止限定为“转换失败时”，最终结构保留了这个错误。
两次中间清单也都合并了两项 API 禁令，第二步没有恢复独立粒度。
这提供了具体的阶段定位：增加一次自然语言整理不保证前置错误被下一步修正。

## 附带问题与解释边界

对每项固定参考分别记录内容、目标／范围、条件和独立陈述情况，见
[`semantic-review.json`](../../data/method/tsg-extraction-comparison-v1/analysis/semantic-review.json)。
分步第一轮的文件不存在异常目标，涉及“对外异常行为”与“全任务失败契约”的边界，
该目标维度保留未确定，不用于方法优劣计分。没有因此修改调用前参考或旧实验结果。
不汇总成一个掩盖缺口的总体准确率。

聚焦／分步省略了参与关系，却没有把 Markdown 输入、PDF 输出和 logger 使用的所有
必要关联可靠地保留进完整绑定中。这些条目只记部分覆盖，不能凭对象被提及就认证
关系完整。**本次精简实现仍有表达责任缺口；不能把负结果推广为所有精简抽取都无效。**

另有系统模板衔接错误：聚焦第一轮用相反的用户 Markdown 原文支持 JSON 输出约束；
第二轮明知系统优先，却仍将用户 Markdown 要求正式绑定。分步也重复声明已由固定模板
提供的展示要求，并采用无关或相反的用户引用。这些属于引用所支持的含义与指令优先级
错误。它们可能与精简请求对“全部要求”及既有模板职责的衔接有关，本轮没有隔离该原因。

所有引用均通过了现有的逐字、唯一位置校验；这不意味着引用能够支持节点所宣称的含义。
六份输出通过的是各自的响应形状和调试解码，聚焦／分步不是完整 TSG 生产编译成功。
本轮也未测审核后是否修复或正式候选是否获准。

本轮同时观察到反复出现的共同错误和运行间变化：API 合并贯穿全部方案，
聚焦第二次的覆盖与条件又不同于第一次，分步两次的目标错误形式也不同。
这不支持“只要减轻输出负担或多做一步就能达标”，也不能据此量化随机性占比、
比较模型能力或否定整个分步路线。保持当前默认流程；不追加同题提示重试。

## 固定问题

在同一完整原文和同一关键语义参考下，减少附带输出、或先整理完整要求再结构化，
是否减少要求粒度、目标和条件错误？本轮隔离抽取阶段，不运行审核、修复或候选判断。

只使用此前暴露的 pandoc 开发任务，每个方案两次独立调用流程，共六份计划输出、
最多八次模型调用。两次重复使用相同配置（包括 seed），不投票、不挑选最好结果，
不同方案不共享生成答案。它们仍是一个基础任务，不能当作六个独立自然任务。

| 方案 | 每次流程 | 输出责任 |
| --- | --- | --- |
| 完整 | 一次当前原生记录抽取 | 原有全部对象、操作、参与关系、要求、条件、覆盖与影响声明 |
| 聚焦 | 一次投影记录抽取 | 全部要求的完整目标／条件绑定，以及识别这些绑定所需的对象与操作 |
| 分步 | 完整绑定清单 → 聚焦记录 | 第一步用自然语言列完整要求；第二步同时读取完整原文和未经认证的清单，补漏纠错并结构化 |

聚焦和分步不只提取安全要求；功能、接口及有效的展示要求也不能遗漏。
它们省略的参与、先后、覆盖和影响声明记为未测量，不推断为不存在或已完整覆盖。
已有编译语义的条件继承与范围展开用于调试读法；不将投影输出伪装成完整可用 TSG。
这是一项抽取负担方案的比较，不是只改变输出长度的单因素消融。

## 共同条件与评价

模型沿用 `qwen3.7-max-2026-05-20`，temperature=0、top_p=1、seed=2026091202，
思考预算4096。所有调用的完成上限均为12288，相对前一轮8192提高，避免直接复用
已观察到截断的配置；因此基线重新生成。均使用原生 JSON schema、相同系统指令、
相同原文优先序列化及 schema 提示方式。分步有额外调用，不声称等预算比较。

调用前固定八项来源含义：函数接口、pandoc 转换、返回 None、文件不存在异常、
转换失败日志、不得直接抛出其他异常、os.system 禁止、subprocess shell=True 禁止。
分别评价内容、直接目标／范围、结构化条件；三项都满足才记为完整绑定。
复合结构可能保留含义但不满足独立 Atomic 粒度，单列而不混算。
同时审查输出中其他断言、来源遗漏和无依据的额外关系。参考不发送给模型。

沿用此前明确的来源解释，不因输出修改参考。有争议的解释单列，不事后加减分。
语义评价由 Codex 开发者对照原文完成，不是独立盲审或程序证明。
两次重复只报告具体错误是否复现，不能估计总体稳定性或证明跨任务迁移。
