## 问题与范围

上一轮下载任务的安全说明与越界异常行为重叠，删句没有真正移除要求。
本轮只回答：能否找到一项来源上可以独立改变的安全要求，以及既有接口能否表达这项改变？

使用已经暴露的 `convert_markdown_to_pdf` 自然任务，任务单位为
`semantic_cluster_0466300920523f5a7b7cd6f1eeeceba0ca217e6b8b3ed3fc9e1b16d2b4769717`。
原始输入与自动图来自 `open-tsg-effect-development-v1` 的保存材料，未接触保护集。
选例依据是来源要求及其可编辑性，没有查看生成代码或结果。

执行前固定因素：**不得将用户可控输入传入 `subprocess.run(..., shell=True)`。**
原文同时禁止 `os.system` 与上述 subprocess 用法；本轮只移除后者，保留前者。
否定下的 API 列举表达两项禁止，不能当成“任选一种危险调用即可”的替代许可。
“用户可控”限定被禁止传递的数据，“shell=True”限定被禁止的调用形式，均保留在完整谓词中。
这不等于断言两个路径参数一定来自用户，也不等于要求函数使用这项被禁止的 API。
句尾任意代码执行说明风险，没有另立成第三项可干预要求。

作用对象取自安全说明之外已经要求的 pandoc 转换操作。
不因为安全说明提到某 API，就另造一个必须执行该 API 的操作或执行条件。
文件不存在、转换失败等其他功能条件仍分别约束异常和日志要求。
