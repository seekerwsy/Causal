修复后的现有数据准备入口得到 **139 条 SeCodePLT 记录、0 条解析排除**。其中原来 134 条记录保持完全一致；恢复的 5 条具有不同的精确提示哈希，且与原有 2,283 条记录没有精确提示重复。

**这不是新增 5 个合格独立任务。** 自然来源、CVE 对应事实、近重复关系、功能描述质量与角色可用性仍未验证。上游填写的不同 CVE 标识不能自动证明独立性。它们只进入待审来源记录，未写入 v5 来源包，不能用于把正式 CWE-918 容量从零改成五。

## 数据准备达到什么条件才进入下一阶段

建议按以下顺序推进：

1. **现有范围覆盖与来源预审。** 完成上面 A/B 的逐项处置，产出可重复的来源、质量、语言、谱系和资格容量清单。旧的质量排除不能为满足数量目标而改为通过。
2. **角色容量与资格材料准备。** 在完整初始角色冻结前规划独立资格、Discovery 和 Confirmation 容量；继续保护原资格预留与暴露记录。新增领域的资格材料和正式任务也必须隔离。
3. **合格表示下的候选支持核验。** 核验实际上下文、Atomic 状态、Pair 自然四格、来源重叠和文本实现支持。全局 CWE 数量不能替代候选有效样本量，Pair 仍不要求其因子先成为 Atomic 候选。
4. **依据实际支持完成设计。** 比较原协议及待审推断修订在实际布局下的区间宽度、不可估计率和功效，再前瞻确定研究范围、固定 K、D/C 数量及预算。数据增加本身不能修复已经发现的家族推断失效规则。

初始来源整理不等于执行 D0。正式 D0 仍须先有合格表示和冻结覆盖目标，并且只允许一次有界、结果与选择器盲态的独立自然任务补充；它只补 Discovery。Confirmation 的新来源和角色准备必须单独前瞻规划，不能在看过确认结局后补数。

当前不写死“每个 CWE 补到多少”或统一 D/C 比例：尚无足够证据把这些数字解释为候选有效样本量或功效要求。若完成来源审查后仍缺独立容量，下一项决策应是明确额外自然任务来源或前瞻收窄研究范围。
