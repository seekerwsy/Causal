# 对开放 TSG 方法框架的研究评估

状态：方法调整建议。本文评估所引用的“TSG语义抽取流程”会话，不替换
`docs/protocol.md`，不启用新实验、重分配数据角色或重解释冻结结果。

## 判断与贡献定位

建议采纳“开发语料归纳概念—保留作用对象的任务图—结构引导假设—独立干预评估”
这一方向。它直接服务于论文的问题：在有限验证预算下，任务语义结构是否帮助提出
并优选具有可执行比较方式的 Prompt 安全假设。

目前尚无证据说明开放抽取比封闭目录更准确，或扩大概念集合就能提高发现收益。
应分别验证两件事：新概念是否补足有意义的假设覆盖；在相同概念和候选范围下，
对象绑定和关系是否改善假设选择或编辑定位。不能仅凭更多节点或几个有趣案例认定创新有效。

LLM 从带标签数据提出并更新假设已有研究，例如
[Hypothesis Generation with Large Language Models](https://arxiv.org/abs/2404.04326)。
本项目的潜在区别应落在要求的作用对象、可比较的局部编辑以及独立代码安全结果之间的联系。
这是拟验证的贡献定位，不是已经完成的相关工作排他性证明。

## 相对于当前实现，真正需要改变什么

当前 `task_context_scope` 先由 `(CWE, task_family)` 匹配预定义机制查询，再取查询需要的
语义与关系并集。虽然单次模型请求已隐藏外部标签，模型仍只判断这个预先裁出的集合。
单纯去掉两个输入字段不会打开表示范围。

当前 contract 以 `semantic_id` 唯一标识任务内的判定，compiler 也以它生成节点。
因此，同一任务里的多个数据库操作或多个文件访问无法自然对应多个同类实例及各自的要求。
底层图结构可以保存实例；需要调整的是当前抽取 contract 对实例与概念类型的绑定方式。
不需要为了这个问题再建设一套图引擎。

最小表示改动是区分：

- 概念类型：例如“参数绑定要求”“签名保持提醒”。
- 任务内实例：哪个输入、哪次操作、哪个函数以及哪段要求。
- 关系：这个输入被哪个操作使用；这项要求约束哪个对象；条件修饰哪项要求。

同一概念可以在不同实例上出现。原文依据绑定实例，跨任务归一化绑定概念类型。
“输入供操作使用”与“输入受到校验”需要不同关系；“进行 HTTPS 通信”与
“明确要求证书校验”需要不同语义角色。这两项区别直接对应本次已观察到的失败。

## 建议的三阶段论文叙事

| 论文阶段 | 核心方法 | 对应现有科学阶段 |
|---|---|---|
| I. 语料驱动的 TSG 建模 | 开发语料单次开放抽取，归一化，固定概念定义；按固定定义构建带对象绑定的图；可选 D0 仅补充预定义任务上下文的自然覆盖 | representation；D0 是进入 Discovery 前的数据准备，不增加科学阶段 |
| II. 结构引导的假设优选 | 从要求与目标对象的局部结构生成候选，检查自然支持，使用发现结果排序并固定待验证假设 | prioritization；hypothesis freeze |
| III. 独立干预评估 | 将固定假设落实为对应 Prompt 比较，按任务随机化，独立测量并报告效应 | intervention/randomization；measurement；outcome assembly；inference/reporting |

三个宏观阶段足以讲清论文；七个科学阶段仍保留各自的输入输出边界。
开发、发现和评估是叙事上的用途区分，不能据此合并已有资格保留集或改变任务角色。

### I. 开发阶段开放概念，研究执行阶段固定含义

预定义少量基本类型和关系：输入/对象、操作、要求/约束，以及输入使用、作用对象和条件修饰。
具体概念从开发 Prompt 中归纳；旧目录可以提供初始概念，但不限定所有可抽取内容。
此阶段不依据生成结果、FCI 分数或选择器排名增删概念，也不因外部 CWE 标签而裁掉原文中
实际存在的接口、资源或行为要求。

开放抽取先记录有原文支持的事实，不要求它宣告所有未提及概念都不存在。概念归一化只合并
操作意义等价的表达：签名保持、返回约定保持和全部可观察行为保持应分开。
统一要求表示可保留“内容、作用对象、范围、表达属性”，但只纳入本轮研究实际需要的属性。

开发完成后，固定概念、归一化规则和出现/未表达/未知的判定定义，再在发现集与评估集应用。
在固定候选范围内应明确判断是否表达，不能把开放抽取的漏项直接编码成不存在。
发现或评估过程中遇到新概念不即时扩充本轮假设空间。

从文本学习表示与独立样本估计之间的分离有已有方法论基础；
[Egami 等人的研究](https://pmc.ncbi.nlm.nih.gov/articles/PMC9581481/)讨论了表示学习可能导致的
识别与过拟合问题以及样本拆分方法。本项目采用这一边界，不将拆分本身声称为创新。

### II. 用同一个局部假设贯穿候选、编辑和验证

建议假设对象明确记录：目标子图、前置上下文、一个或两个可操作因素、具体编辑政策与比较式。
模型、主终点等全研究共用设置不必在每个假设里重复。

例如，任务始终要求给定函数接口；可研究的因素是是否额外强调保持签名，而非是否允许破坏接口。
“参数绑定要求 × 签名保持提醒”可以构成候选，但必须先确认两项能独立操作，并且自然发现数据
对两项的四种状态具有必要支持。此例是方法示意，不是现有语料发现或效应结果。

沿用现有优选器的职责分工：原子候选由 FCI 提供结构资格信息，由共用一阶风险差评分排名；
Pair 使用自己的支持与兼容性条件和二阶评分，不依赖两个原子因素先获支持或入选。
FCI 不直接输出被确认的因果机制，图中的语义边也不是因果边。
图中相互决定的重复编码不应全部塞入 FCI 的变量表。

结构信息可以帮助提出和优选因素对，但不能先用结构限制所有方法的候选池，再声称
“无关系”消融没有收益。比较结构作用时，候选全集、自然支持、任务、评分、预算和后续
评估应相同，只改变是否使用关系信息。纯交互通道继续保留。

新增概念若没有自然变化或四格支持，可保留为表示能力和后续研究的线索，不能强行宣称由
观察数据完成了效应优选，也不能合成或改写自然 Prompt 来填充 Discovery 单元格。
任务内多个局部子图仍属于同一个独立任务单元，不增加统计样本量。

上下文异质性可纳入框架，但上下文对照的任务安排和多重比较规则需要在执行前明确。
本次建议不把当前停用的上下文推断或 Pair 反应模式标签直接改为启用。

### III. 检验可执行的 Prompt 政策

图中的对象绑定应实际决定编辑哪段要求、作用于哪个操作、保留哪些非目标行为。
原子比较使用预先确定的目标编辑与对应对照；双因素比较使用四种合理状态，并报告
风险差尺度上的交互。应按 ADD/REMOVE 的来源条件定义各臂，不能把修改必须遵守的业务
行为混成一个安全提醒因素。

独立评估继续采用按任务区组的随机化、任务单元 ITT 和全分母计数。主安全终点仍是
oracle-evaluable secure-code yield；Oracle 未知、代码有效性、功能和联合成功分别保留。
对照组也可能自然生成安全实现；显式提醒缺失不等于软件保护缺失。

文本编辑的因果结论对应冻结的编辑政策和任务范围，而非某个抽象概念的普遍纯效应。
[Fong 与 Grimmer](https://onlinelibrary.wiley.com/doi/10.1111/ajps.12649)指出，随机化整段文本
本身不足以识别其中每个潜在文本因素的效应。这支持保留具体比较文本和结论范围。

## D0 改进评估：只补充任务上下文覆盖

根据 2026-09-11 提供的 “D0: Prospective Coverage Augmentation” 建议，推荐将下一版原型的
D0 收敛为**表示冻结后、Discovery 冻结前的一轮可选自然任务补充**。这是对当前补样目标的
实质性简化，不单是叙事更名。本节仍为方法调整建议；没有修改活动协议、运行补样或启用新推断。

### 采用的核心及其科学边界

固定上下文定义 \(C_k\)、计数阈值 \(m_k\)、来源范围、预算及停止规则后，按去重任务单元计算
\(n_k=\#\{i:C_k(P_i)=1\}\)，以 \(d_k=\max(0,m_k-n_k)\) 确定场景覆盖缺口。
只有 \(d_k\)、预先允许的来源元数据和既定采集顺序参与补充决策；不按单因素的表达状态、
Pair 四格、候选关系支持、生成结果、FCI/RD 或排名选择来源和任务。

统一阈值 \(m\) 足以作为简洁的原型设计，但其数值须前瞻确定，不能在查看特征分布后倒推。
它是覆盖目标，**不保证自然状态变异、四格支持、可识别性或统计功效**。来源多样性与去重
沿用简单的预设规则，不发展成新的逐候选补样系统。

| 环节 | 应回答的问题 | 使用的信息 |
|---|---|---|
| D0 | 哪些事先定义的任务场景覆盖不足？ | 上下文任务数、独立来源、允许的元数据 |
| Discovery 的自然支持检查 | 哪些候选在固定任务池中有可比较的自然变化？ | 特征状态、四格、谱系重叠与分折条件 |
| Discovery 优选 | 哪些合格假设值得投入固定验证预算？ | 协议允许的发现结果、FCI/RD 与结构信息 |
| 独立干预评估 | 固定 Prompt 政策产生什么效果？ | 独立任务上的随机化、测量及任务单元 ITT |

因此，原建议中“Discovery 决定研究结论”应收窄为“Discovery 优选待验证假设”。确认性的
效果结论来自最后一行。D0 的价值是扩大可研究场景的自然覆盖，不能预先宣称一定提高发现收益。

### 当前代码需要真正解除的耦合

当前 `docs/protocol.md` §25.1 仍允许事先声明的 `STATE_TARGETED`；`discovery_population.py`
也同时保留 `CONTEXT_FIRST` 和 `STATE_TARGETED`。即使选择前者，
`DiscoveryPopulationLineage.__post_init__` 仍通过 `_coverage_targets_met` 判断是否允许启动
补充及补充后的状态。该函数检查的是单因素两种状态、Pair 四格、可填候选槽位与分折可行性，
并非单独的 \(n(C_k)\)。所以，**只禁止采集请求填写特征状态，不足以实现本建议**。

| 现有对象或规则 | 下一版建议 |
|---|---|
| `CoverageTarget` 绑定特征及 PRESENT/ABSENT 最低数 | D0 目标只绑定冻结上下文与最低独立任务数 |
| `PairCoverageTarget`、四格与可填候选槽位进入 D0 | 将这些条件留在 Discovery 的候选支持检查中 |
| `STATE_TARGETED` 作为活动采集选项 | 从下一版活动路径移除；既有冻结记录保持原解释 |
| `_coverage_targets_met` 用状态/四格判断补样是否必要 | D0 的触发、目标选择和停止均只依赖上下文覆盖及预算 |

这些是同一个现有路径中的局部方法修改，不需要增加补样框架、执行器或多层新记录。
现有“补充前计数—计划—来源/去重记录—补充后计数”的信息可保留，论文正文只解释四步操作。
原实现还将 `coverage_enriched` 与 `STATE_TARGETED` 等同；下一版不能据此把 context-first
补充描述为未改变分布，应直接说明它改变了上下文及来源构成，而不重解释旧字段。

### 上下文不能成为特征状态的替身

上下文应描述输入、操作及需要保持的任务边界，例如“外部值进入固定结构的 SQL 操作”，
而不是“要求参数化的 SQL 任务”。对所研究的 ADD/REMOVE 政策，上下文应保持不变；安全要求
是否表达是另一个坐标。同一任务的多个操作实例不增加独立样本量；同一任务可以属于多个
上下文，但各上下文只计一次，总体数取任务并集。

“使用冻结 TSG 上下文”限于由固定输入—操作语义判定任务归属，不能扩展为按候选要求与对象
的关系支持、Pair 关系稀缺度补样。后者与现有禁止用 Prompt-TSG 关系支持选择采集对象的规则
冲突。该区分须写清，不能把同一种关系支持换名为 context 后继续使用。

D0 期间不因新任务出现新概念而重开本轮表示。上下文未解析时保留未知，不当作上下文不存在；
是否能够计入目标上下文由既定语义规则决定，不依据目标特征能否解析来筛选任务。概念或
表示规则若确需修订，应回到方法开发，不能一边扩充表示一边依据新增缺口连续补样。

### 结果盲是程序约束，不是自动成立的独立性定理

建议保留“outcome-blind acquisition”的文字定义，删除无附加假设的
\(\mathrm{Acquisition}\perp Y,\mathrm{Discovery\ results}\mid C\) 声明。
同一上下文中，来源、语言或任务复杂度仍可能同时影响获取机会和模型结果；未读取结果不等于
样本选择与潜在结果在统计上独立。选择偏差与跨总体推广需要额外条件，这一一般边界见
[Bareinboim 与 Pearl（2016）](https://pmc.ncbi.nlm.nih.gov/articles/PMC4941504/)。

更贴切的形式是规定采集政策的输入：
\(A=\pi_{\mathrm{acq}}(C_R(P),M(P);\xi)\)，其中 \(M\) 仅含预先允许的来源/语言等元数据，
\(\xi\) 为固定次序或独立随机种子；目标特征状态、候选关系支持和发现结果不作为筛选依据。
这是对程序的限定，并不证明获取分布等于某个完整自然总体，也不证明特征分布不受来源变化影响。
最终效果仍针对冻结的 Confirmation 任务范围与 Prompt 政策，不借 D0 推广到所有编程任务。

### 一轮结束条件及最小报告

“一轮”指同一个预先确定来源、规则与预算的采集过程，允许过程内仅按新增上下文计数执行
既定停止规则。覆盖目标达到、预算耗尽或预设来源用尽后即结束，保留剩余缺口；不能看完
特征状态或 Discovery 结果再追加一轮。停止时尚缺某个上下文不等同于它不存在，也不应单凭
这一项让所有已覆盖场景失效；研究整体是否满足固定槽位等要求，仍由后续原有设计条件判断。

Confirmation 来源范围、任务保留规则及独立性边界在 Discovery 结果产生前确定。D0 新任务
只进入 Discovery，并与已有开发/资格/Confirmation 任务及近重复组隔离；不因某个候选难验证
而转移或补充 Confirmation 任务。随机化前支持不足应与随机化后测量未知区分，后者必须留在
分配分母中，不能统一写作 “unsupported” 后排除。上下文修饰推断与 Pair 反应标签仍不因此启用。

论文先报告每个上下文的补充前后独立任务数、实际新增任务与来源、采集/审核量和剩余缺口。
若仅把 D0 作为辅助数据准备，不必额外设置一个大型效果 RQ。若要进一步声称提升可发现性，
应在补充结束并冻结后报告实际通过自然支持检查的候选变化，而不是由 \(n_k\) 增加直接推断；
若要比较采集策略优劣，则另需同来源范围、同预算的对照。原有 Full/RD-only、Full/No-Relation
比较必须使用同一补充后的任务池，避免把数据差异误算为结构模块的收益。

目前的 117 个 CWE 标签和 1,992 个候选任务只支持来源容量描述，不是冻结的上下文覆盖图。
附件中的 83、47、6、4 是方法示例数，不是本项目结果。开放 TSG 尚处建议阶段、当前抽取候选
也未通过资格，因此不能拿 CWE-611 或 CWE-295 的任务数代替 XML/TLS 上下文的 \(n_k\) 并开始补样。
下一步若采用本建议，先用已暴露开发任务检验“改变安全要求表达不改变上下文归属”，以及
“改变特征状态/Pair 支持不改变同一上下文缺口下的采集决策”，通过后再形成正式覆盖图。

## 论文需要什么最小证据

| 要验证的设计 | 有辨别力的比较 | 不能替代它的证据 |
|---|---|---|
| 开发语料扩展有用 | 旧概念集合与扩展集合，在共同的任务/预算规则下比较新增可操作假设及独立验证结果；明确这是整个流程比较 | 节点数增加、LLM 认为概念新颖 |
| 图的对象与关系有用 | 同概念、同候选、同选择器和预算，比较保留结构与移除结构；分别分析选择质量与编辑定位 | 将所有组件同时更换后得到更高结果 |
| 优选结果有用 | 同等选择槽位与验证预算下，与共用风险差/无关系消融及明确选定的外部基线比较 | 只验证成功候选，替换失败槽位 |
| 编辑产生效果 | 独立任务上的随机化比较，报告区间、未知与功能变化 | 自然数据相关性、FCI 边、解释听起来合理 |

“直接 LLM 假设生成”可以成为新增候选生成基线，但不能直接把 HypoGeniC 的分类指标等同于
安全干预发现效果。需要让基线获得可比的发现信息，输出同样可操作的比较对象，计入同样的
筛选和验证预算。它与现有 RQ4 专家解释评估是不同任务。

保留当前 RQ1 的预算受限优选、RQ3 的独立安全效果、RQ4 的解释感知价值；会话提出的
开放概念与表示消融扩展了当前 RQ2 范围，不应悄悄覆盖已有 FCI/RD 与 Pair/No-Relation 对照。
可在下一版研究设计中分别提出概念覆盖与关系价值的证据，随后统一调整 RQ2 表述。

## 与刚完成的实验如何衔接

[20 次调用的开发对照](2026-09-11-tsg-label-comparison.md)中，两组均为 7/10，与额外标签无关的
状态结果完全一致。头像案例把数据流误读为校验要求；TLS 目录把通信上下文与证书要求混合；
通用 SQL 仍有语义与引文问题。这支持检查表示定义与作用关系，但不证明开放表征更可靠。

下一步最小原型应首先在已暴露开发材料上演示：

1. 同一任务的多个操作及其要求可以分别表示，并保持准确的作用对象。
2. 从原文归纳出旧目录缺少、且具有清楚编辑对象的概念；不得为了得到“新概念”而合并或编造。
3. 相同概念的扁平表示与结构表示，确实在一个可检验的问题或编辑定位上产生有意义差异。
4. 在扩大调用之前，检查候选的自然状态支持与独立干预可行性；若支持不足，收缩结论或候选，
   不回到全库清洗，也不把合成例子计入自然支持。

开发原型先检查这些边界，不为获得好看的发现结果反复调整概念。本轮没有进行开放抽取、
新增 provider 调用、数据曝光或正式方法切换。旧的 7/10 与失败记录均保留原有解释。
