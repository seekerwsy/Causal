# Remarshal解析后对象图的展开限额测量

## 固定来源与完整政策

固定第十四项CVE-2023-47163，原始提交d95a1846b9e54efeb570ce80f93f24ab13db9976，版本0.17.0。目标为完整remarshal.py，使用原有成熟格式解析与编码库。当前准备Graph组件任务的测量资格，没有模型生成、自然编程请求或相应Atomic ADD资格声明。

研究者政策限定YAML输入：在YAML解码对象进入unwrap、wrap、transform或任何输出编码之前，拒绝存在可达容器循环或展开节点出现次数大于256的对象，抛出ValueError。模块常量YAML_MAX_EXPANDED_NODES=256。根对象计一次；dict、list、tuple、set容器及其每次出现都计一次；映射的每个键和值分别计数；标量每次出现计一次。同一对象由多条路径到达时重复计数，不能使用唯一对象数量代替展开数量。恰好256允许；有限共享引用保持。

完整解码后的对象图决定限额，不按YAML文本中的别名符号数量判断。政策适用于decode_yaml、decode('yaml',...)、YAML输入的remarshal和CLI。transform固定None。非YAML输入保持原有行为，不自动套用此限额。

该限额是明确的局部研究政策，不认证解析阶段内存和时间、标量长度、总进程资源、任意用户transform或完整拒绝服务防护。输出文件原本在解析前打开，不能宣称拒绝时保留既有输出文件内容。

## 实际输入与独立对象资格

prepare_fixtures.py在执行来源之前用成熟PyYAML构造和解析全部固定输入。十一份不合格YAML为：257节点的平面序列、257节点的映射、共享浅序列、嵌套序列共享、嵌套映射共享、经!!omap产生tuple的重复引用、自引用序列、自引用映射、互相引用、!!omap内部循环，以及可以被unwrap跳过的超限分支。前六项及最后一项无循环且展开超过256，其余四项包含循环。

十八份正常YAML包括十四份可移植输入，以及二进制、带时区时间戳、有限!!omap和!!set。可移植输入覆盖空输入、标量、普通与嵌套映射、有限别名、255与256节点边界、完整对象检查后的解包、字面别名文字、保序与排序、null转换。正常二进制转换为CBOR、MessagePack和YAML，时间戳转换为JSON、TOML和YAML；omap与set只检查直接解码。未测量的类型与格式组合保持未知。

另有JSON、CBOR、MessagePack及TOML四份非YAML输入，携带超过YAML限额的普通序列，通过真实解码和YAML输出检查保持。全部输入使用成熟库编码，不编写格式解析器。输入身份、文件字节、独立对象图的循环判断和展开数量均在控制测量前保存。

独立输入资格使用NetworkX 3.3 MultiDiGraph表示实际解析对象的身份及每条包含边。循环使用成熟DAG判断；无循环时按反向拓扑顺序累计所有出边的出现次数，保留平行边。该算法独立于参考控制逐路径访问并提前停止的算法。不存在对象图真值恢复或因果图身份。
