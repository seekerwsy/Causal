# 原始程序安全任务的资料资格检查

## 检查范围

本次检查服务于一个具体问题：能否取得带原始程序、合法输入功能测试与独立安全测试的自然任务，为 Graph 的操作绑定及其下游安全结果提供比较条件。检查只读取公开论文、仓库说明、准备程序、执行程序与任务身份目录；没有选择具体漏洞任务，没有读取任务程序、修复补丁或具体测试，没有执行来源程序或调用代码生成模型。

公开材料为 [Vul4Py 论文](https://arxiv.org/html/2608.00692v1)及其作者发布的 [Vul4Py 仓库](https://github.com/tabudz/vul4py)。仓库检查固定到提交 `f80f861012cb7b7cfeca7323be51d33e72eaf8f3`。论文描述了真实 Python 漏洞、成对漏洞／修复版本与安全及功能测试。这里记录公开材料的实际实现条件，不将论文结果计入本项目证据。

## 后续来源资格与表示比较的必要条件

具体任务进入开发比较前，需要固定来源提交、合法输入范围、单项可编辑要求与任务身份；选择规则必须独立于 Graph 支持程度、方法评分及结果。漏洞原始版本与修复版本分别运行相同的功能、安全检查，记录实际收集、通过、失败、错误及跳过的测试身份。安全差异必须能够追溯到相关断言；收集失败、依赖失败、没有测试与跳过测试继续保留各自状态。功能测试至少应有实际通过的合法输入检查。局部测试通过只支持对应功能范围，完整功能性仍需另外说明。

Graph 与强平面表示取得同一份原始程序、任务说明及可公开合同。制作表示的上下文不能取得修复补丁、答案位置或评价测试答案。独立参考在两种方法输出前固定，先评价要求与操作、对象、条件及所有者的完整绑定，再使用独立测量的安全与功能结果评价下游影响。任何新增代码结果都需要按事前设计生成；已知漏洞程序的存在不证明实验模型的基线程序不安全。

漏洞修复任务的安全目标是否已经表达，需要按原始说明判断。不能将明确要求修复漏洞的来源自动当作安全要求未表达的 ADD 来源，也不能从原始程序含有漏洞推断提示要求缺失。任务背景代码与 JCI 随机上下文分别定义；代码上下文资格不能提供随机分配或跨环境稳定性保证。
