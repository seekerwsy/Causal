# 完整要求到候选与编辑的开发验证

状态：完整范围要求的候选与编辑通路已实现，固定语义对照已通过。
本轮没有新模型调用，不声称自动 TSG 抽取性能提高。此前两项 API 要求合并的问题仍然存在。

## 研究问题与修订

本轮检查：在要求内容、条件和范围已经正确表示时，候选映射是否仍会不必要地排除
它们，或在编辑时丢失这些区别。原实现排除全部保留的 `task/each` 要求，同时要求
要求自身的条件也成为独立操作上下文。这两项规则并非自动抽取能力的限制。

修改发生在原有候选、范围判断、编辑和独立来源审核路径，没有新增审核角色或调用轮次：

- 一项完整要求可以带条件、整体范围或全称量化；不要求其为简单无条件叶子。
  `task/each` 直接绑定任务或函数边界，不恢复广播、不枚举已知实例。
- 要求自身条件进入冻结的因素定义与 `policy_condition_semantic_ids`，操作执行条件
  才进入任务匹配。政策移除后，其内部条件可以不再作为独立节点出现。
- 图中明确断言的完整 OR/NOT 表达式，在成员具有共同范围且语义审核确认单一政策时
  可以进入候选；其成员不因此成为独立义务。AND 父节点不作为多个要求的打包因素。
  不清楚的作用范围、opaque 表达式和不同成员范围仍未自动支持。
- `feature_scope_selectors` 在现有冻结目录中保存边界、目标类别、表达式种类和条件。
  候选绑定与表达状态判断读取同一份定义。根节点或空目标类别不能证明适用性，
  模型仍须根据完整原文分别判断适用性和是否表达。
- 正向状态必须有完整结构依据；条件缺失不能借正确描述放行，也不能改标为已确认不存在。
  独立来源审核列出保留范围的断言；编辑核对非目标组合和范围以及普通连边。
  只有目标表达式的成员及在目标引用内、仅由该表达式使用的条件可归入此次删除。
  共享条件、操作、对象和其他要求仍受保护。

新候选请求使用 `complete_single_requirement`，旧冻结请求不按新规则自动解释。
加入两项独立要求不会因此变成一项 Atomic 政策。顺序等开放谓词的完整含义仍须来源审核；
这次没有实现通用自然语言等价证明，也没有将任意 TSG 关系自动变为 FCI 变量。

## 固定语义对照

输入在 `tests/test_candidate_construction.py` 的 `_whole_policy_source` 与
`test_complete_policy_projection_and_both_edits_preserve_scope_and_internal_conditions` 中。
这些是同一个人工任务基底的八种语义配置，不是八个独立自然样本；模型输出不参与参考定义。
每个配置包含两个操作和一个必须保留的整体格式要求。

| 配置 | 检查的区别 | 结果 |
| --- | --- | --- |
| 失败时禁止记录令牌 | 政策内部条件与任务上下文分离 | 候选及 ADD/REMOVE 通过 |
| 整个任务累计资源上限 | 整体限制不变成每操作限制 | 通过 |
| 每条日志脱敏 | 全称规则不变成实例列表 | 通过 |
| 指定函数范围内每条日志脱敏 | 量化边界保持在函数 | 通过 |
| 脱敏或省略 | 完整替代政策，不同时断言两个成员 | 通过 |
| 禁止同时采用两种处理 | NOT(AND) 整体禁止，不拆成两个独立禁令 | 通过 |
| 记录之前脱敏 | 与之后脱敏保持不同因素身份 | 通过 |
| 记录之后脱敏 | 不与之前脱敏合并 | 通过 |

八种配置均经当前候选编译器、固定范围判断、范围绑定、实际文本 ADD/REMOVE，以及独立
编写的编辑后结构核对。条件删除被拒绝；将同一错误记录改报 absent/not_applicable 也被拒绝。
篡改非目标整体约束为全称约束被拒绝。已有测试继续检查共享条件、替代成员不独立断言、
不可在候选阶段拆源节点和等义出现归并。没有新增一组规模化测试，只增加一个跨阶段用例。

上述通过说明映射和编辑能够利用这些明确结构，不能当作 LLM 抽取、自动语义审核、自然
候选覆盖或安全效应的实测成绩。顺序对照只验证已明确完整谓词不会被投影丢失，不能证明
模型能稳定抽对顺序。条件/范围尚未抽对的任务仍可能不可用。
若候选需要改变两个操作之间已经独立表示的 `precedes` 边，当前编辑器仍将这种
操作关系作为非目标结构保护；本轮没有实现任意关系的干预归属与改写。
