## 研究结论边界

目前可以支持的判断是：实现能保留明确的对象/条件作用范围，并阻止若干范围不一致的
编辑；**类型正确、引文存在、图可编译仍不足以证明语义正确**。当前 Flash 抽取器会把
普通输入使用误标为安全要求，也会遗漏对象关系。此时继续扩大效果实验会使被干预因素
含义不清，因此本轮停止扩大自动抽取与代码实验。

这些是暴露开发材料上的能力检查，不是总体准确率、正式因果效应或 TSG 结构价值证据。
之前 SQL 全安全的零对比、局部模型结果和全部不显著比较保持原有解释，不能用本轮实现
重新解释旧结果。

## 已实现的科学边界

- 每个因素绑定自己的操作、对象集合、固定条件和来源状态。查询与渲染读取同一范围；
  未判断不等于缺失，提示词未表达安全要求不等于生成软件没有防护。
- ADD 只作用于已解析的缺失要求；REMOVE 需要明确正向要求。共享句子的局部删除通过
  预审查的中性改写保留其他对象与非目标关系，不能直接删除整句或加入不安全指令。
- Pair 的两个因素可以属于不同操作，各自保留完整绑定，四格独立改变两个要求。
  不要求 Atomic 父项先获支持。实验四格不构成自然 Discovery 四格支持。
- 开发分配沿用同一执行入口，支持 Atomic 四臂和 Pair 四格。按分配臂、任务单元 ITT
  保留全部结果；新增 Pair 输出是描述性交互及任务自助区间，没有伪造零假设检验或模式标签。
- 图中的局部/条件性正向要求不能成为整个操作或更大对象集合的无条件负向状态。
  这条规则在固定图模型检查之前已实现；模型错误与规则将其保留为未知的结果分别报告。

表示阶段现在是一个线性过程：`extract_contract_task_file` 先列来源事实，再由
`fixed_binding_request` 固定每个事实可填写的栏目，允许选择的目标仅放在响应结构的候选域中，
最后由 `fixed_scope_request` 固定
操作、输入及条件范围。关系步骤只能选择既有编号，列名决定关系类型；范围步骤只判断
适用性与要求表达。关系失败保留事实清单并停止该任务后续调用；范围失败保留已绑定图。
开放概念开发每任务最多两次调用，冻结词表模式最多三次；均属于原来的表示阶段。
唯一活动提示词是 [`open-tsg-annotator-v12.md`](../../data/method/open-tsg-annotator-v12.md)。
下文 v6 至 v11 已冻结运行保留原提示词、响应格式及实现，不能由新接口重新解释。

## 接通作用域到候选支持，并约束资格误差的不确定性

这一步回答两个直接影响科学解释的问题：同一个要求是否从来源到候选支持始终指向
同一操作、对象和条件；小样本的表示验收是否会被误当成确定的高准确率。本次仍为
离线开发，新增真实模型调用、自然任务暴露和费用均为零。

现有 `qualification positivity` 入口现在接收绑定来源、图、因素定义和逐任务范围的
`--scope-bindings`。ADD 与 REMOVE 从同一图范围派生状态；REMOVE 需要原文要求证据，
中性改写在后续干预协议化中检查，不作为来源纳入前提。Pair 的因素可在不同操作上，
其四格支持、谱系重叠和兼容性独立检查，不要求任何 Atomic 父项先通过。

每个任务政策都有处置记录。未知不补为不存在，也不从覆盖分母消失；可解析行可形成
结果前观察表，但来源支持失败会继续阻止分折。后续附加代码结果时，来源状态、
协变量和绑定身份不随结果改变。这些是随机化前的准备规则，不能用于删除分配后的失败。

来源语义验收增加事先列明的语言、操作概念、特征与金标准状态组合，按去重任务计数。
总体不完整、错误断言、错误确定状态和所有预定组合共用 Bonferroni 尾概率，计算
单侧 Clopper–Pearson 精确二项上界。组合错误保守地包含该任务不完整或任一已声明
来源检查未通过；同任务的多个操作或检查不增加独立样本数。没有样本的组合保持未知。
例如在测试夹具的 95% 同时置信度、四个界限下，1/1 正确的可靠性下界仅为 0.0125，
不是 1。这是计算示例，不是抽取器的实测准确率。定义依据
[NIST 精确二项区间说明](https://www.itl.nist.gov/div898/software/dataplot/refman2/auxillar/exacbino.htm)。

来源支持读取并重算绑定验收包中的下界，拒绝配置直接填写可靠性。对同语言、操作
和特征，要求金标准 PRESENT 与 ABSENT 都有覆盖，并取所有匹配预定状态中最低的界限，
避免按预测标签挑有利范围。合成验收不能用于自然来源。代表性独立抽样和审阅独立性
仍需外部验证；这些界限不能证明未覆盖领域的准确性。真实样本设计及阈值尚未选择。

### 已实现的变化

原始任务、声明语言和实际系统消息仍由 `prepare_task_input` 自动整理为同一来源表示，
词语和标点索引也由程序生成。用户需要固定实际输入，不需要手工制作编号文件。
输入身份一旦改变，就需要重新抽取，不能继续使用旧图。

1. `generation_template_facts` 只在实际系统消息与已知 Python 模板完全一致时，直接提供
   代码实现、接口保持、行为保持、JSON 回答和 Python 语言五项事实，以及四项约束关系。
   模型不再反复抽取这些固定含义，也不能通过另取 ID 重复提交。自定义模板仍需来源标注。
2. 第一次模型请求同时提交事实、生成／运行层级、逐来源单元覆盖情况，以及带引文的操作局部角色。
   每个来源单元必须说明已表示、尚未解决或没有任务事实；缺少一行会被拒绝。
   角色区分数据值、标识符、资源、目的地、未明确输入和结果。同一对象可以是前一操作的结果、
   后一操作的输入；有原文支持时，也可以在同一操作内兼具两个角色。

   固定模板边保持不变。候选枚举仍只表示允许选择的对象，不能当作已存在或必须提交的关系。
4. 来源覆盖、层级或已声明角色的绑定存在缺口时，保留任务、原始回答和已有图，将计划范围记为
   `withheld_scopes`，不再调用范围模型。当前暂停以整个任务为单位，尚未实现只暂停受影响子上下文。
