# 默认编译策略要求的表示比较设计

## 任务身份与证据范围

使用固定24项来源中的第一项 `CVE-2025-22153` 作为已暴露开发诊断。原始程序来自固定提交，任务重建指令及默认策略要求由研究者编写。整体提示不标记为自然编程请求。本诊断只有一个自然代码单位，不把API入口、六项判定、源码版本或上下文调用作为独立任务。

task-source.json保存九份原始包源码、原始README、公开API与策略文档以及许可证。没有修复程序、测量测试、修复位置或旧方法输出。编写范围为原始包公开编译接口所在的compile.py，该文件在上游修复中没有修改；本任务不要求重建上游补丁。任务要求明确限定精确默认策略类，自定义类及policy=None的既有行为分别保留。

来源与受控任务资格审查在表示制作前完成；完整绑定参考同样在方法输出前固定。该开发单位不进入未来独立的组件收益统计。其余23项固定身份保持原值，未取得资格、未知和同源问题均需报告，不使用本单位的有利结果替换来源或制定新的成功门槛。

## 共同信息与方法

Graph和强平面分别使用新的隔离上下文。两者获得相同的完整task-source及相同的当前任务文本，可以使用相同原生规范接口和推理能力。Graph实际输出原生来源命题记录及完整读出，使用当前的对象组成关系；平面可以保存全部操作、对象、条件、归属、量词和交叉引用，允许重建结构。

每方法规范JSON最多40000字符，最多64项来源事实／平面条目；Graph关系最多128项。各方法允许一次只涉及字段、类型、连续引用及原生接口的机械检查，之后最多一次对应的机械修订。最终记录不接收参考、评分或另一方法反馈，无法转换仍保留在该任务分母中。不得以主上下文预先编写的相同提示标记两个独立方法处理。

## 固定判定项目

对一个新增完整要求分别检查六项：

1. `requirement_role`：当前源码行为、基准任务义务和新增要求分别表达，新增要求不解释成基准已经要求的保护。
2. `operation_scope`：覆盖本模块相关编译入口及共同过程，保留返回CompileResult与返回代码或抛出异常的不同接口。
3. `subject_and_quantifier`：字符串／ast.Module及其任意嵌套TryStar的语法对象范围；不会将普通字符串内容或其他AST类型自动判作目标。
4. `default_guard`：精确默认类身份，包含省略参数或显式传入同一默认类；None及其他自定义类分别保留。
5. `result_ownership`：CompileResult.code、errors及其返回对象的归属，公开包装入口的既有错误传播，不能把所有入口都解释成返回同一记录类型。
6. `non_target_scope`：普通函数、算术、普通异常处理、非目标错误及基准任务规定的自定义／不受限行为保持要求。

每项使用complete、incomplete、incorrect或unknown，只有complete计入成功；缺少上下文保留unknown。两份新的隔离测量各自读取完整方法记录、原始来源和事前参考，彼此不读取结果。成功要求两份测量均为complete，分歧原样报告。隐藏方法名称不等于完全盲法，表示形式可能可辨识。

本诊断报告逐项判定、完整任务绑定、原生转换及原生绑定状态，语义完整与机器可用绑定分别报告，不互相替代。不做单任务显著性检验，不声称总体Graph收益。旧单任务比较及其平局保持原身份。

## 下游边界

本轮不调用代码生成模型，不运行JCI，不赋予正式任务角色。已有22项来源检查只覆盖指定语法拒绝和局部功能；本任务新增的字符串／AST、None、自定义类和多入口范围必须在代码生成之前另行固定并资格核对。不能以旧测量的精确错误措辞作为所有有效拒绝实现的唯一判据。

未来代码生成的基准提示不包含待添加要求；编辑方法可以读取目标要求进行准备，但代码生成对照不能因此取得该要求。代码生成策略收益、功能保持及模型基线均不由本表示诊断推断。
