# Prompt TSG 对象组成关系与操作参与者绑定设计

## 已有证据与修订问题

原始代码上下文比较中，Graph与强平面均为四项语义完整；Graph的八个要求类型命题却没有原生完整绑定。该结果保持原评分。坐标保留要求的对象是返回对象中的坐标，直接操作参与者是返回对象及调用参数；将内部坐标写成直接参数会改变来源含义。

本修订解决可供程序读取的对象组成关系。它是已暴露任务上的方法开发，不构成新的独立收益证据。独立来源参考需要在新的实际表示制作前固定。当前只使用既有 `pydata__xarray-7229` 的原始问题和三个完整代码文件，不取得补丁、测试答案或新模型代码。

## 原生关系与读出

现有来源命题编译器增加 `part_of`：源端为明确组成部分，目标端为其容器，两端均为data_object。它表示同一已记录对象范围内的真组成关系，允许非独占归属；不表示物理内存所有权、别名、依赖、执行先后或因果关系。自环及有向环无效。条件性组成关系只有在当前对象实例与条件范围明确时才能断言；条件、实例或时间归属不明时保留未确定关系。

`used_by`、`produces`继续连接实际参与者与操作。要求主体可以沿来源明确记录的 `part_of` 路径到达参与者。读出保留原始主体、实际参与者、操作、参与关系和完整路径，不能将组成部分重命名为操作实参。每个可到达参与者保留一条确定性的最短见证路径；完整组成边另行保留，见证路径不宣称唯一归属。普通引用、支持或对照关系不提供组成证据。

完整绑定继续需要来源节点显式声明 `binding_complete=true`、明确角色以及每个主体存在有效的直接或组成路径。缺少关系、完成声明或作用属性时保留原有未知／未完成含义。组成关系不能自动补充量词、一般范围、条件、API合同或输入保证，也不能把一个具体坐标实例扩展成所有坐标。

对象组成只影响来源命题的参与路径和可审查读出。Atomic资格、FeatureScope、固定政策匹配、语义覆盖与编辑审查分别执行；表示完整不提供干预资格。生成代码、功能、安全和随机上下文仍需独立测量和设计。

## 实施边界与验证

在 `compile_source_propositions` 中登记实际使用或明确未确定的组成关系，不新增表示类型或执行入口。`source_proposition_measurement`通过同一参与路径实现绑定检查；`source_proposition_readback`保留路径及相关容器。没有组成关系的既有图保持原读出字段与直接连接规则。现有冻结材料仍使用其归档源码复现。

来源参考的上下文只能读取原始问题、原始代码和统一指令，不能读取旧Graph、平面、评分或本次实现。它需要区分调用参数、返回对象、内部对象、属性及当前行为，给出逐字证据，并保留无法确定的一般范围。之后生成新的实际Graph记录；不得修改旧记录的完成标记或重评分旧比较。

机制验证使用实际来源支持的新记录，检查直接参与者不变、命题主体不变、组成路径可复算、相同容器的其他部分没有被添加为主体、普通引用不改变连接判断、未完成声明不会被路径覆盖，以及组成图的类型和无环边界。验证只支持结构消费者的行为，不能当作Graph相对平面或JCI的收益。
