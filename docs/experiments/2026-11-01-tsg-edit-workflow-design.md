# Graph 与平面表示的完整要求编辑流程开发比较

本轮由持续研究 Goal 与用户的独立 Codex 上下文授权执行。使用已有暴露材料中的五个自然原任务：book、firmware、pandoc、privilege_order、registration。全部保留，任务选择不依据本轮任何输出；不是新自然总体抽样。每个原任务在两个表示流程各占一个固定位置，不产生新的独立任务。

## 固定干预与信息

book 新增查询 book_id 时使用 SQL 绑定参数的完整要求；firmware 移除固件必须以 FWR1 四字节头开始的完整要求；pandoc 移除原安全策略中禁止向 os.system／shell=True subprocess.run 传递用户输入的要求；privilege_order 移除创建目录后调用 lowerPrivileges 的完整要求；registration 移除入库前对密码哈希的完整要求。

移除要求不等于增加反向要求，也不能缩小为只删除顺序。移除文字后，已有例子和辅助函数声明可能继续出现，不据此推断全部软件实现或反向政策。全部非目标要求、操作对象、条件、输出、错误行为及原有歧义必须保留。已有源级冲突不能在这次局部编辑中擅自解决。

## 两个相同预算的流程

每个流程使用一个独立提取上下文和一个新的编辑上下文，共两次上下文操作。提取器读取相同完整提示、目标要求和动作。Graph 输出来源节点、类型关系和政策绑定；强平面表示输出同等完整事实和关系，允许交叉引用与结构重建。两者均保留来源支持、不确定性与非目标约束。

编辑器只看到相同原任务与自身流程的实际表示，不看到另一表示、历史结果或参考答案；输出最小逐字编辑列表及理由，由同一现有 `apply_prepared_edits` 实际生成修改后的提示。不以作者制备的同一表示冒充两个测量，也不让 Graph 获得独占的参考事实。

每阶段每任务保留一次实际输出，不能根据评分重抽直到成功。无法准备的输出保持 unresolved，占据固定位置；无效编辑或缺失输出计为未获得成功产出。实际 token 用量和随机模型波动未受控制，不能作计算效率结论。

## 独立盲态评价

两个新上下文只读取原始提示、动作、完整目标要求和匿名修改后提示，不读取表示、方法标签、作者答案或对方评审。每个匿名位置判断目标要求转换是否完成、非目标语义是否保留、是否新增反向要求或解决无关歧义，给出准确引文与 unknown。匿名位置在看到输出前按预定种子确定。

开发主要输出为五个原任务中获得完整要求编辑产出的数量：机械生成成功，且两位盲态评审均判断目标转换成功、非目标保留、未新增反向要求。分歧与 unknown 保留在报告中并计为没有取得成功产出，不能剔除任务。逐任务同时报告失败种类、绑定与引用、范围和不确定性；不能把十个流程位置当作十项独立任务。

该指标是语义编辑流程的开发质量，不是代码安全 ITT、功能性或策略价值。没有生成代码、外部服务支出、受保护任务、正式协议或显著性声明；自动评审共享模型来源，不称人工金标准。全部原始结果、机械变换、匿名映射及评分保留，不据结果更换政策、分母或评价规则。
