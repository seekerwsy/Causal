# 完整单项安全要求的处理前关系属性

## 固定来源与语义单位

适用材料为已有安全来源包的全部42项位置。任务身份、近重复组、来源家族、原文及已有32项来源资格保持原样，未通过位置不替换、不补充背景。当前定义依据独立来源审查建立，尚没有完整42项独立属性参考或表示收益。

每项查询使用共同原文与完整目标政策，不提供提案者的操作、对象、条件、资格理由、编辑动作或旧表示答案。政策可能透露预期来源状态；目标状态本身不作为独立属性准确率指标。

分别记录目标安全谓词、受约束的原始操作、目标引入的实施步骤。图像可解码性作用于原始上传内容，政策可以约束保存操作；新增验证步骤不能被当作原文已有动作。签名验证步骤与返回解码内容分别记录。目标约束多个来源操作时保留全部操作，不能只选具有关系的一项。操作对应无法明确时保留未解决。

操作身份依据原文动作、发生位置、分支范围及论元共指。共同函数、库、路由、容器、变量名称或任务目的不构成同一操作。谓词直接论元、操作参与对象和背景上下文分别保存；当前不输出混合的对象重叠数值。

## 来源保留的同操作准入条件

字段 `retained_condition_same_operation` 记录：是否存在原文明示、需要保留的另一条规则，限制目标所约束原始操作是否获准发生。

正例必须同时满足：能够在原文定位完整规则；该规则约束同一原始操作或原文明确统一的互斥分支操作族；它不是完整目标的重复、等价表达或必需组成；其条件限制操作准入，而非只改变操作之后的输出内容。

两条分支都执行同一返回操作，仅改变消息前缀时，不形成准入条件。参数类型或输入保证不自动转为运行时验证义务；失败后的错误处理也不自动构成事前准入限制。目标新引入的验证及其时序不能作为原有保留条件。

另一条保留规则可以受到目标规则单向蕴含，只要原文将其独立表达，完整移除目标后它仍须保留。“独立表达”不授予逻辑独立或统计独立资格。例如明确的pickle禁止可以与可信格式允许列表分别保留，不能将这种关系解释为两项互不蕴含的政策。

## 来源明确的操作顺序

字段 `retained_order_with_target_operation` 记录：是否存在目标所约束原始操作与另一项保留原始操作之间的明确先后关系。

顺序证据包括明确时间表达，或原文明确要求后一操作消费前一操作的产物。保存、读取、转换、编码、返回、发送和移动使用相同规则；明确的返回或发送动作不会因位于终止位置而被排除。`Returns: str`这样的类型声明本身不新增操作；“decode ... and return it”明确包含解码及返回其产物两个动作。

句子排列、常识、通常代码实现及共享变量名称不足以证明先后。两个分支互斥时不能构造跨分支全局顺序。目标政策新引入的验证先于保存等顺序不属于原文保留关系。提示要求的执行顺序不等于因果方向。

## 三值与实际证据

两个字段分别使用 `expressed`、`not_expressed`、`unresolved`。

- `expressed`：至少一项完整满足定义的关系得到原文支持。其他候选未知不取消已经证明的存在性。
- `not_expressed`：完整原文可读、目标与全部受约束来源操作对应明确，且完成候选检查，没有表达满足定义的关系。它只描述提示表达，不表示软件缺少条件或顺序。
- `unresolved`：目标边界、操作对应、共指、非目标身份或范围的歧义可能改变存在性，或者完整目标尚未解决。

正例保留双方原始操作、直接论元、完整规则、条件或方向、逐字来源区间及目标等价表达。零例保留候选排除理由，不能只输出空列表。量词、条件充分必要关系及范围改变属于语义改变；同一合取拆句、必要条件与其等价逆否形式不改变属性值。
