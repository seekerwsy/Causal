# Reviewer guide

The single normative method is the [active protocol](protocol.md),
protocol `phase-context-policy-v3`. It remains `SPECIFIED_DRAFT`. The local method
core is implemented; representation/measurement qualification, formal role
allocation, the scientific power design and a formal provider budget are not closed.
No formal Discovery, provider Confirmation or claim-bearing schema-3 result exists.

The current representation procedure and development evidence are defined in the
[TSG workflow guide](tsg-workflow-stability.md). Source graph construction ends
before candidate-specific applicability/expression assessment. Requirement composition,
their source evidence, operation/object bindings and conditions belong to the graph;
candidate selection never splits a composite source requirement after extraction.
The [candidate guide](tsg-candidate-construction.md) describes the downstream bridge.

Bounded development extracts source records with finite requirement composition and participants,
conditions and scope in one response, then uses one comprehensive source review and
at most one local semantic patch. The program compiles graph bindings; there is no
separate free binding call. Input assumptions remain distinct from obligations and
cannot become editable requirement candidates. Failed review/repair retains the task
and withholds scope assessment. Positive model review is not independent qualification.
The [current workflow](tsg-workflow-stability.md) is authoritative for live behavior
and the [atomic-record pilot](experiments/2026-09-16-tsg-atomic-records.md) records its
bounded evidence. Frozen historical attempts are not alternative current instructions.
The [composition/locality report](experiments/2026-09-16-tsg-candidate-locality.md)
records the implemented boundaries, failed semantic pilot, reference limitations,
budget and a short offline reproduction using the frozen execution archive.
The [readback diagnostic](experiments/2026-09-16-tsg-structural-readback.md)
compares five structural variants using ten frozen requests. Neither prompt detected
deleted guards or expanded targets. The additional paid prompt was removed after
showing no incremental gain; deterministic debug readings and empty-field repair
addresses remain. This is a negative development result, not semantic qualification.
The [binding-check diagnostic](experiments/2026-09-16-tsg-binding-checks.md)
requires answers for each condition/target and aggregates them mechanically. Focal
controls passed, but background judgments were inconsistent. A saved repair exposed
unapproved impact narrowing; the final merge preserves accepted source impacts and
its offline replay matches the original correct control. Natural stability is unproven.
The latest [cross-task detection comparison](experiments/2026-09-16-tsg-binding-coverage-transfer.md)
found a one-case detection gain but retained a missing-condition failure and an
uncertain composite reference. The experimental detailed review was not promoted;
the default is again ordinary source review, with debug readback and accepted-impact
preservation. Its16 calls and all references, including the ambiguous one, are retained.
Missing edges never prove independence; prompt absence never establishes insecure
software. Required meanings, extra assertions and completeness need source review.
Source-cited local impacts can isolate unrelated unknowns; absent localization stays
global. Candidate evaluation combines fixed source dependencies with assertion impacts,
and cannot waive required endpoints. Non-gating contexts remain distinct from execution
guards. Only asserted atomic obligations supply candidates; semantic atomicity does not
establish independent editability. See the [revision plan](tsg-revision-plan.md).

For the active representation acceptance path, first freeze an independent source reference and
its exact sample thresholds, then run the existing extractor with `--qualification-reference`.
An independent reviewer subsequently judges every compiled source assertion. Run
`qualification prompt-contract TASKS EXTRACTION CATALOG GOLD EVALUATOR ANNOTATOR_PROMPT OUTPUT
--assertion-review REVIEW`. The scorer checks the prospective reference identity, replays the captured
record extraction/review/patch and scope steps, and retains failed/missing tasks. Unknown or missing source review blocks acceptance.
The source-reference author and assertion reviewer must be independent of the extractor;
their declarations require external review. The current exposed runs lack the required prospective
reference and cannot be retroactively qualified. The synthetic fixtures in `test_open_prompt_tsg.py`
illustrate the record structure and do not select thresholds for the real study.

The reference also freezes the required language/operation/feature/gold-state profiles and
uncertainty thresholds. Error bounds use simultaneous one-sided exact binomial limits; empty
profiles stay unknown. Their population interpretation requires representative independent
task-unit sampling, which synthetic or convenience samples cannot establish.

Then run `qualification positivity TASKS CATALOG OUTPUT --prompt-tsg-bundle GRAPHS
--scope-bindings SCOPES`. The scope file contains the existing Atomic/Pair policies, one global
factor definition and one task-local scope per feature, shared support thresholds, and
`representation_qualification: {bundle, bundle_sha256}` (the path is relative to the scope file).
The producer recomputes accepted qualification bounds and writes `positivity-rows.json`,
`support.json`, `coverage-summaries.json`, `atomic-preoutcome-observations.json` and
`pair-preoutcome-observations.json`. Unknown tasks stay in coverage; support failures block folds;
Pair has no Atomic-parent requirement. `_scoped_support_fixture` in `test_open_prompt_tsg.py`
shows the record shape. Its artificial cells and qualification trials cannot supply natural support.

all seven stages with synthetic inputs and local measurements. It makes zero
provider calls and writes `evidence_level=tested`, `NON_CLAIM_TEST_ARTIFACT` and
`scientific_claim_allowed=false`. The second command independently verifies the
exact saved package and never generates new outcomes.

`verify-development SAVED_RUN` for independent raw-response/accounting checks.

its Atomic descriptive sign-flip/Holm plan is not the formal simultaneous family.

its null test and response-pattern labels remain explicitly inactive.

and `data/method/local-llm-development-v1/server-results/run-32b`.

development estimator is preserved per model; `inference.summarize_development_models`

to independently verify both saved runs and rebuild the stage tables and views with zero

## Seven stages and their boundaries

| Stage | Input | Output and invariant |
|---|---|---|
| Representation | frozen source tasks, catalog and role manifest | task units and Prompt TSG facts; semantic edges are not causal edges |
| Prioritization | outcome-blind universe, support and fold freeze; then separate Discovery outcomes | model-bound Atomic/Pair fixed-K slots; Core and baselines share discoverability |
| Hypothesis freeze | slots, qualification, budget and shared union | one protocolization per policy and one dispatch per model effect |
| Intervention/randomization | Q, original task pool, allocated realization, complete arm bundles and exclusions | one realization per task-policy; no replacement after bundle failure; balanced replayable arms |
| Measurement | frozen assignments and independent evaluator contracts | validity, local Security Oracle, blinded functionality, raw responses and failures |
| Outcome assembly | every assignment's measurement or infrastructure failure | total assigned-arm ledger; unknown, invalid, harmful and failed records remain visible |
| Inference/reporting | fixed task-unit ITT plan and total ledger | fixed-Q effects, joint max-T families, fixed-K tables, explicit non-evaluable states and independent verification |

Optional D0 is outcome- and selector-blind data preparation before Discovery,
not another scientific stage. It permits at most one bounded acquisition round
of independent natural tasks under frozen context task-unit targets. Trigger and
stopping decisions do not use feature states, Pair cells or candidate support.
Unresolved membership and remaining coverage gaps are retained; candidate support
and power are separate design checks. Pair admission
never requires an Atomic candidate to have ranked or passed a structural gate.

The offline case/result view is exported with
`prompt-mechanism-study representation visualize TASKS EXTRACTION_BUNDLE OUTPUT.html`.
Add `--results RESULT_BUNDLE` to inspect saved effects and every assigned row.
It verifies graph evidence before export and performs no provider calls or estimation.
The [previous view](../results/open-tsg-explorer/index.html) contains all 30 development
sources and all 120 experiment assignments, with manual-subgraph provenance and
post-hoc mechanical replay explicitly labeled.
The [SQL refinement view](../results/open-tsg-explorer/sql-refinement.html) defaults to full
graphs and distinguishes the raw old/new annotations from source review. Its five-arm
results use only the exact source-reviewed graph frozen in the new execution plan.
The latest [two-model view](../results/open-tsg-explorer/local-models.html) separates
assignment counts from independent task counts, complete seed cells from failed cells,
and seed Monte Carlo error from task bootstrap uncertainty. Each model's detail page
contains 60 exact task-arm prompts and every one of its 600 assignments. Semantic
coverage is not estimated from mechanical check counts. Syntax diagnostics bind the
unaltered returned code to independent Python parsing; incomplete provider envelopes
prevent attribution of the seven non-stop failures to a specific finish reason.

## Scientific checks

- Universe and fold identities hash only pre-outcome task/representation fields.
  Discovery outcomes have a separate scoring-data hash.
- A semantic policy is model independent; its effect is `(policy_key, model_id)`.
  Each selector plan must match every model-bound candidate it consumes.
- Expert/Random use the exact same frozen discoverability and fold decisions as
  Core. Zero eligible candidates preserve all empty slots and create no fake effect.
- For each realization, average independent task units first; then apply the
  original `q_r`. Every endpoint and latent bound uses the same weights. The
  estimand is a mixture of realization-specific protocolizable populations.
- A family bootstrap samples each task unit once within its original source
  stratum and carries all descendants together. Every draw must meet the frozen
  per-realization and per-cell minima; too many invalid draws block inference.
- Power simulation generates categorical request outcomes and runs the actual
  family procedure. Non-evaluable replicates stay in the denominator. Its
  inference plan must exactly match the eventual power-and-margin memo.
- Current preflights also store power recomputed on exact task-effect membership
  and realization allocation, including partial overlap. The verifier reconstructs
  that table and rejects changed assumptions or inadequate power. Empty families
  produce no artificial power result.
- A D0 successor preserves all old role bindings and adds only receipt-matched,
  independent Discovery units within the frozen source scope. The receipt carries
  the original manifest; qualification keeps that identity while Discovery binds
  the checked successor. No acceptance dataset is reopened.
- Post-assignment fidelity, semantic compliance, generation success and drift
  are diagnostics. They never filter the ITT denominator.
- Secure-code yield, validity, evaluability, unknown coverage, functionality and
  joint success are distinct. Impossible outcome combinations are rejected.
- Source completeness is descriptive: every syntax-valid program enters blinded
  functional review. Whole-task pass, demonstrated failure and unresolved material
  requirements remain distinct; frozen pre-revision records retain their old rule.
- TLS safety is checked at actual use sites with bounded ordered state tracking.
  Unresolved kwargs, aliases, mutation or control flow remain unknown. A default
  SSL-context constructor alone does not prove that generated code is secure.
- Formal claim authorization resolves actual frozen inputs and raw execution
  artifacts, checks active author authorization, and reconstructs measurements
  and outcomes. Relabeling a smoke package or supplying arbitrary hash references
  cannot enable claims. An installed package without the checked-out author
  decision and qualification manifest reports an explicit authorization block;
  files supplied by the execution package or current working directory cannot
  grant that authority.
- Context inference and Pair response-pattern labels remain explicitly blocked
  until their exact assignment, multiplicity and deterministic rules are frozen.

## Reading order

After the specification, read these ten core files under `src/prompt_mechanism_study/`:

1. `target_workflow.py` — the linear seven-stage entry point and bounded development.
2. `source_records.py` — complete source propositions, one review/local patch and deterministic graph compilation.
3. `candidate_construction.py` — source requirements to reviewed factors, policies and automatic scopes.
4. `mechanisms.py` — factor binding, scoped ADD/REMOVE and reviewed joint realizations.
5. `prioritization.py` — Atomic design, slots, union and dispatch.
6. `interaction_selector.py` — independent Pair discoverability and scoring.
7. `study_design.py` — actual assignment preflight and the two pre-outcome freezes.
8. `measurement.py` — independent generation/security/functionality records.
9. `inference.py` — weighted task-unit effects and simultaneous families.
10. `verification/verifier.py` — exact-package verification entry point.

`prompt_contract_extract.py` supplies the shared extraction entry point and immutable
downstream scope assessment. `prompt_tsg.py` supplies coherent graph queries and exact operation/input/condition states.
`task_input.py` binds the source and prepared baseline messages. `randomization.py`
implements the frozen realization and arm allocation. `verification/reporting.py` independently checks development
requests, code, endpoint arithmetic, task-level contrasts and the fixed Holm family.

The verifier delegates independent calculations to `verification/design.py`,
`effects.py`, `qualification.py` and `reporting.py`; it does not call the production
effect or power estimator. `rq1_baselines.py` supplies the optional blinded Expert
and seeded Random selectors inside the same slot/union path.
`discovery_population.py` owns outcome-blind source preparation, role allocation
and optional D0 supplementation. `study_planning.py` owns qualification,
actual-procedure power and budget planning before the study. Their frozen outputs
enter the core path above. Atomic and Pair share only the numerical optimizer in
`selector_numerics.py`; their design matrices, standardization, 300/800 iteration
limits and scoring rules remain separate. The independent verifier does not use it.
Saved-package verification checks budget, preflight, freezes, evidence and tables
once each. Standalone public verifiers still check their own prerequisites.
Writing a result checks statistical evidence once before writing and once again
from the saved bytes; table construction reuses the first check. These two checks
protect different boundaries and do not rely on a persisted bypass flag.
The obsolete Gaussian `qualification study-design` command has been removed;
power design uses the actual family procedure in `study_planning.py`.

For ordinary reproduction, consume the frozen source bundle. When source data
must be prepared, `curate` exposes four responsibilities: `prepare`, `review`,
`repair` and `finalize`. Repairs are conditional steps for unresolved records;
they are not study stages. The [data preparation guide](contract-content-cleaning.md)
lists the exact commands. The archived single-provider review is not an active CLI.

## Reproduction

Use Python 3.12 and install the repository with its `dev,selectors,languages` extras
in a fresh virtual environment. The default reviewer suite includes one complete
seven-stage smoke and independent saved-result verification:

```text
python -m pytest -q
```

For standalone inspection or export of the smoke package, run:

```text
prompt-mechanism-study study smoke NEW_OUTPUT_DIRECTORY
prompt-mechanism-study study verify-result NEW_OUTPUT_DIRECTORY
```

Standalone smoke reproduction is not an additional gate after the same checks
pass in the default suite. Daily development uses the affected checks in the
[test guide](../tests/README.md). The current 110-case suite contains only the
maintained scientific checks; there is no separate extended or reviewer filter.

The smoke's ten-task power fixture uses a 0.01 engineering threshold solely to
exercise accepted-package plumbing. It is not a scientific target or formal
sample-size recommendation. The repair record gives exact executed checks and
reproduction identities: [2026-09-07 repair verification](experiments/2026-09-07-research-artifact-repair.md).
The subsequent [five-step simplification record](experiments/2026-09-08-framework-simplification.md)
documents installed-package reproduction and unchanged scientific smoke outputs.

The latest September 11 power-computation check in the clean Python 3.12.13 environment
passed all 228 default reviewer tests (113 extended cases deselected). The current
seven-stage smoke and independent verifier agree on 80 assignments and bundle
`f4c7c06da12bcf32ea3b7b9babac69dcb26f80af64b92a3123d18646a4f051a3`.
The [planning report](experiments/2026-09-11-power-design-development.md) records
the frozen inputs, source archive and byte-identical representative calculations.

A frozen full scientific reproduction is unavailable because the protocol and

inputs, allocation/exclusion pool, raw responses, measurements, environment,
