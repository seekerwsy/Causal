# Active protocol: context-conditioned Atomic prompt policies

## 1. Authority and status

This is the single normative method on `main`, protocol `phase-context-policy-v3`,
status **SPECIFIED_DRAFT**. It permits source preparation, offline verification and
explicitly authorized bounded development checks. It does not authorize formal
Discovery, provider Confirmation, protected-task exposure, provider spending or
scientific reporting. Formal use requires a prospectively authorized frozen
package and the qualifications below.

The 2026-09-16 scope decision defers Pair interaction research to
[`codex/pair-interaction-research`](https://github.com/seekerwsy/Causal/tree/codex/pair-interaction-research),
commit `e6833027`. Main now has one Atomic policy family. The old draft, complete
Pair implementation and original manuscript remain on that branch. Frozen
artifacts are never reinterpreted under this reduction; Pair reproduction uses
the preserved implementation. Protocol IDs in historical artifacts are unchanged;
implementation/configuration digests distinguish the prospective Atomic draft.

## 2. Research objective

CausalGuide investigates how changing one task-bound prompt requirement affects
LLM-generated code outcomes and what scoped explanation that evidence supports.
Engineering exists to make the scientific procedure inspectable and reproducible.

The active path has exactly seven stages:

**representation → prioritization → hypothesis freeze → intervention/randomization
→ measurement → outcome assembly → inference/reporting.**

The manuscript groups these into representation, requirement-level causal analysis,
and evidence-grounded explanations/guidance. This changes presentation, not execution.

## 3. Scientific boundaries

Prompt TSG describes source semantics; its edges are not causal edges. Generated
code supplies independently measured security and functionality outcomes. It is
not a primary-PAG variable or causal mediator. Observational scores and FCI
adjacency prioritize hypotheses; assigned interventions identify policy effects.

The independent unit is a cross-source-deduplicated **task unit**. The legacy
field `semantic_cluster_id` retains its frozen meaning. Repeated seeds, task
instances and overlapping selector slots do not create independent observations.
Assigned-arm ITT is primary. Fidelity, compliance, generation success and
non-target drift are diagnostics, never post-assignment denominator filters.

## 4. Populations and outcome-blind preparation

Development, qualification, Discovery and Confirmation use prospectively bound,
non-overlapping task-unit roles and source lineages. Record development exposure
before inspecting new task-level feedback. Preserve protected inputs, reservations
and all previous reviews. No outcome-driven replacement or retrospective role change.

Optional D0 is source preparation, not another scientific stage. It permits one
bounded round of independently sourced natural tasks before Discovery under a
frozen context-only coverage target. Acquisition cannot depend on feature states,
selector ranks, FCI/RD, candidate support, outcomes, paraphrases, interventions or
synthetic cell filling. Unknown context membership and remaining gaps are retained.
Candidate support and power are separate checks, not acquisition targets. The
post-preparation population digest binds all downstream support and design records.

## 5. Representation

Prepare the actual system message, user task and declared language before
extraction. Original input identity and exact evidence spans bind the graph;
later generation must use the corresponding input. Development may discover
source concepts, but their definitions and producer are fixed before Discovery.
External CWE labels cannot replace source evidence or decide extraction scope.

The [TSG workflow](tsg-workflow-stability.md) defines the current extraction path:
source records with participants/composition/conditions/targets, mechanical checks,
one ordinary source review with at most one local semantic patch, then deterministic
compilation. The existing bounded mechanical repair limit is unchanged. There is
no additional default readback or detailed binding reviewer. Debug readings remain
available; a positive LLM review is not an independent semantic reference.

A requirement preserves content, negation, thresholds, direct objects, operation
instances and conditions together. Conditions providing information are distinct
from targets being constrained. Participation in the same workflow does not
justify spreading a requirement to every operation. Input assumptions are not
editable obligations. Atomic requirements may retain conditions; and/or/not/opaque
composition preserves meanings that cannot safely be treated as independent factors.

Candidate construction selects, normalizes equivalent definitions and binds exact
scope; it cannot split a source node, repair its missing relations or select half
of a compound obligation. Complete semantic bindings, not plausible description
text, determine downstream meaning. Semantic atomicity does not prove independent
editability. The [candidate guide](tsg-candidate-construction.md) specifies the bridge.

Applicability and expression are distinct. Source-grounded local impacts limit
unknown propagation to affected candidates; absent localization and shared
constraints remain blocking. Required target endpoints cannot be waived. Preserve
`UNRESOLVED != ABSENT`; an unexpressed prompt requirement does not mean generated
software lacks that protection. Evaluation reports critical meanings, extra
assertions, candidate correctness and coverage alongside whole-graph diagnostics.

## 6. Context-conditioned hypotheses

`AnalysisScope` contains exactly `security_pattern_id`, `context_query_id`,
`language_scope`, `api_scope`, and `task_archetype_scope`. Scope collections are
nonempty, unique and sorted. One `AtomicPolicyKey` binds that scope, one feature,
one operation (`ADD` or `REMOVE`) and one outcome. A model effect is
`(policy_key, model_id)`; the protocol-bound candidate record adds protocol identity.

Rank, score, expected direction, model, qualification result and selector are not
semantic policy identity. Different task-local object names do not create new
factors. Context queries and scope selection are independent of the target state;
ambiguous matches remain unresolved rather than choosing a convenient state.

## 7. Discoverability and observational prioritization

Before reading Discovery outcomes, freeze one candidate universe, source/state
support decisions, uncertainty/reliability thresholds and task-unit fold manifests.
Each Atomic candidate needs an applicable context, natural factor-state support,
source-lineage overlap and valid folds. Unknown memberships remain in coverage;
support insufficiency is not a null effect. No task edits manufacture natural support.

For each model and security scope, qualified FCI uses natural prompt states,
approved pre-treatment covariates, independently measured baseline outcomes and
frozen typed background constraints. Atomic Full applies the qualified adjacency
criterion. RD-only omits that criterion. Both use identical candidate rows,
discoverability decisions, folds, cross-fitted standardized first-order risk
differences, absolute-value ranking, deterministic tie-breaks and fixed K.
ADD ranks expressed-minus-unexpressed; REMOVE reverses that orientation. Scores
retain sign without requiring a favorable direction. FCI is not the score and
neither score nor admission establishes a randomized causal effect.

## 8. Selectors and fixed budgets

Atomic Full and RD-only form the core selector comparison. Blinded Expert and
seeded Random are optional only within their prospectively qualified, funded
comparator envelope. They share the same universe and fixed-K accounting.

Every slot remains in K, including empty, failed and non-evaluable slots. The
selected union is deduplicated by model effect; one shared result fans back to
all referring slots. Protocolization and model dispatch are distinct. No reranking,
replacement or budget reassignment follows Confirmation outcomes.

## 9. Prompt policies and realizations

ADD introduces a source-resolved unexpressed requirement without assuming insecure
baseline code. REMOVE withdraws an identifiable expressed requirement through a
validated neutral counterpart; it never instructs the opposite insecure behavior.
Both preserve declared non-target behavior and remain separate policies.

Each Atomic comparison has four arms: target edit, operation-matched no-op,
placebo/sham, and direction-compatible generic-security instruction. The primary
contrast is **target minus matched no-op**. No-op preserves the source requirement
state while matching the editing operation. Placebo and generic comparisons need
their own prospectively frozen secondary rules before supporting specificity claims.

Freeze finite editing realizations and positive weights summing to one. Assign
exactly one realization to each task-policy coordinate by the existing seeded,
source-stratified balanced allocation before task-specific materialization. Generate
and validate only that complete arm bundle. Retain a failed allocation without
retrying another realization, replacing the task or renormalizing weights.
Different realizations can have different protocolizable populations; the estimand
must retain that limitation. Source tasks need not arrive with experimental controls.

## 10. Randomization

Freeze eligible task pools, realized arm bundles, model/request settings and the
complete assignment table before generation. Within each task-instance, policy,
realization and model block, allocate equally across the four arms using the frozen
seed/block schedule. Preserve task, arm, realization, model and request-randomness
bindings. Failed bundle materialization is a pre-assignment record; every committed
assignment subsequently remains in its assigned arm and has a terminal record.

## 11. Measurement and estimand

Measurement is arm blind. Keep raw requests/responses and separate:

- code production and syntax validity;
- Oracle support/evaluability and secure/insecure/unknown labels;
- functionality pass/fail/unknown against the original task;
- secure-and-functional joint success and its unknown coverage;
- infrastructure failures and post-assignment diagnostics.

The primary endpoint, **oracle-evaluable secure-code yield**, is one only when a
request yields valid code evaluated as secure. A valid Oracle-unknown program has
zero observed secure yield, not an insecure label. No-code/invalid generations
remain recorded. Infrastructure failure is not silently recoded as a measured zero;
it blocks affected inference until the same assignment is resolved under its rules.

Syntax-valid programs receive original-task functional review, allowing reasonable
implementation freedom and unknown for genuinely unassessable requirements. Source
incompleteness alone does not imply functional failure. The prospective functional
judge revision still requires qualification; frozen old labels retain their rules.

Average seeds within each task instance, then apply frozen within-task instance
weights. For task-unit difference D and realization weight q:

    tau = sum_r q_r * mean_(assigned task units in realization r)(D)
    D = within-task mean(Y_target - Y_noop)

Within realization/source-stratum cells, lambda_rs = q_r * n_rs / n_r. Use these
same fixed weights for every arm mean, diagnostic fraction and sensitivity bound.
Missing realization/support never creates a smaller renormalized policy.

For latent secure valid-code yield, L is observed secure yield and
U = L + I(valid and Oracle-unevaluable). Report the contrast bounds
mean(L_target)-mean(U_noop) through mean(U_target)-mean(L_noop).
Differential code production or Oracle coverage must not be called improved
underlying software security. Functionality and joint claims need their own evidence.

## 12. Multiplicity and simultaneous inference

There is one primary family: all unique Atomic target-minus-no-op secure-yield
model effects in the frozen confirmation union. Empty unions have
`NO_ELIGIBLE_COORDINATES`, not fabricated zero effects. Secondary endpoints and
contrasts require separately frozen and implemented families.

For effect j, the variance is sum_(r,s) lambda_jrs^2 * sample_variance(D_jrs)/n_jrs.
Each bootstrap draw samples the union of family task units with replacement within
original source strata. All descendants of a sampled unit move together, including
overlapping effects/models. Each effect uses its own frozen support and realization
labels. Original lambda weights are not refit to bootstrap frequencies.

A draw is invalid when any coordinate loses its frozen cell/realization minimum
or has zero standard error. Otherwise compute the maximum across coordinates of
abs((bootstrap_estimate - estimate)/bootstrap_standard_error). Require at least
ceil(B * minimum_valid_bootstrap_fraction) valid draws and use the sorted one-based
ceil((1-alpha)*B_valid) maximum (the stored `higher` quantile rule). Intervals are
estimate +/- critical * standard_error. Failed provenance, inadequate initial
support, excessive unknown coverage, zero initial standard error or too few valid
draws yields an explicit non-evaluable family. There is no unadjusted fallback.

With prospectively frozen practical margin epsilon, the five statuses are:

| Status | Rule |
| --- | --- |
| POSITIVE_MEANINGFUL | interval lower > epsilon |
| NEGATIVE_MEANINGFUL | interval upper < -epsilon |
| PRACTICALLY_NULL | entire interval lies within [-epsilon, epsilon] |
| INCONCLUSIVE | evaluable interval meeting none of the above |
| NON_EVALUABLE | failed provenance, support, coverage or inference |

Margins, alpha, minima, draw count/seed and validity criteria come from the frozen
power-and-margin memo, never from inspected effects. Meaningful Yield@K counts
positive- or negative-meaningful slots divided by original K. Every other slot
contributes zero utility without being called a zero causal effect. RQ2 reports
descriptive Full-minus-RD-only Yield@K on the frozen Discovery split; no nested
utility interval or pooled hypothesis ATE is an active claim.

## 13. Robustness and context modifiers

Retain realization-specific populations, weights and failures, and separate model
effect coordinates. The mixture estimate alone does not prove wording robustness
or cross-model replication. Such labels require frozen populations, contrasts,
margins and simultaneous rules. No one-snapshot run is a replication study.

Context-modifier inference remains `BLOCKED_NO_FROZEN_CONTEXT_RULE` until exact
task assignment, contrasts and joint bootstrap/multiplicity rules are frozen.
Missing rules do not receive guessed defaults or claims. These follow-ups are not
prerequisites for reporting an otherwise evaluable primary Atomic effect.

## 14. Implementation markers

Generated-code markers can only be separately qualified diagnostics. They do not
enter primary-PAG variables, candidate selection, eligibility or effect status.
An assignment effect on a marker cannot identify mediation, causal necessity or
sufficiency, or the generator's internal reasoning.

## 15. Evidence levels

Keep `specified`, `implemented`, `tested`, `executed` and `reported` distinct.
A unit test is not an executed experiment. Smoke, calibration and development
observations cannot become confirmatory evidence. Observational selection,
randomized policy effects, specificity, robustness and replication have different
evidence requirements; one cannot silently promote another.

### 15.1 Evidence-grounded explanations and guidance

This is a specified reporting contract, not a qualified explanation generator.
Explain applicable scope, source requirement/target/condition, concrete edit and
comparator, effect evidence, functionality/uncertainty, then supported action.
Tie each statement to exact source, policy and verified result records.

Without formal randomized evidence, an edit is an unconfirmed option. A favorable
primary endpoint does not establish preserved functionality, lower underlying
insecurity, specificity or joint success. Adoption advice additionally requires
resolved applicability and prospectively specified security/task-preservation
criteria, secondary margins, coverage and a joint decision predicate. Those exact
rules remain open; missing support blocks advice, not reporting the effect.

Retain negative, practically null, inconclusive and non-evaluable findings.
Harmful REMOVE evidence cannot validate reverse ADD. A negative effect warns about
the tested policy only. Task-local binding is not an individual causal effect,
transportability guarantee or evidence about internal model reasoning.

## 19. Prospective Sample Size and Data Gate

Source usability depends on an interpretable task, relevant operation/security
boundary and observable non-target behavior. Missing unrelated detail limits
claims rather than automatically excluding the task. Source screening is separate
from exact intervention/control design. Frozen five-axis source reviews remain
historical judgments and cannot be retrospectively relabeled.

Qualify representation against independently frozen source references and declared
language/operation/state profiles, including coverage/uncertainty. Qualify the
Oracle for the endpoint and code forms actually admitted, using representative
positive/negative/unknown cases and differential-error checks. Unused languages
or profiles do not block a narrower study. These checks do not prove universal
semantic or measurement accuracy.

The power-and-margin memo must use the categorical task-unit simulation and exact
Atomic inference rules, including validity, evaluability, secure yield, dependence,
realization mixtures, support and non-evaluable replicates. Actual Confirmation
allocation must meet the frozen design's support and power criteria. Gaussian
planning approximations, convenient historical counts and development success
cannot substitute for this qualification. The formal provider budget must cover
the exact comparator envelope, tasks, arms, models, request slots and qualification
costs before execution. Current paid development balances are not this budget.

## 20. Failure and negative-result semantics

Preserve all assigned outcomes, unknowns, harmful/null results, backend failures
and non-evaluable cases. Distinguish source exclusion, candidate ineligibility,
protocolization failure, missing outcome and inferential insufficiency. Each has
its own stage and cannot erase a fixed selector slot or committed assignment.
Diagnose exact requests, transformations and measurements before attributing a
failure to model quality or randomness. No new reviewer loop follows merely from
an unfavorable result.

## 22. Acceptance criteria

The maintained suite protects input/source identity, unknown handling, exact
Atomic scope, shared-universe selection, fixed-slot fanout, replayable randomization,
arm-independent outcomes, total assignment accounting, weighted task-unit ITT,
simultaneous inference and independent saved-result verification. One end-to-end
smoke exercises the seven stages. Run focused checks during editing and the
complete reviewer path once before completion; broaden only for a concrete change
or failure. Offline tests do not close empirical qualification or authorize claims.
