# Task-unit data bundle

This compiler is the single active path from the completed seven-source
curation artifacts to the reviewer-facing task-unit data set. It performs no
model calls, semantic re-clustering, contract extraction, Prompt TSG
extraction, experimental assignment, generation, or outcome analysis.

## Build and verify

From the repository root:

```powershell
prompt-mechanism-study data task-unit-bundle build `
  .codex-runtime/reviewer-task-unit-data-20260831-04 `
  --prepared-root .codex-runtime/external-gate-c-overlap-audit/seven-source-prepared-v2 `
  --clusters-root .codex-runtime/semantic-problem-pilot-final `
  --candidate-root .codex-runtime/dataset-final-quality-20260831-36-target-oracle-final `
  --legacy-roles-root data/method/legacy-v5-role-bindings-v2 `
  --development-exclusions data/dataset-curation/contract-review-development-exclusions-v1.json `
  --role-census-root data/method/phase-context-policy-v3-role-census-v6

prompt-mechanism-study data task-unit-bundle verify `
  .codex-runtime/reviewer-task-unit-data-20260831-04
```

The reference build contains 2,283 source records compiled into 2,165 task
units. Quality is stored separately: 1,217 pass, 930 require contract repair,
12 require independent review, and 6 contain source defects. Historical data
use is also separate: 25 are qualification/development data, 41 are legacy
exposed data, and 2,099 remain prospectively unassigned. These counts do not
authorize a formal experiment.

## Files and boundaries

- `task-units.jsonl` contains the immutable task identity, exact representative
  prompt, source provenance, and references to evaluation assets.
- `task-quality.jsonl` contains outcome-blind curation quality. Measurement
  readiness is deliberately not treated as task quality.
- `task-roles.jsonl` contains development and legacy exposure history. It does
  not allocate confirmatory roles.
- `source-lineages.jsonl` records the seven source lineages without imposing a
  quota or exclusion rule.
- `near-duplicate-groups.jsonl` supplies conservative grouping coordinates for
  later allocation; it does not silently merge additional task units.
- `readiness-worklist.jsonl` assigns every task unit to exactly one current
  workstream without changing task quality or allocating a formal experiment
  role. The reference build contains 930 contract repairs, 12 independent
  quality reviews, 58 mechanism-binding reviews, 209 Oracle qualifications,
  174 runtime qualifications, 603 prospective scope decisions, 9 permanently
  exposed non-confirmatory tasks, 6 source-defect exclusions, and 164
  technically ready tasks waiting for method freeze.
- `report.json` records the population counts and scientific boundaries.
- `manifest.json` binds every generated byte and row count.

Prompt TSG is intentionally absent. The report must state
`NOT_GENERATED_PENDING_METHOD_FREEZE`, with null extractor and catalog
identities and a task count of zero. TSG generation begins only after the
representation method and semantic catalog are prospectively frozen.

The compiler rejects incomplete source coverage, cross-lineage task units,
quality-ledger drift, overlapping development and legacy exposure, readiness
census drift, non-canonical output, or any input indicating that arms or
outcomes were used. The verifier checks the compiled population, record hashes,
lineage and near-duplicate partitions, file identities, and the explicit TSG
boundary. The worklist also distinguishes an evidence gap from an irreversible
historical exposure: rerunning a review cannot make exposed development data
confirmatory again.
